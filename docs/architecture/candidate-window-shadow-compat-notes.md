# 候选窗软阴影的宿主兼容性记录

2026-08-25 排查「QQ 传统版群文件工具栏 → 搜索按钮弹出的文本框，一打中文就被关掉」得到的结论。
症结不在输入法逻辑的任何一环，而在**候选窗的窗口矩形比它看起来大一圈**。

## 结论

候选窗是 layered 窗口，**软阴影由我们自己绘制、计入窗口矩形**。候选窗贴在 caret 下方显示时，
阴影的上边缘会向上扩出内容之外（blur=8 的默认主题约 29px），正好压在 caret 所在的那一行 ——
也就是宿主的输入框本身。

QQ 那个弹出搜索框会检测自己是否被其它窗口遮挡，**判据看的是窗口矩形，不问像素透不透明**，
于是把自己收起来。用户观感是「一出候选，文本框就没了，而候选窗还在」。

### 为什么只有我们

`UpdateLayeredWindow` 拿不到 DWM 的系统阴影（本仓早有定论，勿再调研）。要有阴影就只能自绘，
自绘阴影就必然占窗口矩形。不画阴影的输入法、或者用非 layered 窗口拿系统阴影的输入法，
窗口矩形与可见内容一致，不会侵入宿主输入区。

## 决定：不修

阴影是默认主题的既定观感，为一个宿主的遮挡检测去掉它、或给候选窗定位加一层「避让宿主输入框」
的特例，代价都远大于收益 —— 而且我们并不知道输入框的完整矩形，只有 caret rect，避让无从算起。

**用户侧规避**：把候选窗设成固定位置，摆到不会压住输入框的地方即可。实测有效。

## ⛔ 已逐条实测排除，勿重复排查

下面七项都做过「关掉它 → 真机复现」的单项实验，**全部仍然复现**。再遇到同类症状不必重来：

| # | 关掉的动作 | 结果 |
|---|---|---|
| ① | `OnLayoutChange` 首帧的同步 `TF_ES_SYNC` 取坐标探针 | 仍复现 |
| ② | 给组合范围设显示属性（下划线） | 仍复现 |
| ③ | 候选出现时 `RegisterHotKey` 抢 20 个系统级热键 | 仍复现 |
| ④ | 完全不往宿主文档写 composition | 仍复现 |
| ⑤ | 吃掉字母键但不发服务端（无候选窗） | **不复现** |
| ⑥ | 字母键直接透传给宿主（无候选窗） | **不复现** |
| ⑦ | 不调 `ITfUIElementMgr::BeginUIElement` 声明候选界面 | 仍复现 |

⑤⑥ 与其余各项的唯一差别就是候选窗出不出现。随后用候选窗显示开关直接验证：不显示即无问题；
再用固定位置验证：只要候选窗（含阴影）不压在输入框上，同样无问题。**几何相关**这一点
排掉了 Z 序抢占（`HWND_TOPMOST`）和窗口显现事件（`SWP_SHOWWINDOW` 触发的 WinEvent）两种解释。

## 方法论教训

- **「A 档和 B 档的差集」不等于「唯一嫌疑」**。本次连续三轮把判据表写窄（先咬定 composition 写入，
  再咬定候选窗，再咬定 `BeginUIElement`），每次都是拿两档之间的差集当唯一变量，忽略了差集里
  还躺着没单独测过的动作。可靠的只有逐项单关单测得出的排除表。
- **在实验组里失效的指纹不能当判据**。④ 档下没有 composition，「组合被宿主终止」这个计数
  天然恒为 0，拿它跨档比较等于读一个已经坏掉的仪表。有鉴别力的是「用户连打了几个字才停手」
  这类不受档位影响的行为证据。
- **窗口的可见边界 ≠ 系统眼中的边界**。凡是自绘阴影/圆角的 layered 窗口，都要记得它对
  命中测试、遮挡检测、`WindowFromPoint` 呈现的是那个更大的矩形。同源的坑另见候选窗宽度钳制
  （钳 content_w 时须减去阴影扩边）。

## 诊断脚手架

`wind_tsf` 侧留有一组二分开关，出厂全关、零行为影响，配置落点与 TSF 日志同一个文件
`%LOCALAPPDATA%\<变体>\logs\tsf_log_config`：

```
diag_no_layout_probe    diag_no_display_attr    diag_no_cand_hotkeys
diag_no_composition     diag_no_send_key        diag_no_eat_keys
diag_no_ui_element
```

改完存盘后按 **Ctrl+Shift+F12** 立即重读（该热键原本只导出环形缓冲日志，现顺带重读配置）。
⚠ 该热键**出厂关闭**，同一个配置文件里要先写一行 `dump_hotkey=1` 才有它——而这一行本身
只在宿主进程启动时读，所以第一次得重启宿主。默认关的理由见 `wind_tsf/AGENTS.md` 的
File Logging 一节：它排在所有吃键闸门之前，开着就等于对所有用户抢走这个组合键。
当前档位会当场以 `[WindInput diag: ...]` 打到焦点处，同时写进日志的 `compat.diag` 行。
`CTextService::ActivateEx` 也会重读一次，所以切走输入法再切回同样生效。

⚠ **别在被测的弹出框里按 Ctrl+Shift+F12** —— 它往焦点处插入文本的动作本身可能改变被测状态。
