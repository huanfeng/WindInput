# 方案设置对话框：纵向 TAB 与稀疏覆盖

状态：设计稿（待实施）。涉及仓：wind-setting（主体）、WindInput（core 暴露来源信息，视核实结果而定）。
前置：`override-presentation.md`（R8，本文修订其中 R8.1 / R8.5 / R8.7 在方案对话框内的适用范围）、
`schema-scoped-behavior.md`。

> **2026-11-03 修订（以此为准，下文 §3–§5 中与之冲突处作废）**：用户试用后把原「方案覆盖」拆成两页：
>
> - **自定义行为**：候选窗 / 标点 / 输入——对**公共配置**做方案级特殊处理。**不用「添加覆盖」**，
>   各项常驻列出，形态同拆分前（勾选行 + 跟随档 + 全部恢复跟随）。
> - **方案覆盖**：覆盖**引擎类型的全局配置**（码表 / 混输 / 拼音 / 双拼）。大多数方案一项不改，
>   所以走「添加覆盖」：分类标题右侧的复选菜单，勾上的项才出现；取消勾选即移除。
>   **目前只有码表有**（码表配置并入此页）；拼音 / 混输的全局配置在 core 里刻意「全局唯一、无方案
>   override」（`docs/redesign/schema-config-layering.md` §3.2 / §3.3），要支持得先在 core 定哪些字段可覆盖。
> - TAB 集合：全拼/双拼 = 基本·按键设置·自定义行为·辅助码；码表 = 基本·按键设置·整句输入·自定义行为·
>   方案覆盖·特殊模式；混输 = 基本·按键设置·整句输入·自定义行为。
> - §4 里「方案文件已覆盖的项直接显示」在码表页沿用既有的「方案自带」来源标注；稀疏化只作用于码表配置。
>   先做过一版把「本方案行为」也稀疏化（含 core 的 schemaBase / schemaUserOverride 旁路字段），
>   已回退，见提交历史。

## 1. 为什么改

方案设置对话框现在是三个横向分段页（基本配置 / 按键设置 / 方案自定义），内容由 `SettingsSection`
分节生成（`dialogs/schema_manager.rs`）。问题：

1. **扩展性差**。横向页签数量上限低；码表方案还要塞整句输入、码表配置、特殊模式，辅助码也要独立成块。
2. **「方案自定义」是一面墙**。每个可覆盖项都以「勾选行」常驻（每页候选数、标点、排列、字体、
   排列方向、短语、注释、自定义标点……），而绝大多数用户一项都不会动。常驻只是在制造噪音。
3. 应用兼容页已经验证了更合适的形态：只列已设置的项，用「添加覆盖项」从完整清单里挑。

## 2. 目标 / 非目标

目标：
- 左侧纵向 TAB，TAB 集合随方案类型变化，加新功能时加一个 TAB 或一个覆盖字段即可。
- 方案覆盖页改为**稀疏列表**：默认只显示有意义的项，其余通过「添加覆盖」按需出现，可移除。
- 不改任何存储格式（方案 override 文件的键与哨兵不变），不需要迁移。

非目标：
- 不改码表配置子对话框（`schema_codetable.rs`）和注释模板、自定义标点这些子对话框本身。
- 不做全局页「已被 N 个方案覆盖」的反查（R8.6，另行排期）。
- 不改 core 的合并/分层语义。

## 3. TAB 集合

纵向 TAB 在左栏，右侧是当前页；**每页内部可竖向滚动**（覆盖页不定长，本来就该滚）。

| 方案类型 | TAB（自上而下） | 与同类的差别 |
|---|---|---|
| 全拼 | 基本 / 按键设置 / 方案覆盖 / 辅助码 | 辅助码页仅在方案声明了辅助码表时出现 |
| 双拼 | 基本 / 按键设置 / 方案覆盖 / 辅助码 | 「基本」多一行双拼布局；辅助码页多一行「直接辅助码」 |
| 码表 | 基本 / 按键设置 / 整句输入 / 方案覆盖 / 码表与特殊模式 | 「整句输入」仅在方案支持时出现；「特殊模式」仅 overlay 方案有 |
| 混输 | 基本 / 按键设置 / 整句输入 / 方案覆盖 | 「基本」里只读显示构成（主/副方案）；融合策略（`schema.mix`）是全局项，本期不做方案级覆盖；没有辅助码页 |
| 英文等其它 | 基本 / 按键设置 / 方案覆盖 | 一项可覆盖项都没有时整个「方案覆盖」隐藏 |

四类方案共用同一套 TAB 外壳与「方案覆盖」页，**差别只在于哪些节进哪个 TAB**——由 `SettingsSection::tab()`
之外再加一层"方案类型 → TAB 集合"的映射决定，不为某类方案写专用页面。

- 「基本」= 方案信息 + 扩展词库（+ 双拼的布局下拉）。因为方案信息太薄，合并后内部滚动。
- 「整句输入」仅码表方案，对应现有 `SettingsSection::Sentence`，独立成页。
- 「码表与特殊模式」= 现有 `CodeTable`（总开关 + 子对话框入口）与 `Overlay` 两节。
- 「辅助码」= 现有 `AuxCode` 节。
- 标签可带计数：「方案覆盖 · 2」= 当前已生效的覆盖项数（含文件级）。有改动的 TAB 沿用现在的星号规则（见 §8）。
- 无内容的 TAB 不显示（沿用 `redirect_off_empty_tabs` 一类做法）。

**实现形态**：纵向 TAB 是 wind-setting 里新写的一个小控件（按 `Signal<usize>` 选中，行为同 `subnav` / 方案列表的
可选行），不依赖 windui 的 `Element::tabs*`。所有页**同时建好、靠 `visible_when` 切换**——
各节的工作态（勾选、下拉、行编辑器）挂在 Element 上，按需重建会丢用户刚改的值（现有代码已因此这样做，沿用）。

## 4. 方案覆盖页

### 4.1 三类内容（用户定的规则）

| 类别 | 判据 | 呈现 |
|---|---|---|
| ① 全局没有的选项 | 全局设置里不存在对应项 | 直接列出，始终显示，不进「添加覆盖」 |
| ② 方案文件已覆盖 | 方案文件（`*.schema.toml`）里写了该键，且值与全局不同 | 直接显示，来源标注「方案默认」 |
| ③ 其它 | 全局有、方案文件没写 | 默认不显示；通过「添加覆盖」出现 |

说明：
- 今天落在 ① 的项很少（特殊模式、双拼布局分别在别的 TAB），覆盖页的 ① 区默认是空的，**空则整区不渲染**；
  机制保留给以后新增的方案独有项。
- ② 的行可以编辑，编辑写入用户 override 层（不改方案文件）。行尾「移除」仅在**存在用户 override** 时可用，
  含义是「恢复方案默认」（删用户层的键），文件级的值仍在，所以这一行不会消失。
- ③ 一旦添加就写入用户 override 层，进入「已覆盖」列表。

### 4.2 行形态

- 一行 = 标签 + 控件 + 来源/说明 + 行尾**图标按钮**（移除）。移除用图标（垃圾桶或 ×，悬停提示「移除」），不占文字列。
- 控件沿用现有各行的控件（下拉、步进器、输入框、子对话框入口）。**不再有「勾选 = 自定义」那个复选框**：
  行存在即自定义。
- 添加某项时的初值 = 该项当前的**生效值**（即原来「跟随全局」档显示的值），这样添加后立刻不改变行为，
  用户再去改。
- 移除 = 写回「未设置」（沿用现有各项的 `*_write` 函数：`null` / 删键 / R3 哨兵），之后该项回到可添加清单。

### 4.3 「添加覆盖」入口与对话框

- 入口按钮「＋ 添加覆盖」放在**分类标题行的右侧**（与标题同一行），不单独占一行。覆盖页按分类分区
  （见 §4.4），每个分类标题右侧各一个按钮，该按钮的对话框只列该分类的可添加项。
  > 我的判断：每分类一个按钮比全页一个按钮更省步骤；若觉得按钮太多，可退化为页头一个按钮，对话框内仍按分类分组。
- 对话框沿用应用兼容页「添加覆盖项」的结构（`pages/compat/dialogs.rs`）：按分组列出尚未添加的项，
  勾选后确认；已全部添加的分组不显示；全空时显示「没有更多可添加的项了」。
- 被定制版精简掉（`custom_hidden`）或用户隐藏（`user_hidden`）的项**不出现在对话框里**，已存在的这类行也不渲染
  （沿用 `behavior_rows_hidden` 的判据）。

### 4.4 可覆盖项清单（现状盘点，首期范围）

| 分类 | 项 | 现有写入键 | 备注 |
|---|---|---|---|
| 候选窗 | 每页候选数 | `candidate.per_page` | `per_page_write` |
| 候选窗 | 候选排列 | `candidate.layout` | 下拉带「跟随」档 → 行内去掉该档 |
| 候选窗 | 横排时文字排列 | `candidate.text_orientation` | |
| 候选窗 | 候选文字字体 | `candidate.font_family` | `font_write` |
| 候选窗 | 候选注释 | 注释模板子对话框 | 行 = 摘要 + [设置] |
| 标点 | 默认标点（中/英） | `punct.mode` | |
| 标点 | 自定义标点 | `punct.custom_mappings` | 子对话框 |
| 输入 | 加载命令短语 | `phrases.enabled` | 本身是布尔，无「跟随」档：见 §9 第 3 条 |

加新项 = 在这张表（代码里是静态表 `OverrideField`，含 key、标签、分类、构建行函数、读/写函数）加一行，
不改对话框与列表逻辑。**起步用静态表**；是否改成由 `settings_manifest.toml` 驱动，等第二批项（码表配置并入）时再定。

### 4.5 「已覆盖」的判定（打开对话框时）

一项视为**已列出**，当且仅当：
- 用户 override 层里存在该键（含值等于全局的情况——用户显式写了就尊重）；或
- 方案文件里写了该键且值与全局不同（② 类）。

打开后的增删只改界面状态与暂存，确认才写盘（沿用 `stage_settings_edits` 的「对比 at_open 才写」模式）。

## 5. 其它 TAB 的处理

- **辅助码**：固定列出，**不走「添加覆盖」**（用户已确认）。这些选项只在辅助码页出现、别处没有，
  属于功能本身的配置而不是零散覆盖；节内保持现有行形态。
- **按键设置**：内容不变（`EntryKeys`），只是挪到独立 TAB。
- **码表与特殊模式**：内容不变，只是挪位置。码表配置的 ~20 个字段仍在其子对话框里按现有勾选行形态，
  **本期不并入稀疏列表**（子对话框自成体系，且已有「全部恢复跟随」）。
- **整句输入**：现有开关原样搬到独立页。

## 6. 对既有规范的修订

- **R8.1**（标准形态是勾选行）：在**方案设置对话框的方案覆盖页**改为稀疏列表；码表配置子对话框、
  辅助码页仍用勾选行。
- **R8.5**（含 ≥2 行要有「全部恢复跟随」）：覆盖页改为「逐行移除」；不加「全部移除」（见 §11）。
- **R8.7**（列表式只用于字段 > 30 的作用域）：判据放宽——方案覆盖页的字段合计（行为 ~8 + 将来的方案级
  UI 覆盖键 + 码表配置）已经多到常驻显示是噪音，且覆盖高度稀疏。实施时同步改 `config-design-rules.md`。
- 文案三词（跟随全局/主题/方案）不变；行内不再出现「跟随全局」档，来源标注改为行尾说明（②类写「方案默认」）。

## 7. 分期

1. **P1 纵向 TAB 外壳**：新控件 + `SETTINGS_TABS` 改为按方案类型动态集合 + 把现有节分配到新 TAB。
   **不改任何行为与存储**。验收：各方案类型的 TAB 集合正确、切页不丢状态、空 TAB 隐藏、
   搜索/深链能落到正确 TAB。
2. **P2 方案覆盖稀疏化**：`OverrideField` 静态表 + 稀疏列表 + 添加对话框 + 移除图标；
   旧的 `Behavior` 节拆掉。验收：见 §10。
3. **P3 收尾**：更新 `config-design-rules.md` R8、`override-presentation.md` 状态、文档站相应页、截图。

每期独立可合入、可真机验证。

## 8. 需要同步改动的现有机制（实施时易漏）

- `SettingsSection::tab()` / `SETTINGS_TABS` / `CUSTOM_TAB` / `split_sections_by_tab`，以及测试
  `sections_split_into_tabs_with_dividers_reinserted`、`custom_tab_index_points_at_the_custom_tab`、
  `every_content_section_belongs_to_exactly_one_tab`。
- 「TAB 星号」（现在打在「方案自定义」上，表示有自定义项）：改为打在「方案覆盖」，计数规则见 §3。
- 设置页搜索与深链：`search/index.rs` 的 `page_tab`、`--tab` 之类入口若指向方案设置的页签，要映射到新 TAB。
- `SettingsSection::ALL` 手写清单（新增变体必须加，否则 `.small()` 误用无防护网）。
- 定制版精简（`custom_hidden` / `section_hidden`）对新对话框同样生效，且 e2e 用例（`WIND_INSTALL_ROOT`）要覆盖。

## 9. 设计者已定的细节（审阅时请重点看这一节，都是设计者的判断）

1. **来源信息是 P2 的前置子步骤（P2a）**，先于 UI：核实 `schema.getConfig` 能否区分方案文件层与用户层，
   不能就在 core 加只读旁路字段。「与全局不同」= **方案文件里该键的原始值 ≠ 全局生效值**。
   「该键」以**一个覆盖字段**为单位（`punct.custom_mappings` 整表算一项，注释模板的横/竖各键算一项）。
2. **行预建、显隐切换**：覆盖页的全部可覆盖行在打开时一次建好，靠 `visible_when(已列出)` 显隐，不做行级重建。
   「移除」只是置"未列出"并清空暂存；再次「添加」时**重置为当前生效值**（不保留上次编辑的值）。
3. **移除的写盘结果**：统一走各字段现有的 `*_write(None)`（删键或写 R3 哨兵）。
   `phrases.enabled` 目前是普通布尔、总会被写：**移除 = 删掉用户层的该键**，回到方案文件/全局的值；
   实施 P2 时核实 core 对缺键的取值路径（应为 `Option` 或有默认），若不是则先补，**不改存储格式**。
4. **搜索 / 深链命中一个未添加的项**：自动把该项置为"已列出"（仅界面暂存，未确认不写盘）并滚动定位到它。
5. **TAB 标签计数与星号**：计数「方案覆盖 · N」= 已列出行数（含文件级）；星号只在**用户层有覆盖**时亮
   （文件级的不算"我改过"）。两者同时显示。
6. **子对话框型项（候选注释、自定义标点）添加时**：写入全局内容的副本（注释模板为全局当前模板，
   自定义标点为全局当前映射），保证添加后行为不变；行内只显示摘要 + [设置]。
7. **其它类方案（英文、混输等）**：所有方案都有「方案覆盖」页；某方案若一项可覆盖项都没有（定制版精简后），
   整个 TAB 隐藏。

## 10. 验收要点

- 各方案类型 TAB 集合正确，切页不丢未保存的编辑，空 TAB 隐藏。
- 覆盖页：初次打开只显示文件级项与用户层已有项；添加 → 生效值入行 → 确认后写盘；移除 → 键回到未设置；
  反复添加/移除不残留键。
- 精简/隐藏的项不出现在添加对话框，也不渲染。
- 窄窗口下 TAB 标签不被截断，覆盖页长列表可滚动。
- 所有 `SettingsSection` 变体仍被"每节恰属一个 TAB"的测试覆盖。

## 11. 仍留给实施者

- 纵向 TAB 的宽度（约 120–140 逻辑像素，需容纳「码表与特殊模式」）与窄窗口退化。
- 图标选型、动画。
- 是否把覆盖字段表改由 `settings_manifest.toml` 驱动（第二批码表配置并入时再定）。
- 不加「全部移除」按钮（项数少）。
