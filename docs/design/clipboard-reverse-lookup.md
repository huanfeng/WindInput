# 剪贴板反查

复制一段文字 → 切回输入法 → 打直通命令 `cofc` → 候选即「文本: 编码 拼音」，选中直接上屏。

与既有反查的区别在**输入方向**：既有反查要求先用拼音/码表把字打出来，才能在悬停提示里看它的
编码与读音；本功能反过来，字是从别处复制来的，用户根本不知道怎么打。

## 1. 出厂形态

```toml
[[phrases]]
code = 'cofc'
text = '$CC(default(dict.rev(clip()), "剪贴板反查（需先复制文字）"), type(dict.rev(clip())))'
weight = 2000
```

出厂**只预置单条**：`dict.rev(clip())` 省略 `n` ⇒ 整串反查（见 §2）。多字逐字展开留给用户按需
自己写，见 §5。

### 为什么是 `$CC` 而不是纯模板

⚠️ **实测反馈修正**：初版是纯模板 `{dict.rev(clip())}`，剪贴板为空时整条候选不出现 ——
而「什么都不出」与「功能坏了」在用户侧完全同形，没法自查。

纯模板的 display **既是显示又是上屏文本**，二者绑死，于是只有两个都不好的选择：
查不到时整条消失（用户一脸茫然），或者把提示语本身当文本打进文档。

`$CC` 把两者拆开，用已有函数就够，无需新机制：

| 位置 | 表达式 | 查得到 | 查不到 |
|---|---|---|---|
| display | `default(dict.rev(clip()), "提示语")` | 反查结果 | **提示语** |
| 动作 | `type(dict.rev(clip()))` | 上屏反查结果 | 求值为空 → **什么都不上屏** |

`run_command_candidate` 对 Text 动作有 `Ok(t) if !t.is_empty()` 守卫，空串不会走 push，
故提示语绝无可能被打进文档。

**副作用（正面的）**：前缀列举走廉价的 `NavCtx`（不读剪贴板、不查词库），`dict.rev` 在
那里恒为空，于是打 `co` 时这一条的标签正是提示语 —— 兼作命令名，自解释。改提示语时
要顺带想一下它在导航列表里读起来是否成立。

## 2. `dict.rev` 函数

```
dict.rev(text)                              → 整串反查，默认版式
dict.rev(text, n)                           → 第 n 个字（1 起）
dict.rev(text, n, format="${...}")          → 自定义版式
```

默认版式 `${char}: ${code_rev_all} ${pinyin}` → `我: q/trn/trnt wǒ`。

### 为什么省略 `n` 就是整串

`n` 的两种状态对应两个真实需求，用途不重叠：

| 写法 | 语义 | 谁在用 |
|---|---|---|
| 省略 `n` | **整串**交给宿主，命中码表词条 | 剪贴板反查（出厂 `cofc`）：复制「好吧」就该查到「好吧」这个词的码 |
| 给了 `n` | 取第 n 个字 | `$SS` 逐字展开（§5）：一条候选列一个字 |

**逐字列表替代不了整串**，这是本轮改动的直接动因：

1. 逐字只能拼出「各字的码」，拼不出**词条自己的码**。双拼/拼音方案下两者碰巧相等（词码 = 各字
   音节拼接），所以问题在双拼用户那里不明显；但形码方案存在**词级简码**与词条级容错码，逐字
   拼接永远拼不出来——正是「这词怎么打」最想要的那个答案。
2. 逐字列表把一条查询变成 N 条候选，用户还得自己认哪个是整词的结果；而「复制什么就查什么」
   本来就该是一条。
3. 宿主侧**不需要任何改动**：`EvalContext::reverse_lookup(text, format)` 收的就是任意文本，
   `reverse_render` → `eval_text_var` 走的 `word_codes_display` / `codetable_reverse_hint`
   本就是**按词条**查主码表反向索引。拦路的只有 cmdbar 层那句 `.chars().nth(n - 1)`。

保留 `n` 而不是删掉：`$SS` 逐字写法已在出厂注释与用户笔记里流通，删掉会让它们静默失效
（参数个数超上界 → 求值报错 → 整条短语连候选一起消失，用户零提示）。

### 命名

叫 `dict.rev` 而不是 `reverse`：**扁平的 `reverse` 已被占用**（`funcs/text.rs`，字符串按 rune
反转）。registry 按全名索引，故 `dict.rev` 与它不冲突；`dict.` 命名空间也已有 `dict.add`，
同属「查/改词库」这一域。

`pure = true` 是硬要求 —— `assert_pure_display` 只允许纯函数出现在 display 表达式里，
而本函数的全部用法都在 display 位置。

### 越界返回空串而不报错

`n` 超出字数、文本为空时返回**空串**。这是为 `$SS` 展开服务的：词条固定写 N 个元素、
各查第 1..N 个字，剪贴板不足 N 字是**常态**而非错误。若报错，`evaluate_phrase` 的 `Err`
分支会把整条短语丢掉 —— 连前几个查得到的字一起消失。

`n` 写成非数字仍然报错：那是词条作者的笔误，不是运行时的正常输入。

整串模式下「查不到」（文本不是码表词条、只有空白、反查索引尚未建好）同样返回**空串**而不是
报错：出厂 `$CC` 的 `default(反查结果, 提示语)` 正是这样接住的（§1）；写纯模板则表现为整条
候选消失。

## 3. 版式模板复用候选注释段的语法

`format` 用 `${name}` 而不是 `{name}`，两个原因：

1. **`{expr}` 在 cmdbar 字符串里是插值**。写 `format="{code}"` 会去调用**已存在**的
   `code()` 函数（触发候选时的输入编码），静默算出完全不相干的值。而 lexer 的
   `scan_dir_var` 对未知 `${NAME}` 是**原样保留字面**的（那条豁免本就是为了防止
   `UnknownFunc` → 整条候选被静默丢弃），故 `${code}` 能完整存活到本函数手里。
2. **候选注释段已经是这套语法**，变量名也复用，用户学一次。

可用变量（与 `Coordinator::eval_var` 逐项对齐）：

| 变量 | 含义 |
|---|---|
| `${char}` | 被查的那个字本身（本入口独有，注释段不需要） |
| `${code_all[:分隔符]}` | 该字在码表里的**全部**码位，默认 `/` 连接（`我` → `q/trn/trnt`）|
| `${code}` | 只取**最长**的那个全码（`我` → `trnt`），与候选注释段同义 |
| `${pinyin}` | 带声调注音 |
| `${chaizi}` | 字根串（仅单字） |
| `${chaizi_code}` | 该字在拆字库里记录的编码（仅单字） |
| `${chaizi_all[:分隔符]}` | 逐字字根，默认空格连接 |
| `${dict}` | 用户挂载的注释词库释义 |

注释段专属的 `${code_hint}` 在这里**不存在** —— 它取自候选的引擎产物，而剪贴板文本没有
候选身份。写了会被渲染层原样回显 `${code_hint}`，让人看见拼错。

### 为什么默认用 `${code_all}` 而不是 `${code}`

⚠️ **实测反馈修正**：初版默认版式用的是 `${code}`，结果「我」在五笔下只显示 `trnt`，
而它实际有 `q` / `trn` / `trnt` 三个码位。

根因是 `codetable_reverse_hint` 取的是 `codes.last()`，而 `codes_of` 按**码长升序**返回，
故它给的恒是最长的全码。那个取舍对候选注释段是对的 —— 注释是候选右侧的窄条，塞下三个码
会把候选行撑爆；但它是**显示空间**的取舍，不是语义。

剪贴板反查回答的恰恰是「这个字怎么打」，**简码才是最有用的答案**，只给全码等于给了最不
实用的那个。故新增 `${code_all}` 走 `word_codes_in`（全部码位 `/` 连接）并作默认。

命名照搬同文件 `chaizi` / `chaizi_all` 的既有惯例：不带后缀取单个，`_all` 取全部、
且可用 `${code_all:分隔符}` 换连接符。`${code}` 保持原义不动，故与注释段的「同名同义」
仍然成立。

### `${char}` 不计入「查到了」

`render` 的语义是「变量全空 ⇒ 整体返回空串」，这正是「查不到就不出候选」的实现方式。
但 `${char}` 恒有值（它只是把输入原样回显），若算进去，这条规则就永远不会触发：
剪贴板里是英文字母或标点时，会渲染出孤零零的 `A:` 并当作正常候选出现。

故 `reverse_render` 单独记录「除 `char` 外是否有变量填上了内容」，没有则返回空串。

## 4. 分层：谁做什么

| 层 | 职责 |
|---|---|
| `wind-cmdbar` `fn_dict_rev_named` | 省略 n 时整串交出、给了 n 挑第 n 个字（按 rune）、填默认模板、校验参数 |
| `EvalContext::reverse_lookup` | 纯粹的能力注入面 |
| `wind-coordinator` `reverse_render` | 反查取值 + 模板渲染 |

**渲染必须在 coordinator 侧**，因为 `wind-cmdbar` 刻意零 `wind-*` 依赖，够不着模板渲染器
（`comment.rs`）与反查表。在 cmdbar 里另写一份占位符替换，就会变成同一套模板语法的第二份
实现 —— 而 `comment.rs` 那份带着可选段 `{}`、`${a|b}` 取首非空、空变量吞空白这些细微语义，
两份必然漂移。

`eval_text_var`（裸文本）与 `eval_var`（候选）刻意挨着放：它们是同一套变量词汇的两个入口。

### `EvalContext::reverse_lookup` 无默认实现

与 `clip` 同处置，而不同于 `quick_var`。判据是**漏接会怎样**：

- `quick_var` 漏接得到空串是**正确答案** —— 短语上下文本就没有「当前解析出的年月日」；
- `reverse_lookup` 漏接得到的空串是**错的** —— 调用方明明要查，却只表现为「候选出来了但
  内容是空的」，没有任何报错。

给了默认实现，这种漏接就再也没有编译期的抓手。全部 6 个实现各自表态：

| 实现 | 行为 |
|---|---|
| `PhraseCtx` | 真实（宿主注入回调） |
| `NavCtx` | 空 —— 前缀列举要为每条候选跑一次求值，不能摊 N 次词库查询到按键线程 |
| `CmdbarCtx` | 真实 |
| `QuickCtx` | 空 —— 快捷输入格式表只排列本次解析出的量 |
| `MemoryContext` / `QuickTestCtx` | 测试桩 |

### `PhraseHost` 取代并排的回调形参

`lookup` / `lookup_at` / `expand_dict_value` 原本尾随一个 `clip` 回调，本次要再加一个。
按 `ProcSpawn` 立的规矩收进结构体：加字段时每个构造点都会编译失败、被迫面对新能力；
而多加一个形参很容易被某个调用点漏掉，表现为「某个入口下这个功能就是不出来」且无报错。
本次改造就是靠编译器一次逼出了全部 6 个缺口。

## 5. 多字展开：元素个数即上限

`$AA` **用不了** —— 它的炸开在**解析期**，且强制要求字面字符串，`clip()` 是 Call 表达式，
直接解析失败。

`$SS` 可以：它的元素校验只要求是字符串字面量或 `$CC`，而**字符串字面量允许带插值**，
求值发生在 `expand_array`（运行时，带 ctx）。只有元素**个数**在解析期固定 —— 这恰好就是
「最多查几个字」的表达方式，不需要任何配置键：

```toml
text = '$SS("反查", "{dict.rev(clip(),1)}", "{dict.rev(clip(),2)}", "{dict.rev(clip(),3)}")'
```

剪贴板不足位数时，尾部元素求值为空并被丢弃。

⚠️ 元素必须是**无动作**的纯插值字符串，不能包 `$CC`：带动作的数组元素在
`lookup_at` / `expand_dict_value` 里会被**整个丢弃**（「带动作的嵌入 $CC 需元素级源，后续补」）。
包了 `$CC` 的后果是候选凭空少几条而毫无报错。

## 6. `DictExpansion::None` 与 `Drop` 必须分开

⚠️ **实测栽过一次**：剪贴板为空时，用户词库里的 `{dict.rev(clip())}` 候选显示成了模板
**源码字面**，看起来完全像「这个功能没生效」。

根因是 `expand_dict_value` 把「求值为空」映射成了 `DictExpansion::None`，而 `None` 在词库
路径里的语义是**「这不是特殊语法，保留原文当文本用」**（`finalize_candidates` 收到 `None`
就 `expanded.push(cand)`，原样保留）。于是：

| 真实情况 | 应有呈现 | 错误映射的后果 |
|---|---|---|
| 这不是特殊语法（普通词条 `你好`） | 保留原文 | 正确 |
| 是特殊语法，但这次查不到 | **整条不出** | 显示 `{dict.rev(clip())}` 源码并原样上屏 |

两者的正确呈现完全相反，故不能共用一个变体。现由 `DictExpansion::Drop` 承载后者，
`finalize_candidates` 收到它直接不 push。

短语路径（`lookup_at`）没有这个问题 —— 它本来就是「不 push 即消失」，没有「保留原文」
这个概念。**这正是为什么短语层测绿证明不了词库路径**：两条路径对同一件事的表达方式不同。

`$SS` 组的 `items.is_empty()` 分支同理（此前也返回 `None`，会泄漏 `$SS(...)` 源码）。

## 7. 顺带补上的空串守卫

求值型 display 落空是本功能引入的**常态**，而此前四条产候选的路径里有三条没有空串守卫，
会产出点了没反应的空白候选：

| 位置 | 分支 | 此前 |
|---|---|---|
| `lookup_at` | `Single { actions: [] }` | 无守卫 |
| `lookup_at` | `Array` 元素 | 无守卫 |
| `lookup_prefix_at` | `Phrase::Template` | 无守卫 |
| `lookup_prefix_at` | `Phrase::Literal` | **已有**（`display.is_empty()` → continue） |
| `expand_dict_value` | `Single` / `Array` | 无守卫 |

`Literal` 分支早就有这道守卫（注释写着「全空展开不出空候选」），其余分支只是没跟上。

出厂 `system.phrases.toml` 里**没有任何纯模板短语**，故 `lookup_prefix_at` 那条守卫对
现有短语零影响，只作用于新增的 `cofc` 与用户自建的模板短语。

## 8. 已知边界

- **macOS 上不出候选**。候选构建期的 `clip` 回调在非 Windows 分支恒返回空串，这是既定行为
  （`handle_candidate.rs` 注释明写「勿因 trait 化顺手统一成读 Pasteboard」）。`clip()` 恒空 ⇒
  无字可查 ⇒ 整条候选不出现。反查本身没有平台约束，受限的是剪贴板读取那一环。
- **前缀列举里显示的是提示语而非反查结果**。`NavCtx` 不读剪贴板、不查词库（见 §4），
  故 `cofc` 在打 `co` 时走 `default` 的回落分支。这不是缺陷 —— 那个位置本就该显示
  「这条命令是干什么的」，而不是某次剪贴板内容的反查结果。
- **`has_code_prefix` 对瞬时短语判为不存在**。该判据传空宿主（它只问「有没有这个码」，
  不值得为它读剪贴板 / 查词库，这是每次按键都过的路径）。当前调用方传的都是单字母或
  z 缓冲串，那些前缀下都还有别的短语撑着，故不影响既有判定；若将来出现「整个前缀只剩
  一条瞬时短语」的情形，这里会翻转成 false。
- **`eval_command_text_only` 不再是「无锁」**。`dict.rev` 经 `reverse_render` 取
  `self.reverse` 读锁。这与候选构建路径是同一个加锁顺序，不引入新的死锁面；但 std 的
  `RwLock` 读锁不可重入（写者排队时同线程重入读会死锁），故 `reverse_render` 的调用方
  不得已持有该读锁。
