# 中英/数字间自动空格 与 英文后智能标点

状态：设计已定（2026-11-06，11-07 撤回英文词间空格的按需补），实施中（分支 `feat/auto-spacing`）。阶段 1–3
已完成，阶段 4 做了 Windows 主键盘数字，阶段 5 的文档站待做。

## 1. 需求

1. **中英间自动空格**：混输时得到 `中 en 中`。现有 `commit_space` 只在英文**后**补，英文前面没有。
   数字前后同理（单独开关，默认关）。Markdown 类应用自带空格处理，要能按应用关掉。
2. **英文后智能标点**：同「数字后智能标点」，英文单词后的指定标点直出半角（`Node.js`、`a/b`、
   `snake_case`）。

## 2. 两者的共同底座：输入序列的「上一笔末字符」

数字后智能标点的判据早已定为**只认输入法自己记录的输入序列**、不认文档现读（理由见
`wind_tsf/include/SmartPunctPrevChar.h`：现读受宿主支持度左右、时灵时不灵；光标碰巧落在旧字符后
不等于用户意图）。两个新需求问的是同一类问题——「上一笔进文档的是什么」——只是从「是不是数字」
扩成「是哪一类字符」。故沿用同一原则，把客户端的数字记账扩成**字符记账**。

### 2.1 协议：`KeyPayload` 追加 `seqChar`（18 → 20 字节）

```
uint16_t seqChar;  // 输入序列里最近进文档的字符（代表值），0 = 不可知
```

- 服务端 `KeyPayload::from_bytes` 对 18 字节旧包读成 0（= 不可知，功能不触发），不报错。
- `prevChar` 语义**不变**（数字后智能标点、智能符号 press2 守卫照旧），两个字段各管各的。
- 取值规则（客户端，三平台一致）：
  - 经输入法上屏的文本：取末尾**码点**的首个 UTF-16 单元（BMP 即本字符；辅助平面取高代理——
    服务端据此把 CJK 扩展 B–H 认成汉字，emoji 所在的 1 号平面认成「其它」）。
  - 透传进宿主的可见字符键：字母报 `'a'`，数字报本数字，空格报 `' '`，其余可见符号报 `'?'`
    （只需要类别，不需要键盘布局下的确切字符）。
  - 编辑/导航键（方向、Home/End、退格、Delete、回车、Tab…）、焦点切换、鼠标点击（看得见的平台）：报 `0xFFFF`（不知道）。
  - 单击 Shift 切中英、工具栏切换：**不清零**（用户定：「切换不清零」）。
- DLL 只报事实，策略全在服务端（与 `_lastPassthroughDigit` 同分工）。

### 2.2 服务端：边界上下文

`State` 记一个「插入点前一字符」`boundary_prev: Option<char>`：

- keydown 到达且**无输入会话**（`has_input_session` 为假）时，用 `seqChar` 重新锁存——组合中的
  后续按键不改它（组合期间客户端序列会被组字键清掉，真正的「前一字符」是组合开始时那个）。
- 服务端每发出一笔上屏，就把它更新为该笔文本末字符（覆盖分步上屏、顶码、鼠标点选）。

字符分类（`wind-punct` 纯函数）：`Cjk`（汉字、假名、CJK 扩展的高代理）/ `Latin`（ASCII 字母与
拉丁扩展字母）/ `Digit`（ASCII 数字）/ `Other`（空白、标点、全角字符、不可知）。

## 3. 需求 1：切换处补空格

### 3.1 规则：空格作为**切换后那一笔上屏的前缀**

中英 / 中数**切换处**，在切换后那一笔上屏时看交界补空格：

| 交界（前一字符 → 本笔首字符） | 补空格的条件 |
|---|---|
| Cjk → Latin、Latin → Cjk | `input.spacing.cjk_latin`（默认关） |
| Cjk → Digit、Digit → Cjk | `input.spacing.cjk_digit`（默认关） |
| 其余（连续英文、任一侧 Other） | 不补 |

- 标点永远不前补空格；用户自己按过空格（前一字符是空白）也不补。
- **英文词间空格不归这里**（用户定，2026-11-07）：`schema.english.commit_space` / `input.temp_english.commit_space`
  保持原来的「上屏后立即补尾随空格」——打完 `hello` 就看得见后面有没有空格，可预期。尾随空格之后切到
  中文时前一字符是空格，自然不再补，得到 `中 Hello World 中`。没开 `commit_space` 时连续的英文之间
  一概不管，切回中文时才补。
  - 中文方案主路径里混入的英文词库候选（码表 / 拼音的英文候选）跟随临英那份开关（用户定，2026-11-07）：
    与临英、快捷输入同属「中文里插一个英文词」。原码、短语不算；快捷输入有自己的出口，不重复补。
  - 英文词后要接标点时用标点**顶屏**（`hello` + `,`），标点紧贴单词、不带尾随空格；`commit_space` 只在选词
    上屏时补。选词上屏后（已带尾随空格）再按标点**不换位**（用户定，2026-11-07），得 `hello ，`。
    测试钉在 `auto_spacing.rs` 的 `punct_top_commit_after_english_word_has_no_space`。
  - 曾试过「词间空格也改成补在下一个词前面」：上屏后看不出接下来会不会补，实测体验不可预期，已撤回。
- 统一出口：`handle_key_event_policed`（桌面按键）与 `select_candidate_at`（鼠标点选、移动端候选栏）的动作
  做一次后处理，给 `InsertText` / `InsertTextWithCursor` / `CommitAndHoldComposition.commit_text` /
  `CommitThenDeferComposition.commit_text` 的文本加前缀。不散落到几十个上屏点。
- **文档兜底只做抑制**：宿主读得回文档且光标前已是空白（`prevChar` 为空白）时不补。只会少补、不会多补，
  主要防 Markdown 编辑器插件自己补了空格的情况。与「别让文档值否决序列」那条不冲突——那条防的是
  误判成「不是数字」从而少出半角，这里的失败方向是少一个空格，安全。

### 3.2 应用独立配置

`compat.toml` `[[apps]]` 新增 `auto_spacing = false`（字段级叠加，未写 = 跟随全局），关闭该应用的
中英/中数空格（英文词的 `commit_space` 属英文输入本身，不受影响）。典型对象：自带 pangu 类空格处理的
Markdown 编辑器、终端、代码编辑器。

### 3.3 分期

- **一期**：经引擎上屏的文本（中文候选、临英、英文方案、混输/快捷输入英文候选）。各平台无需改上屏逻辑。
  「数字 → 中文」也在一期覆盖（数字已在序列里，空格前补在中文上）。
- **二期**：透传键之前补空格——中文模式空缓冲下的数字键、英文模式下的首个字母。需要 DLL 在
  「序列末字符是汉字且对应开关开」时吃下该键交给服务端出 `" 3"` / `" h"`，受
  「C++ 吃键集 ⊆ Rust 出字集」约束，开关要推给 DLL。
  - 数字（Windows 已做）：开关经 `CONFIG_KEY_SPACE_BEFORE_DIGIT` 按客户端推（全局 `cjk_digit` 且应用未关）；
    DLL 只吃主键盘与小键盘的 0-9、无修饰、CapsLock 关（`NumberKeyPolicy.h`）。Windows 下服务端对「`seq_char` 是汉字的
    空闲数字键」**恒出字**、不看开关——DLL 的开关慢一拍时最多少补一个空格，不会丢键。
    macOS / Linux 客户端每个键都发给服务端、按回复决定透传，所以那里这条臂**必须看开关**（及应用规则）：
    关着时照旧透传，汉字后的数字仍交给宿主（数字当快捷键的场景不受影响）；开着时顺带也就补上了空格。
    判据单点在 `Coordinator::digit_after_cjk_outputs`，三处出字：主键盘数字臂、小键盘 direct 臂、
    follow_main 归一化后的小键盘闸（它把数字也当 `punct_char` 先截住，要单独放行）。运算符不在其列。
  - 英文模式首字母：**不做**（用户定，2026-11-07）：主场景是中文里穿插英文；英文模式下吃字母会让
    vim、游戏、快捷键多的程序出异常。

### 3.4 客户端不可知时（退格、方向键……）

两个「不知道」：`0` = 客户端不带这个字段（旧版），`0xFFFF`（`SEQ_CHAR_UNKNOWN`）= 客户端在记账、但这一刻
不知道（导航键、回车、焦点切换、鼠标挪光标之后）。两者都按 `Other`，一律不补。联想态不重新锁存，
沿用服务端推进好的值。

退格之后同样是「不知道」：组字中的退格不写文档、记账不动；空编码退格交给宿主，客户端报 `0xFFFF`，
下一笔两侧都不补（`你好` 退格成 `你` 再打 `Hello` 得 `你Hello`）。用户删掉自动补的空格后也不会再补回来。
曾考虑「不知道时退回读文档」，用户定不做（2026-11-07）：违背只认输入序列的原则，且不少宿主读不到。

### 3.5 已知限制

- 鼠标挪光标，三端各自识别，识别到就报 `0xFFFF`：
  - **Windows**：DLL 在 `OnEndEdit` 判——选区变了、鼠标按着、这次编辑没改文本（`WindInputSeq::CursorMovedByMouse`）。
    **不用**服务端的 `selection_changed`：透传字符进宿主、宿主晚到几百毫秒的回声都会让它判成「用户移动光标」，
    误把数字后的记账作废（实测：数字后的汉字不补空格）。OnEndEdit 晚于鼠标抬起的宿主会漏判（多补一个空格）。
  - **macOS**：只比鼠标按下计数（`CGEventSource.counterForEventType`，左 / 右 / 其他键之和）：记账之后点过鼠标就报
    不知道。不读 `selectedRange()`——跨进程调用，放不进按键热路径。点工具栏之类的点击也算，失败方向是少补。
  - **Linux**：两条。宿主发 `reset`（GTK 点击会发）时作废；宿主支持周边文本时，每次按键前拿宿主报的光标位置比
    「预期光标」（每次写进文档按字数往前推），对不上就作废（Qt 系点击只报光标位置、不发 reset）。上屏那一刻 Qt 会
    先报「编码已清、新字未插」的中间态，所以放在按键时判、并把写入前那一刻的位置当回声忽略——但光标后紧跟着
    刚上屏的字时是用户点回了那里，不算回声。位置对得上时再比光标前的字（透传键按类别比），防点到别的行同一列。
    周边文本是滑动窗口或更新滞后的宿主（Chromium 长段落）上比对会时准时不准，失败方向是少补。Electron 点击会
    切一次焦点，走焦点切换的清零。既不发 reset、又不报周边文本的宿主识别不了。
  - KDE 虚拟机实测（Kate / VS Code）：点到行首打数字不补、连打与透传数字后补对、点在行尾光标没动时照常补。
- HoldComposition 方案下顶屏的待定标点取武装串（中文），不经英文后智能标点。
- 移动端候选栏点选会经过统一出口，但从不锁存，交界判断只靠服务端自己的上一笔；出厂两个开关都关，暂不处理。

### 3.6 范围外

移动端：按键路径不经 `handle_key_event_policed`、客户端也不报 `seqChar`，本功能不触发。移动端本来就有
自己的一套英文自动空格（`wind-mobile` 的 `auto_space`，带标点换位），与这里互不相干。

### 3.7 全角

全角字母与全角数字归一类（`WideLatin`）：只参与英文词间空格（补全角空格 U+3000），不参与中英交界——
全角态的排版本来就不在中英之间补空格。

## 4. 需求 2：英文后智能标点

- 配置：`input.punct.smart_after_latin`（默认关）+ `input.punct.latin_smart_list`（默认 `./_:@`，
  实际使用后再调）。与数字那一对独立。
- 判据：前一字符为 Latin 且标点在列表内 ⇒ 按英文半角出。前一字符的来源：
  - 空缓冲直接按标点：`seqChar`；
  - 顶屏（临英 / 混输英文候选 + 标点键）：本次上屏文本的末字符。
- 智能符号连按两次的方向与数字后一致（反向：press1 半角 → press2 中文），作为误转的补救。
  ⚠️ 只在空缓冲直接按标点时反向：主路顶屏时 press1 在顶屏之前就武装了，那时还拿不到被顶出
  候选的末字符（数字后智能标点在顶屏时同样不反向）。
- 空格的处理：前一字符是空格（用户自己按的，或 `commit_space` 补的尾随空格）⇒ 视为英文语境结束，
  按默认中文标点。要 `Node.js` 这类紧贴的写法，英文词就别开 `commit_space`。
- 已知取舍：`.` 在列表里会让「我用的是 iPhone。」变成 `iPhone.`，靠连按两次补救；
  默认列表不含 `,;!?`（中文句子里英文词后接中文逗号很常见）。
