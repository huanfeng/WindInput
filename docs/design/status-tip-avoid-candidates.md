# 状态提示泡：默认位置与避让候选窗

## 为什么做

状态提示泡跟随光标时固定弹在光标下方，候选窗也在光标下方，组字中弹的提示（切注释态、单字模式……）
会盖住第一个候选。先弹提示、紧接着打字出候选窗时同样会盖住。

## 要做的

1. **默认位置**（维护者定）：`ui.status.caret_side = "below"`（出厂）/ `"above"`，设置页「默认位置：光标下方 / 光标上方」。
   只在跟随光标（`position_mode = "follow_caret"`）时生效。
2. **自动避让**（维护者定，常开、不设开关）：提示泡与候选窗重叠时换位置。与默认位置不冲突——默认位置是首选，
   避让只在首选位置被候选窗挡住时才起作用。

## 落位规则（跟随光标）

依次试，取第一个放得下（不出工作区）且不与候选窗相交的：

1. 首选侧（默认位置）；
2. 光标另一侧；
3. 候选窗外侧：候选窗在光标下方就贴在候选窗下沿外，否则贴在上沿外；那边放不下换另一边。

都不行时退回首选侧（与现在一样，下方放不下翻上方）。没有候选窗时只有 1、2 两步，即现在的「放不下就翻」。

固定位置（`fixed`）与锚点模式不避让：位置是用户自己挑的。

## 时机

- 弹提示时候选窗已显示：按上面的规则落位。
- 提示还在、候选窗后出现或换了位置：重新落位一次。

## 各平台

| 路径 | 候选窗位置从哪来 | 提示泡落位 |
|---|---|---|
| Windows 本地窗口 | 管理器里候选窗的窗口矩形 | 管理器算定 |
| Windows 宿主渲染（host_render） | 管理器写给 DLL 的候选窗帧位置 | 管理器算定，DLL 原样摆放 |
| macOS `.app` / Linux addon（overlay） | 管理器推给宿主的候选窗**建议**落点 | 避让生效时改用 `FOLLOW_CANDIDATE`：宿主按候选窗实际落点平移，候选窗被宿主翻到光标上方时提示泡跟着走；不需要改宿主 |

几何判定是一个纯函数，三条路径共用，单测覆盖。
