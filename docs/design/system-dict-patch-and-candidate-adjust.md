# 系统词库补丁与候选调整增强

状态：草案，待维护者定 §8 的几处取舍后再分阶段实施。

## 1 要解决的事

1. 系统词库能在界面里编辑（改权重、屏蔽；加词进用户词库），改了之后**软件升级仍随新版更新**。
2. 系统词库（主库 + 分类词库）的开关从「方案管理 → 扩展词库」搬进词库窗，与用户词库统一操作；拼音分类多，要有不刷屏的列法。
3. 删除分层：能**定向**屏蔽系统词库的某条，不波及用户自己加的同一个词。
4. 修 bug：候选调整里删过的词，再手动加词也永远出不来。
5. 拼音也能调候选位置（现在只有置顶），在智能组句、词频变动、简繁转换下仍有确定语义；明确双拼与全拼是否共用。

## 2 现状与成因（2026-11-12 核查，路径相对 `wind_input/crates/`）

- **系统词库零编辑能力**：用户能动的只有附加库的 `enabled`（`schema_overrides/<方案>.toml`，`wind-config/src/schema.rs:1104-1127`）。想改词只能把整个 yaml 复制到用户目录，由 `resolve_dict_file` 整体替代安装目录那份——此后升级不再生效，且主库 65 万条复制一份很重。
- **规模**：拼音主库 `rime_frost` 引 6 张子表（8105 / 41448 / base 36.6 万 / ext 23.6 万 / others / corrections），另随包 16 张分类（15～4.9 万条），用户还可往 `pinyin/ext/` 放 B/C 档大库。
- **开关入口**：设置端 `dialogs/schema_manager.rs:6187-6252` 平铺列表，不分组。用户分库则在词库窗中栏（`pages/dict/category_nav.rs`）。
- **删除只有一种语义**：右键删系统词 → `delete_shadow(data_schema_id, code, text)`（`wind-coordinator/src/handle_candidate.rs:5586`）；读端 `wind_candidate::apply_shadow` 按 `text` 过滤，**不看来源**（`wind-candidate/src/shadow.rs:63`）。
- **删了再加不显示的成因**：
  1. 删系统词留下 `deleted` 里的 `text`；
  2. 用户随后手动加同码同文的词：`CompositeDict` 把它与系统词按 text 合并为**一条**候选（`wind-dict/src/composite.rs:186-300`），即使不合并，shadow 也按 text 一并滤掉；
  3. 所有加词入口（`add_user_word`、造词、转正、设置页、导入）都不查也不清 `deleted`；能清的只有置顶 / 恢复默认 / `shadow.removeRule` / `shadow.clear`。
  - 结论：**在候选层按 text 删，原理上分不出删的是哪一层**；定向删除必须下沉到词库层（合并之前）。
- **拼音调序**：只有置顶，前移后移在写端被拒（`handle_candidate.rs:5362`）。规则 key 是原始击键串（全拼保留 `'`），双拼能完整转换时存连写全拼（`hc`→`hao`），故全拼/双拼共用 `data/pinyin/shadow.dict.yaml`，已知窄串扰 `nh`→`nang`。
- **简繁**：转换只在上屏时做（`handle_mode.rs:1225`），候选与规则都用转换前文本——**OpenCC 不会让规则失配**，用户顾虑的「候选不固定」主要来自整句、词频与学词，不来自简繁。

## 3 系统词库补丁层（核心）

### 3.1 思路：记差异，不复制

不复制系统词库，只在用户数据里记**对它的改动**，加载时叠加。升级换了系统词库，补丁照样叠上去；补丁里指向已不存在词条的行标「失效」，界面可一键清理。这与 `compat.toml` / `schema_overrides` 的「每层只记差异」是同一思路（见 compat 分层设计）。

### 3.1a 与候选调整的分工：两层，不合并

| | 系统词库补丁 | 候选调整（shadow） |
|---|---|---|
| 改的是 | **词条**：某本词库的「编码 → 词」 | **呈现**：某个输入码下候选窗的排法 |
| 键 | `(dict, 词条编码, 词)` | `(数据方案, 输入串, 词)` |
| 生效 | 查词库时、合并之前 | 全部排序之后的最后一步 |
| 波及 | 用到该词条的全部路径（简拼、前缀、整句、反查、编码提示） | 只有这一个输入串 |
| 对象 | 只有系统词 | 任何候选，含整句、逆切分段、补全等合成候选 |

码表上两者大体重合（输入码≈词条编码，差在前缀 / 逐码提示 / 反查）；拼音上差别很大——补丁屏蔽「shi jian 时间」会让 `shijian` `sj` `shij` 与整句里的「时间」都消失，候选调整只管当前输入串。两者键与生效位置都不同，存两份文件、分两个列表，界面上互相标注状态（§6）。

- **加词不进补丁**：加词一律进用户词库或用户分库，补丁只「修正系统词条」，避免用户不知该往哪加。
- 候选窗右键删除如何在两层间分流，待拼音词库逻辑与用户需求评估后定（§9）。

### 3.2 文件

```
data/<数据方案>/
  system.patch.yaml     对系统词库的改动（新增）
```

Rime 风格表格，列 `text, code, weight, op, dict`：

| op | 含义 | weight |
|---|---|---|
| `weight` | 改某条系统词的权重 | 新权重 |
| `hide` | 屏蔽某条系统词 | 空 |

- `dict` 为词库 id（`pinyin_main` / `cell_idiom` / `dir:…`）；必填。键是 `(dict, code, text)`，**按编码定向**——屏蔽「shi 是」不影响「shi 事」，也不影响其它编码下的「是」。
- 按数据方案存（全拼双拼共用 `data/pinyin/`），与用户词库、shadow 一致。
- 文件头一行自述，走 `data.beginEdit` 外部编辑，进备份。

### 3.3 生效位置：查询期叠加，不重编系统缓存

主库重编要数秒且峰值高，不能每改一条就重建。故：

每个系统词库带一张 `(code, text) → Hidden | Weight(w)` 的小表，在**该库出结果时**改写；用户层同码同文的词不受影响。落点码表、拼音不同（2026-11-12 核查更正）：

- **码表**：在 `SystemDictLayer`（`codetable-system` / `codetable-extra-*`）出结果时、进 `CompositeDict` 合并前。
- **拼音**：系统词**不经过** `CompositeDict`——引擎直接持有 `CachedDict`（`wind-engine/src/pinyin/mod.rs:1186`），`DictManager` 里只有用户层与临时层。须在 `CachedDict` 的查询方法里过滤：`search_with_boundary`、`search_prefix_with_boundary*`、`search_prefix`、`search_abbrev_weighted`（`wind-dict/src/cached.rs:535-748`），含 `Layered` 分支与简拼段。这样精确、整句建图、混合简拼、残码、子短语、补全、纯简拼、单字兜底、纠错、双拼降级都能盖住。
- **拼音词条屏蔽仍会漏的路径**（屏蔽的是一条词条，不是这几个字）：
  1. 整句由别的节点拼出同文（「时」+「间」→「时间」，`lattice.rs:627`）；
  2. 同文的其它读音 / 其它编码 / 模糊变体；
  3. 用户层、临时层的同文记录（整句、分步上屏会经 `learn_phrase_on_commit` 学进临时层）；
  4. 读错音召回表、联想（独立反查索引 / bigram / 联想历史）、英文混入、短语；
  5. 另一个实例：码表整句另开的 `rime_frost`、造词读音索引 `CharPinyinIndex`。
  这些对「词库编辑器里精确屏蔽一条」是可接受的；对「候选窗里删一个错词」不够（§4a）。
- 补丁变更走 `dict.reload` → 只重建小表，不碰系统缓存指纹。

**改权重能动什么**（拼音不走 `weight_norm`，直接用 raw weight）：

- 能：同层内先后、整句节点打分（`ln(w/T)`）、补全能否上浮（`w>0`、`≥100`、近距离取前 8）、简拼 64 条 / 补全 top-N 截断窗口里留不留得下、`w=0` 并入简拼层的语义。
- 不能：消费长度与匹配层级（精确>简拼>前缀>子短语）、词频位次（`base_pos/2^count`，与权重无关）、shadow、单字兜底、裸声母加成、读错音召回。
- 故界面文案要说明「权重决定同类候选之间的先后与整句选词，越不过层级与词频」，固定位置请用候选调整。

### 3.4 与现有「整体覆盖」的关系

用户目录同名文件整体替代的机制保留（方案作者 / 高级用户），界面不提供「复制系统词库到用户目录」按钮；文档写明它会让该库停止随版本更新。

## 4 删除分层与加词联动

右键「删除」按候选**来源**落到不同载体（来源判定沿用 `delete_candidate_by_source`）：

| 候选来源 | 删除写到 | 效果 |
|---|---|---|
| 用户词 / 临时词 / 用户分库 | 真删该词条（拼音多字：所有编码真删**并**屏蔽这个词，§4a） | 码表不变；拼音见 §4a |
| 短语 | 软禁用 | 不变 |
| 码表系统词（含扩展库） | **`system.patch.yaml` 的 `hide`**（拟） | 只屏蔽系统层那条，含前缀 / 逐码提示 / 反查 |
| 拼音多字系统词、拼音整句 | **屏蔽这个词**（§4a） | 拼音数据方案下所有输入都不再出现 |
| 拼音单字 | shadow `delete` | 只在当前输入串下隐藏 |
| 码表合成候选（整句、逆切分段等无单一词条） | shadow `delete` | 不变，按 (code, text) 隐藏 |

合并候选（系统+用户同码同文）右键删除：码表只删用户那条（真删），系统层那条仍在则继续显示——菜单文案按此说明「删除我加的词」。
拼音多字的合并候选按 §4a：真删用户那份**并**屏蔽这个词，系统那条也不再出现（用户要的是「别再出现」，§8 第 10 条）。

**加词联动**（修 §1.4，已实现）：**单条**显式加词（候选窗加词、快捷加词、命令栏 `dict.add`、设置页加词与改词、单条转正）成功后，对同 `(数据方案, code, text)`：

- 清掉 shadow `delete`；
- 不动 `system.patch` 的 `hide`（用户加的是用户词，系统那条仍屏蔽也无妨，候选照样出现）。

自动学词（上屏学习、自动造词、临时词自动晋升）**不**清删除标记——用户删过的组合不该因为又打到一次就复活。批量操作（导入、全部转正）也不清，结果里报「N 条在候选调整里被隐藏」（§8 第 9 条）。

存量 shadow `delete` 不迁移（无法判定当初删的是哪一层），继续有效；词库窗「候选调整」列表里给它们一个「转为屏蔽系统词」的批量操作，作为可选整理。

## 4a 拼音的「屏蔽这个词」（按文字，不按编码）

**依据**：拼音用户删词要的是「这个词别再出现」，不是「这个码下不出现」——GH#269（小鹤双拼）
删的是手滑造出的错词，原话「就当作没有输入过一样」；没有一条拼音反馈要求只在某码下隐藏。
码表用户（GH#61、GH#2）天然是「这个码下不出现」。§3.3 已列出：词条屏蔽在拼音下会被整句、
其它读音、临时词、联想等路径绕过，不能满足这个诉求。

**三种删除语义并存**：

| | 屏蔽这个词（新） | 屏蔽这条词条（补丁，§3） | 当前编码下隐藏（shadow，现有） |
|---|---|---|---|
| 键 | `(数据方案, 文字)` | `(dict, 词条编码, 文字)` | `(数据方案, 输入串, 文字)` |
| 覆盖 | 该数据方案下所有输入串、所有来源 | 这本词库这一条 | 这一个输入串 |
| 用在 | 拼音右键删除**多字**的系统词 / 合成词（菜单「屏蔽该词」） | 词库窗精确编辑 | 码表右键删除；拼音单字；显式选「在此编码下隐藏」（§9） |

- **只限拼音，码表不给**（维护者定）；英文后来也给，见 §8 第 11 条。
- **单字排除**：全局屏蔽「是」等于这个字打不出，拼音单字仍只在当前编码下隐藏。
- **用户词 / 临时词**（含与系统词同文的合并候选）：真删这段文字在所有编码下的用户 / 临时条目，清掉它的
  词频与联想记录，**并且同样记屏蔽**。只删不屏蔽不够：GH#269 的错词正是分段上屏学进临时词库的，删了会被
  再学回来；学过的整句真删后组句仍会原样拼出它（维护者 2026-11-12，§8 第 10 条）。
- **存储**：复用 shadow 文件，`code = *` 表示所有编码；词库窗候选调整列表里同列。
- **加词联动**：单条显式加词撤销屏蔽，与 §4 同一收口；批量不撤、只报数（§8）。

**整句**——屏蔽要在两处生效，否则首选会退成只覆盖前半截的词、空格上屏一半：

1. **建图**：被屏蔽的文字不作为词节点进入整句图（系统、用户、临时各来源都排除）。
2. **出结果**：整句文字等于被屏蔽的文字时，用 N-best（`viterbi.rs:379 decode_nbest`，出厂 k=1）多取 2～3 条，取第一条未被屏蔽的，首选仍覆盖整串；全被屏蔽才退回最长词。
3. 不拦：被屏蔽的文字作为更长整句的一段、由更小的块拼出（按子串拦误伤太大，且少见）。

**分段上屏又造出这个词**：屏蔽优先——上屏照常，但 `learn_phrase_on_commit` 及其它自动学词路径
**不学**被屏蔽的文字（不写临时词库），下次仍不出现。理由：GH#269 那种错词正是手滑分段上屏造
出来的，把分段当成「想要」会原样复现问题；误屏蔽的代价低，显式加词或在候选调整里撤销即可恢复。

## 5 拼音的候选调整：固定到第 N 位

### 5.1 能力与入口

| 操作 | 码表 | 拼音（现） | 拼音（本期） |
|---|---|---|---|
| 置顶（= 第 1 位） | ✓ | ✓ | ✓ |
| 固定到第 N 位 | 前移/后移写下的绝对下标 | 仅设置页手填（无入口、无校验） | **右键子菜单「固定到第 N 位 ▸ 1…每页条数」**（码表共用） |
| 前移 / 后移 | ✓ | ✗ | ✗ |
| 删除类 | 见 §4 | 屏蔽该词 / 在此编码下隐藏 | 同左 |

读端本就不分引擎，拼音能处理任意位置；缺的是入口、两处正确性问题（5.2）和易用性（5.5）。拼音不做前移/后移：相对邻居的操作，邻居随词频、学词、整句每天在变。证据：GH#236（同一码钉多个位置，「无论怎么调频都不影响」）、其跟帖（「常用但不必置顶，固定在某个位置」）；GH#70 置顶已够用。

### 5.2 先修两处正确性问题（码表今天就受影响）

- **多条 pin 互相挤位**（`wind-candidate/src/shadow.rs` 的 `apply_shadow`）：按 position 升序逐条「摘出再插入」，后处理的规则摘自己时若原位置比先就位的更靠前，先就位的被往前挤一格（例：`[x,B,y,A,z,w,v]`，A→3、B→5，结果 A 实在第 2 位）。只钉第 1 位不触发，所以拼音只开放置顶时没暴露。改为两阶段：先把所有命中项摘出，再按 position 升序（同位置后写在前）插回。
- **写端下标与读端不在同一个列表上**：`reorder_positions` 读的是 `state.candidates`，里面已含 shadow 之后才插入的简繁变体（`expand_s2t_variants`，凭 `s2t_override.is_some()` 识别）、单字母重复上屏项、emoji；读端按插入之前的列表解释 position，开了简繁时偏大。写下标时跳过这些后插入项。
  - 实现：`candidate_grid::inserted_after_shadow` 认这三类（重复上屏项凭 `natural_order == LEADING_REPEAT_ORDER` 且无来源无码）；变体的位置取它的原字。重复上屏项本身不给调位（置顶、前移、后移、固定到第 N 位都灰，写端同守卫）。
  - **英文引擎（英文方案、临英；快捷输入的英文成员本就没有调位入口）本期不给「固定到第 N 位」**（按 `CandidateOpScope.engine_type == English` 判，自建英文类方案同样适用）：头部候选（原文 + 大小写变形，与之同文的词库词被挪进头部）在 shadow 之后才插入，名次会偏头部条数，「第 1 位」点了没反应。置顶保持现状。英文方案 / 临英的置顶、前移、后移同样受头部偏移影响（计位含头部条），这不是本次引入的，本期不处理。以后要做：头部候选在候选上打标记，`inserted_after_shadow` 认它，「第 N 位」按界面名次折算（同下文 5.3），占位的词库词另算。
  - **前移 / 后移是与邻居交换**：两阶段插回后，若邻居自己也有固定规则，两条规则同位、后写的在前，会把邻居挤远（`[a,b,c,d]` 后移 a 再后移 b 得 `[c,b,a,d]`）。写端在邻居有规则时把它改写到本条原位（`Store::move_shadow_swapping`，与本条的规则同一次提交），前移对称。「邻居有规则」按读端口径判：规则带 id 只认 id，不按文本回退（动态短语的规则记的是旧求值文本，回退会误改 / 误清）。这一条是两阶段修复带出来的，不是「码表前移/后移同时受益」。

### 5.3 语义

- 菜单里的「第 N 位」是**界面名次**（完整列表第 N 格，含简繁变体、单字母重复项等后插入项；翻页不影响）。**开了 emoji 扩展、列表里有 emoji 候选时暂不提供**（整组灰、写端不写）：emoji 挂在前 `max_hosts` 条之后或常用候选之后，词一挪它就改挂别处，界面名次没法稳定折算。写端折算成读端 position：把被钉的词连同紧随其后的变体摘掉得 `L`，position = `L[..N-1]` 里非后插入项的条数；`L[N-1]` 是后插入项（变体紧跟原字、重复项钉在首位，被钉的词插不进去）时那一格灰、写端不写；当前所在那格也灰。菜单与写端同用 `pin_at_slots`。菜单只列到每页条数，上限 20，且不超过界面候选条数；移动端长按菜单再封顶到 9（扁平列表，免得一屏全是它）。存储的 position 仍是读端 0 基下标。取值范围受首批候选上限（桌面 300）限制，目标不在列表里则规则不生效，也不计入 `user_pinned`（现有契约）。
- 与整句：position 计数含整句候选；整句切换键（N-best）换槽位时若与被钉词同文，被钉的词会被去重删掉（已知、少见）。
- 两个词钉同一位：后写的在前、先写的顺延，规则不丢。同一候选命中多条规则（按词与按 id 各一条）时取 position 最小的那条。
- 与屏蔽/隐藏互斥：pin 清同词的 deleted、delete 清同词的 pin（现有）。**`*` 屏蔽行在另一个组，不被 pin 清除**：设置页给被屏蔽的词加位置规则时提示「该词已被屏蔽，固定位置不会生效」；右键路径里被屏蔽的词本就不出候选，点不到。
- key：全拼是原始击键串，`xi'an` 与 `xian` 是两条（分隔符表达不同切分）；仅把结尾多余的 `'` 归一。双拼完整转换时存全拼归一码，转换覆盖不全时退回击键码（已知窄串扰，影响面小）。双拼与全拼共用（§8 第 2 条）。

### 6.1 系统词库：中栏一个分组，右栏两级（维护者 2026-11-13 改定）

  主词库 / 各分库
系统词库（可点的分组标题）──→   一级：词库表（主词库 + 全部分类 / 附加 / 我放入的库）

- **同一套表格**：两级都是词库窗的类别（`WordCategory::SysDicts` / `SysEntries`，各有 `CategorySpec`），走同一个 `reload` / 分页 / 搜索 / 排序管线与 `table_sortable_server`，行高、样式、翻页栏（含跳页）、右键菜单与其他表格一致。不占子标签、不进导出。
- **窄窗**：右栏表格区窄于 520（词库窗最小 760 宽时约 340，默认 990 宽约 575）时换窄表的列：一级收起「分组」「优先级」（勾选列不写表头），二级收起「子表」，操作列的文字按钮保持完整；换列时取消排序（排序按列下标记）。
- **一级词库表**：「启用」是表格的启用列（勾选即生效），主词库与写了 `default` 的库禁用。拼音族折叠域只对**有这张库**的成员调 `schema.setDictEnabled`，任一失败改回各成员原值；core 广播 `schema.configChanged` 时重取（分库开关的广播与本端刚写的回声除外）。按读开关的那个成员取（拼音族取活动方案），活动方案换了即重取。行操作 [查看] 进二级（不靠双击或点行进入），[信息] 弹头部信息；右键另有「启用」。没有「来源」列：随包库的分组、`dir:` 的「我放入的」、主库的「主词库」已说清来源，来源与路径在 [信息] 里。
- **优先级**只显示、不可调：即实际叠层先后，表默认按它排并显示序号。拼音方案按方案文件顺序（`load_dictionary` 把启用的库依次叠成 `CachedDict::Layered`，`base_order` 不起作用）；码表 / 英文按 `base_order` 升序，主库也按自己的 `base_order` 排、不一定在首，`base_order` 相同的库之间没有库级先后（同权时按词条行序），表里按方案文件顺序列出。分组作为一列（§8 第 14 条的五组；未写 `group` 的随包库「其他」、`dir:` 登记的「我放入的」、主库「主词库」）。是否允许用户调先后以后再议。
- **条数**：口径同加载器，按大小与 mtime 缓存，停用的库也有。只算加载器会收的行（逐行走同一个解析函数：列数不足、编码或词为空的行不算）；`columns:` 声明残缺的文件加载器整库跳过，条数为空、显示「—」。只有拼音（`rime_pinyin`）库按「本文件 + `import_tables` 子表一层」求和（相对主表目录，不进子表自己的 `import_tables`，缺的子表跳过，同 `rime_source_paths`）；码表 / 英文库加载器不展开 `import_tables`，只算本文件。
- **二级词条表**：只读。默认按文件顺序，拼音库依次展开加载的子表（多一列「子表」）。表头排序走服务端（编码 / 词条 / 权重升降序，子表列不排）。搜索与用户词库同一个搜索框、同样输入即搜，不分编码与词（编码前缀或词子串取并）；但每次搜索 core 要整扫词库，故停手 300 ms 才发（回车立即发），core 侧新查询是旧查询延长时只在旧命中里复核。整库被加载器跳过时空态显示 core 的说明。行操作「加进用户词库」（右键、双击同）预填加词对话框，落本域用户词库的主词库，右栏停在原页。本期**不做**屏蔽 / 改权重（补丁层 §3 做完再接到同一张表）。
- **中栏**：「系统词库」是与「用户词库」同级的分组，放在用户词库分组（主词库 / 分库）之下、「其他」之上；标题本身可点（打开一级表，选中时同普通行变强调色），不显示计数、不挂子项。方案没有用户词库时在最前；没有任何系统词库可列（不应出现）时不出。
- 「方案管理 → 扩展词库」一节**过渡期保留**开关与一句说明（「也可在『词库管理 → 系统词库』里开关」），过几版再删（§8 第 14 条）。方案对话框够不着开词库窗的入口（要 `AppState`），故只给文字。

### 6.3 RPC（新增）

`sysDict.search {schema, query, mode: code|text, offset, limit}`、`sysDict.patch.list / setWeight / hide / remove / clearStale`、`sysDict.categories {schema}`（返回数组，每项 `{id, label, description, group, enabled, source: "main"|"bundled"|"dir", count, order, togglable}`，含主词库、不含 `user:` 分库，按生效先后排；`group`/`count` 缺时为 null）、`sysDict.header {schema, dictId}`（头部字段 `name / version / sort / columns / importTables`、`---` 前的说明注释 `notes`，外加 `path`、`mtimeMs`、`count` 与真正加载的子表清单 `tables: [{name, path, count}]`（只拼音库有；`importTables` 原样列声明）；另带 `id / label / source`）、`sysDict.entries {schema, dictId, query?, mode?: code|text, sort?: code|text|weight, order?: asc|desc, offset, limit}`（`{total, rows: [{code, text, weight, table}], note}`，`note` 说明被加载器整个跳过的表，只读；`query` 空即不过滤，`mode` 缺省为编码前缀或词文本子串取并，`code` 只看编码前缀（忽略大小写与音节空格），`text` 只看词文本子串；`sort` 缺省按文件顺序，给了按该列稳定排序（同键按文件顺序，编码按拼平后比），`order` 缺省升序；`limit` 上限 500）。过滤与排序要整扫：结果按「表下标 + 行首偏移」打包成每行 8 字节的序列缓存（小 LRU，最多 4 组、合计 100 万行，单组超了不缓存；键含各表文件戳与编码是否小写化，文件一变即失效；闲置 5 分钟整个清空），升降序各排一份（同键都按文件顺序），翻页按偏移读行；新查询是缓存里某查询的延长时只在那组命中里复核。排序键不逐行分配（权重带 `i32`，编码 / 词拼进一个大字符串、行上只记偏移与长度）。拼音主库（约 65 万条）实测（release，本机）：整库按权重排序首次约 0.45 s、按编码 / 词约 0.62 s，之后翻页约 1 ms；排序那一次的堆峰值约 29 MB（大头是整读的词库文本），之后缓存一份 5.0 MB；搜索首键约 0.1–0.2 s，往后加字约 40–65 ms。`dictId` 须是 `categories` 列出的某项，主库没写 id 时用其 `path`。开关继续用 `schema.setDictEnabled`。

2. **双拼**：与全拼继续共用候选调整（§5.4）。

6. **改权重保留**：只在词库窗提供（以前系统词没有改权重的入口），候选窗菜单不出现。
7. **拼音删除按文字屏蔽**（§4a）：多字系统词 / 合成词默认「屏蔽这个词」；单字与码表仍按编码隐藏；码表不给按文字屏蔽。
8. **屏蔽优先于自动学词**：分段上屏造出被屏蔽的词时上屏照常、不学（§4a）。
9. **批量不撤销删除**：导入词库、临时词「全部转正」不撤 shadow 删除 / 屏蔽，结果里报「N 条在候选调整里被隐藏」；只有单条显式动作（加词、改词、单条转正、快捷加词、命令栏 `dict.add`）撤。
10. **删用户词/临时词也屏蔽**（维护者 2026-11-12）：拼音右键删多字的用户词 / 临时词（含合并候选），真删所有编码的条目、词频与联想，同时写 `*` 屏蔽行（§4a）。单字、短语、码表不变；混输见第 12 条。
11. **英文按文字屏蔽，只管英文输入**：英文方案、临时英文（及快捷输入的英文成员，同读 `english` 桶）右键删 ≥2 字母的词写 `english` 桶的 `*` 行；用户词 / 临时词同拼音，真删各编码条目再屏蔽；屏蔽的词不自动学；输入原文那一条不受屏蔽、仍可回车上屏。键取词库原文（`freq_text`），**不做大小写归一**（`us` 与 `US` 是两个词）。混在拼音、码表、混输里的英文仍按各自方案、各自编码隐藏。
    实现补记：英文引擎是共享实例（混入的英文也用它），屏蔽集不推进引擎，由引擎管理器按英文方案取候选时
    在截断前滤（`convert_unblocked`）。`raw_candidate = in_dict` 下被屏蔽的词仍算「词库里的词」（字面或
    大小写跟随投影后等于原文即算），原文条不消失。头部候选（无来源）只在字面就是所打原文、且词库有字面相同
    的词时按那个词删，其余（含大小写变形条）删除灰掉——放宽到忽略大小写会屏蔽同码的另一种写法。英文桶里输入码恰为 `*`（触发键进临英 +
    `allow_symbols` 放行 `*`）时不写规则，免得混进屏蔽组。混入英文的用户词 / 临时词固定去 `english`
    桶按编码真删（此前按宿主桶删，删不到）。
12. **混输的拼音段与拼音方案互通**：混输里删拼音来源的多字词，按 §4a 写进 `pinyin` 桶；混输读端也滤 `pinyin` 桶的屏蔽集，只滤拼音来源的候选（码表段出的同文词不受影响）。码表段仍按编码。
