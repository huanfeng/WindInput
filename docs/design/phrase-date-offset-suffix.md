# 日期短语的偏移后缀：`zzrq+1` / `zzrq-2`

> 2026-11-06 设计稿，**未实施**。起因：用户想打「昨天 / 明天」的日期。已先落地的前置改进：
> `date()` 支持全部 `$变量` 能力（农历、中文数字、星期、时间戳），文档给出昨天 / 明天短语写法，
> 想要的人可自行加短语。本稿是进一步让出厂日期短语直接支持偏移。

## 1 结论

可行且纯加法：新逻辑只在缓冲恰为「日期短语的码 + `+`/`-` + 数字」时进入，其余路径不变。

- **日期偏移本身几乎免费**：`PhraseLayer::lookup_at` 已接收 `now`，偏移 N 天 = 把 `now` 平移 N 天后照常展开，
  `$Y` `$LMD` `$WC` `{date()}` 全部自动正确。
- **难点全在输入层**：`+` `-` 与数字在组码中都有别的身份。

## 2 现状（为什么现在 `zzrq+1` 查不到）

| 键 | 现在 `zzrq` 后按下 | 要处理 |
|---|---|---|
| `-` | 候选非空且没翻过页时已能入缓冲（`buffer_symbol_chars` 出厂 `-`），但 `buffer_has_literal_symbol` 为真，**候选被强制清空**、顶码被否决 | 偏移形态开例外 |
| `+` | 不在白名单，落标点路径：顶屏首选后上屏 `＋` | 新增入缓冲口子 |
| 数字 | 组码中是选词键；`symbol_buffer_key_free` 明确不允许数字入缓冲 | 偏移形态下改入缓冲 |

## 3 设计

1. **单一判据** `parse_offset_buffer(buffer) -> Option<(基码, 偏移天数)>`，规则 `^基码([+-])(\d{0,4})$`，
   基码在短语表里有「日期类」条目。所有消费点共用，避免「候选空着却还在顶码」式的自相矛盾。
2. **日期类识别用隐式规则，不加字段**：文本含 `$Y` `$M` `$D` `$W*` `$L*`，或 `{date(` `{now(`。零 schema 改动
   （不动 store / webdata / 设置端往返）；用户自己的 `rq` `date` 短语自动支持。
3. **消费点**（漏一处就是「五笔第 5 码顶码且零日志」）：
   - `update_candidates` 查词：偏移形态**不问引擎**，只用基码 + 平移后的 `now` 查短语，关前缀导航；
   - `buffer_has_literal_symbol`：偏移形态返回 false；
   - `phrase_owns_code` / `has_exact_code` / `has_longer_code`：偏移形态视为短语独占；
   - 自动上屏：偏移形态**恒不自动上屏**（后面可能还有数字）；
   - 按键层：`+` `-` 在「基码刚敲完」或偏移形态入缓冲，数字在符号之后入缓冲；小键盘同理。
4. **取舍**：偏移形态下数字延长偏移（`+12`），不能再用数字选词，改用空格 / 回车 / 二三候选键。仅限该状态。
