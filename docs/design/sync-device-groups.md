# 数据同步：设备组、全量范围与主动同步（设计）

状态：草案，待审。日期：2026-11-25。

本文在 [data-sync.md](data-sync.md) 一期、P1、P2 已实现的基础上修改：同步范围、设置的同步
方式、设备标识、设置页与主动同步入口。远端加密、清单、裁决、合并规则不变，沿用那份文档。
与它冲突的地方以本文为准（§10 列出被取代的条目）。

## 1. 为什么改

1. **目标是同步所有配置**，现在的范围是写死的白名单。`schema_overrides/`、`emoji/`、
   `system.softkeyboard.toml`、`data/pinyin_misread.yaml`、`extensions/`、`wind_setting.toml` 都不同步，
   以后新增的配置也不会自动加入。
2. **设置不该一律共享。** 单机时没有这个问题。同步后会出现「公司要开工作词库、家里不开」「笔记本和台式机
   字号不同」「公司装的扩展不该带回家」。逐项选「仅本机」太复杂；只分「共享 / 独立」两档又不够。
3. **设备号不可读也不可恢复。** 现在是同步状态里的 64 位随机数（16 位十六进制），重装后变成另一台设备，
   原来的设置接不回来。
4. 设置页里同步卡片的选项太多，原地显隐留下多余的分隔线；没有命令行、直通命令和菜单入口；
   主动同步没有结果提示。

## 2. 目标、非目标、反目标

**目标**

- 用户目录里的东西默认都同步，只排除明确列出的本机项；新增的文件或目录不归类就让测试变红。
- 词库数据所有设备共享；设置按**设备组**同步：组内完全一致，组与组互不影响；默认每台设备自成一组。
- 设备号、组号短而可读，可以改；重装或换机后能认回原来的设备。
- 单机、未启用同步、绿色版的配置加载逻辑**完全不变**。
- 「立即同步」有直通命令、命令行、右键菜单三个入口，主动触发的同步弹 toast。
- 未启用时不拉起同步进程（现状如此，保持）。

**非目标**

- 学习数据（`temp`/`freq`/`assoc`/`draft`/`stats`/`completion`），仍归二期。
- 按设置项挑选同步与否、多套配置切换（Profiles）。
- 官方账号同步服务本身（§9 只定接口要求）。

**反目标**（做成这样就算失败，即使能用）

- 单机用户需要理解设备组才能正常使用。
- 改了设备号或换了组之后，词库数据要整份重传。
- 同步把一台设备的设置悄悄覆盖到不想要它的设备上。

## 3. 三类内容

| 类别 | 内容 | 同步方式 |
|---|---|---|
| **数据** | `data/` 下的用户词（`user.dict.yaml`）、屏蔽（`shadow.dict.yaml`）、分类词库文件（`<schema>/dicts/`）、`phrases.dict.yaml`、`quick_format.toml`、`common_chars.yaml`、`charsets/`、`pinyin_misread.yaml`；`emoji/` | 所有设备共享，三方合并（规则见 data-sync.md §8） |
| **资源** | `schemas/` 下的方案文件、`themes/`、`extensions/`（扩展本体与扩展自己的选项文件）、`system.softkeyboard.toml` | 所有设备共享；`themes/`、`extensions/` 按桌面/移动分开（`themes/` 是现状，`extensions/` 新加） |
| **设置** | `config.toml`、`compat.toml`、`schema_overrides/`、`data/<schema>/dicts.toml`（分类词库开关）、`wind_setting.toml`、`wind_setting_hide.toml` | 按设备组同步 |

判据：资源只是「可选的东西」，用不用、怎么用由设置决定，所以资源共享不会让设备互相影响。分类词库**文件**是数据，
**开关**（`dicts.toml`）是设置——这就是「公司启用工作词库、家里不启用」的落点。扩展同理：本体是资源，
启用与授权在 `config.toml` 的 `[extensions]` 里，跟着组走，不做特殊处理。

**不同步**（排除清单，代码里一处定义）：

- `meta.toml`：本机目录的格式版本与 `dir_id`，后者用来识别目录被复制，同步过去会误判。
- `screenshots/`、`data/.backup/`、`*.sys_hash`、旧版遗留的顶层 `charsets/`。
- 隐藏文件、`*.tmp`、`*.bak-*`。
- 顶层 `service/`、`state/`、`logs/`、`cache/`：macOS 的用户目录与本机目录是同一个，安装目录与本机状态会混进来。
  同步进程另按实际路径跳过落在用户目录内的本机目录与安装目录。
- 二期的学习数据：`temp.dict.yaml`、`freq.table.yaml`、`assoc.table.yaml`、`draft.dict.yaml`、`data/stats/`、`completion.table.yaml`。

各类只在该平台的用户目录里有对应文件时才起作用。比如 Android 没有 `extensions/`，移动类别下就没有扩展条目。
桌面各系统之间，扩展目录整份同步，包括其他系统的程序文件；没有本系统程序的扩展，由扩展宿主按
`extension.toml` 的 `exe` 声明判为「本平台不可用」，不运行。〔我的决定：不按系统再细分，量小，且换系统时现成可用〕

**归类守卫**：一条测试列出出厂用户目录（`build_dev/data` 布局 + 首启生成物）里的每一个顶层项与 `data/` 下的
每一类文件，断言它属于上面四种之一（数据 / 资源 / 设置 / 排除）。新增文件未归类即红。

**范围开关**：一期的四类开关（配置 / 方案 / 主题 / 词库）删除，不迁移（未发布）。理由：目标是全同步，
不想要某台设备的设置被影响，用设备组表达。〔我的决定〕

## 4. 设备号与设备组

### 4.1 设备号

- 字符集 `[a-z0-9-]`，长度 1–24，不以 `-` 开头或结尾。
- 默认由主机名生成：转小写，非法字符换成 `-`，合并连续 `-`，截到 16 个字符。结果为空（如中文主机名）时，
  用 4 位随机码，字母表 `23456789abcdefghjkmnpqrstuvwxyz`（去掉 0/o、1/l/i）。
- 绿色版加后缀 `-portable`。绿色版的设备号跟着这份副本（U 盘）走，不随所在电脑变化。
- 存在同步状态里（`<local>/state/sync/state.json`，绿色版在 `localdata/` 下），**只给同步用**；
  数据层日志用的 32 位 `device_id`（`wind-userdata/src/device.rs`）不动，它从不显示。
- 取代现在 `SyncState::new_random()` 的 64 位随机号，不做兼容（未发布）。
- 可以在设置页改号。改号 = 以新号发布一份新清单、移除旧号的清单与名册条目。blob 内容寻址不变，**不重传文件内容**。
- 显示名称（可以是中文，如「家里台式机」）单独存在名册的 `name` 字段里，现有改名功能保留。

### 4.2 设备组

- 每台设备属于且只属于一个组。组号的规则同设备号，组名可以改（如「个人电脑」）。
- 组有类别：桌面或移动，建组时确定，只有同类别的设备能加入。现在按桌面/移动区分设置的做法由组取代；
  `themes/` 作为资源仍按类别区分。
- **新设备默认新建单机组**，组号取设备号，组名取显示名称。「独立」就是只有一个成员的组，代码里没有第二套逻辑。
- 组不单独建远端对象：名册 `devices/<设备号>/info` 加 `group`、`group_name`、`group_name_at` 三个字段，
  组名取组内成员里 `group_name_at` 最大的那个。改组名只改本机的名册条目。〔实现时改：引擎只处理有本地文件的路径，
  单独的 `group.toml` 没有本地落点〕

### 4.3 设置的映射

本机文件路径不变。同步时，属于「设置」类的路径在逻辑路径上加组前缀：

```
本机 config.toml                     ↔  逻辑路径 groups/<本机组号>/config.toml
本机 schema_overrides/wubi86.toml     ↔  groups/<本机组号>/schema_overrides/wubi86.toml
本机 data/wubi86/dicts.toml           ↔  groups/<本机组号>/data/wubi86/dicts.toml
本机 data/wubi86/user.dict.yaml       ↔  data/wubi86/user.dict.yaml（数据，无前缀）
本机 themes/x/theme.toml              ↔  desktop/themes/x/theme.toml（资源，按类别，现状）
```

这是对现有 `scope::to_remote` / `to_local`（按类别加前缀）的推广：设置类改按组加前缀，其他组的设置条目
对本机来说「不在范围内」，裁决时跳过，但仍留在远端作为那个组的版本。

### 4.4 组操作

| 操作 | 结果 |
|---|---|
| 加入组 G | 问一次：**用 G 的设置覆盖本机**（默认）或**用本机设置覆盖 G**。语义见下方「覆盖」。完成后改名册里的 `group`。 |
| 退出组 | 以当前设置新建单机组，原组不受影响。 |
| 新建组 | 同「退出组」，可以起名。 |
| 改组名 | 改 `groups/<组号>/group.toml`。 |

组里最后一台设备退出或被移除后，这个组就不存在了：清单只带本机范围内的路径，没有设备再携带它的条目。
退出时设置已原样延续到新的单机组，不丢东西；被移除的设备本来就是不要了。所以不设「空组」状态。

**覆盖**是整树替换，不是合并。只针对设置类路径，数据与资源不受影响：

- **用 G 覆盖本机**：设置类文件变得与 G 完全一致——G 有的下载并覆盖，本机有而 G 没有的删除，
  可合并的 TOML 也整文件替换，不做合并。动手前把本机全部设置类文件复制到
  `data/.backup/sync/<日期时间>/`，保留最近 3 份。状态库里这些路径直接设为 G 的条目。
- **用本机覆盖 G**：G 变得与本机完全一致——本机文件以高于 G 现有全部条目的 lamport 上传；
  G 有而本机没有的发布删除标记。
- 现有裁决在「状态为空、两边都有」时会走合并或冲突副本，达不到覆盖，所以引擎要加一个显式的
  「按某一方整树替换」操作，不复用常规一轮同步。
- 认领设备（§4.5）用的也是「用 G 覆盖本机」。

改设备号不丢数据：本机发布的清单是状态库的完整快照，包括采纳过的其他设备条目。新号的清单完整继承这些条目，再删除旧号的清单。

### 4.5 加入同步时认领设备

新设备在向导里粘贴同步密钥后，读名册：

- 远端已有与本机默认设备号相同的设备 → 默认选项「恢复为 `desktop-7f3k`（上次活跃：…）」，
  另一选项「作为新设备」（自动取 `desktop-7f3k-2`）。
- 否则列出：**恢复为已有设备**（任选一台：沿用它的号和组）/ **加入已有组** / **新建独立组**（默认）。
- 恢复为已有设备时：本机状态库清空，号与组沿用；按 §4.4「用 G 的设置覆盖本机」下载；名册的平台与版本更新为本机。

**先确认身份再同步**：粘贴同步密钥加入已有远端后，同步进程不做任何同步，直到用户在向导里选定
「恢复为已有设备 / 加入已有组 / 新建独立组」。首台设备（生成同步密钥即初始化）直接确认。

### 4.6 撞号检测

- 每份清单带随机 `nonce` 和上一份的 `prev`，同步状态记着本机最后发布的代次与 nonce。远端本机号的最新清单
  比本机记录新一代且 `prev` 接得上，是「写出后未提交就崩溃」，照常；其余比本机记录新、或同代但 nonce 不同，
  说明另有一处在用这个号（复制的用户目录、复制的绿色版、两台机器认领了同一设备）。
- 处理：本轮不上传，状态进错误态「另一台设备在使用相同设备号」，设置页给出「给本机改号」。不自动改号——
  这时无法判断谁是原主。
- 刚认领（状态为空）时不会误判：认领流程直接把本机代次设成远端最新代次。
- 已知窗口：整份复制出的两处，先同步的一处正常推进，后同步的一处才报撞号。这时远端只多了一份正常的清单，
  没有损坏，报错后改号即可，不另做提示。

## 5. 扩展文件的同步

扩展本体会同步，因此要补两件事：

1. **可执行位**：清单条目加 `exec: bool`（序列化时缺省为 false）。Unix 上读本地时取 owner 可执行位，写本地时设置；
   Windows 上恒为 false、写入时忽略。三方合并不涉及它（扩展文件不可合并，冲突走冲突副本）。
2. **运行中的程序无法覆盖**（Windows 上 `keysound.exe` 被占用）：`extensions/<id>/` 下的写入，先请 core 停掉该扩展，
   写完再恢复。同步进程 → core 的请求白名单加 `extensions.suspend(ids)` / `extensions.resume(ids)`，
   与 `data.beginEdit`/`endEdit` 的用法相同。core 在 `apps/service/src/extensions.rs` 里把这些扩展临时移出 `want`。
   `resume` 在同步进程崩溃时也要兜住：core 在同步进程退出时自动恢复所有被暂停的扩展。

安全：远端内容端到端加密并带认证，存储方伪造不了文件；剩下的风险是自己的某台设备被攻破，与「设置同步」
本身的风险相同。扩展只在本组设置启用它时才运行。扩展首次因同步到达而被拉起时，弹一次 toast
「扩展 X 已从同组设备同步并启用」。

## 6. `wind_setting.toml` 的调整

整份文件跟组同步，但 `[update] last_check_at` 是运行状态，每次检查更新都会变，会让同组设备反复同步。
把它移到设置端的本机状态文件（与 `wind_setting.toml` 同级的本机状态目录，由设置端定位置），
其余键原样保留。〔我的决定〕

## 7. 设置页

同步从「高级」移到独立的「同步」页，在「高级」之前（spike 已出截图）。原则：不在卡片里原地增减行，
多步或少用的操作进对话框；条件行一律用 `CardItem::RowWhen`，不在行内 `visible_when`（后者会留下分隔线）。

**未配置**：只有一张卡片。

```
┌ 数据同步 ─────────────────────────────────────────────┐
│ 用 WebDAV 或 S3 在多台设备间同步配置、方案和词库               │
│ 数据先在本机加密再上传                         [开始配置…] │
└───────────────────────────────────────────────────┘
```

「开始配置…」打开向导对话框：存储类型与参数 → 测试连接 → 同步密钥（远端空：生成并展示，提示「请保存好同步密钥，其他设备加入时要用；丢失后无法解开已同步的数据」；
远端已有：粘贴同步密钥）→ 本机身份（§4.5）→ 完成。

**已配置**：

- 状态卡：状态、上次成功、冲突数、`立即同步`。
- 本机卡：设备号与显示名称（改…）、所在组与成员数（更换组…）。
- 设备卡：按组分列全部设备，本机标出；改名、移除（二次确认）。
- 存储卡：类型与地址摘要、`更换存储…`（对话框，换存储后要求重填密码）。
- 安全卡：`同步密钥`（`查看…`）、`重置远端`（`重置远端…`，换新密钥，其他设备需重新加入）。
- 底部：`停用同步`（确认后状态回到未配置，不删远端）。

**授权类的设置端偏好**（`wind_setting.toml` 里的 `extensions_consented`、`update.network_consent`、
`wizard_dismissed`、`protocol`/`file_assoc` 的 `self_heal`、`[log]`）跟组同步，不单独处理：加入组是用户
明确选择「这些设备用同一套设置」，扩展的启用本身也跟组走，授权跟着走才一致。〔我的决定〕

深链与搜索锚点：原 `advanced:sync` 改为 `sync`；定制版的隐藏 feature 门沿用 `[settings] hide`。

## 8. 主动同步入口与提示

| 入口 | 形式 |
|---|---|
| 直通命令 | `$CC(…, sync.now())`，在 `wind-cmdbar` 注册新函数 `sync.now`（Effect 类），经 `Services` 调到协调器 |
| 命令行 | `wind_input sync now`、`wind_input sync status`（新 `apps/service/src/sync_cli.rs`，需 core 在线，同 `ui`/`ime`） |
| 右键菜单 | 主菜单（`build_main_menu_items`，macOS 为 `build_menu_items_macos`）加「立即同步」，仅在同步已启用时出现 |

三个入口最终都调 core 现有的 `sync.command{op: sync_now}` 路径，并标记为「主动」。

toast：

- 主动同步：完成弹「同步完成」（有变化时带「收到 N 个文件、上传 M 个」，有冲突时带冲突数）；失败弹「同步失败：原因」。
  已有同步在进行时弹「正在同步，完成后会提示」，不排第二次。
- 未启用时调用：弹「数据同步未启用」，不拉起同步进程。
- 后台自动同步：只在**进入**失败状态时弹一次，恢复成功前不再重复。
- 冲突、撞号（§4.6）也走后台失败这一档。

同步进程的 `Status` 需要带上本轮由哪个请求触发（命令 id），core 据此判断该不该弹「完成」。

## 9. 为官方账号预留：单文件增量

现状已经是文件级增量（blob 内容寻址，只传变化的文件），但每轮都要：全量扫描本地、读写整份本设备清单、
列举所有设备的清单。用户自备的 WebDAV/S3 没有原子操作，只能这样。

官方服务可以做得更细，接口上要留出余地：

- 服务端维护合并后的清单，提供「从游标起的变更」与「单文件条件提交（基于上一版本号）」。
  客户端只提交变化的文件条目，不重写整份清单。
- 本地侧用文件监听得到的变更路径直接驱动单文件提交；全量扫描只作兜底。
- 大文件（如大的用户词库）可在以后支持行级差量，基于三方合并已有的规范化键。

本次只做一件事：在 `wind-sync` 的后端抽象上把「读写清单」与「读写 blob」分成两个 trait 层次
（`ManifestStore` 与 `BlobStore`），现有 WebDAV/S3 用「每设备整份清单」实现 `ManifestStore`。
官方后端以后换成增量实现，不碰裁决与合并。〔我的决定：只拆接口，不改行为〕
