# 九宫格（T9）拼音：引擎侧设计

> 范围：`wind-engine/src/pinyin/t9.rs`（全拼与双拼九宫格解码）。协调器状态、手机门面在后续阶段，
> 落地时补进本文。产品侧规划（交互、键盘、分期）在安卓仓的 `docs/t9-pinyin-plan.md`。

## 1. 入口与边界

- 只在 `ConvertOptions::keypad = Some(KeypadMap)` 时进入 `PinyinEngine::convert_keypad`。
  电脑端从不设置这个字段，`convert_with_opts` 只多一次 `None` 判断。
- 混输的两组选项显式写 `keypad: None`：码表侧不认数字键。
- 双拼方案只支持纯字母布局（小鹤、自然码、智能 ABC 等）；布局用到 `;` 等符号键（微软、搜狗、
  紫光）时 `PinyinEngine::keypad_supported()` 为假、转换返回空，界面据此置灰
  （判据 `t9::shuangpin_layout_is_letter_only`）。

## 2. 查询串字母表

| 字符 | 含义 |
|---|---|
| `2`–`9` | 九宫格键，代表 `KeypadMap` 里的一组字母 |
| `a`–`z` | 已锁定的字母（左栏选定的读音、实体键盘），只代表自己 |
| `'` | 分词：音节不能跨过它，消费长度把紧随的 `'` 并入前一段 |

其他字符（包括 `1`、`0`）出现时整串不解码，返回空结果。

一个键对应一个字母，所以击键偏移（去掉 `'` 后）与全拼字母偏移一一对应。节点的音节掩码、
词典的 `boundary`、造词码都在全拼坐标里；候选的 `code` / `consumed_length` / `boundary`
再换回含 `'` 的原串坐标。

## 3. 解码

1. **音节图**：对每个起点，用 414 个标准音节逐个比对键位（`KeypadMap::admits`），得到完整音节边，
   以及「串尾只打了开头」的音节（尾部残缺）。不改 `SyllableTrie`。
2. **词节点**：从每个可达起点逐音节延伸组合，每层对组合码做精确查词；只有
   `has_longer_code` 为真的组合才继续延伸（前缀剪枝），每层上限 `LAYER_BUDGET` 只作保险。
   - 词条有边界时必须等于组合的音节掩码；
   - 用户层（`sentence_uses_user_words`）同码并入，同全拼的用户词节点口径；
   - 不从开头起的节点只进整句，每个码保留权重最高的 `INNER_NODE_LIMIT` 条；从开头起的
     节点是候选，每个码保留到候选上限。
3. **尾部残缺**：
   - 单字（整句末字）：按已打的字母前缀查，只收单字，同全拼的残码节点；
   - 从开头起的多音节词：把残缺音节逐个补全成完整音节后**精确**查。不用前缀扫描，因为
     前缀扫描要遍历整棵子树（`xian…` 下的词极多），短串上会慢一个数量级。
4. **整句**：所有节点上跑 Viterbi，每个节点额外扣 `NODE_PENALTY`；至少两个词才出整句候选。
   有吃满整串的词典词时，整句让位（`is_sentence_demoted`，同全拼）。
5. **候选**：整句在前；从开头起的词按「消费长度 → 是否补全 → 权重」排，按文本去重。每条候选都带
   `meta.learn_code`（全拼码），所打的数字码不能当造词码。
6. **预编辑**：整句（或最优路径）的全拼按音节加 `'`，如 `ni'hao`。

## 3a. 简拼（全拼九宫格）

整串 2–4 个键、每键读作一个声母时出简拼词（`99` → y'w → 因为）：

- 每键取它能代表的声母首字母（zh/ch/sh 取首字母，另加零声母开头 a/e/o），组合后查简拼索引，
  同 26 键纯简拼：索引给全拼码，回主表装配，音节数必须等于键数；
- 候选标 `is_abbrev`、吃满整串：显示排序里排在同长度的全拼读法之后，只吃一部分的单字之前；
- 编码栏显示声母（`y'w`）；
- 带分词键、锁定字母的串和双拼九宫格不走简拼。

整串读不通（没有吃满整串的候选，如 `99999999`）时按简拼**分步选**：从开头起给前 4、3、2 键的
简拼词（`is_partial`，只吃这一段），再给首键当声母的单字兜底；选掉一段后剩下的键接着解。
读得通的串不走这一步，不多花时间。

分步选完会自动造词（`[schema.pinyin.auto_learn]`，写进临时词库）。用户词 / 临时词按简拼**整串**
召回（2–16 键，不受系统简拼 4 键的限制）：用户层的简拼索引只能按完整声母串精确查，8 键的声母
组合有几万种，故改按首键的几个字母各做一次前缀查询，逐条核对「音节数 = 键数、每个音节首字母
落在对应键上」。召回到用户词时仍给分步候选，想换分法还有得选。

列表里没有吃满整串的候选时，分段候选也参与词频调序（协调器 `apply_freq_rerank_with_extra`），
比较器先按消费长度分层，只在同长度之间提升。

组合数随键数指数增长（`9999` 是 256 种），所以上限 4 键，每个声母串只取权重最高的 4 个码。
加上简拼后评测命中率逐位不变，2–4 键耗时 p50 3.0 → 3.5ms、p99 5.4 → 5.9ms。

## 4. 评测与取值

`tests/pinyin_eval.rs` 的 `pinyin_eval_t9`（`WIND_PINYIN_EVAL_T9=1`）把 A/B/C 抽样的真值拼音转成
数字串，与同一批样本的 26 键全拼比较，另按键数统计耗时。阶段 1 的结果（每类 1000 条，桌面 release）：

| 类 | 26 键界面首选 | 九宫格界面首选 | 九宫格界面前 5 |
|---|---|---|---|
| A 普通词 | 86.7% | 77.1% | 93.0% |
| C 多音节含缩合音 | 92.0% | 84.0% | 92.7% |

| 键数 | p50 | p99 |
|---|---|---|
| 2–4 | 3.0ms | 5.4ms |
| 5–8 | 3.5ms | 7.3ms |
| 9–12 | 4.9ms | 9.2ms |
| 13+ | 7.0ms | 14.1ms |

参数怎么选的：

- `NODE_PENALTY = 3.0`：取 0/1/2/3/5 比较。A 类引擎首选 63.1% → 73.0%（3）/ 75.0%（5）。
  在 `grammar_sentence_eval.rs` 的 192 条真实句子上，0 时首选 137 条，3 和 5 都是 154 条
  （26 键 169 条）。取 3：效果相同时罚得小，对词图扭曲少。
- 整句让位：词语集界面首选 +4 个百分点左右；句子集上不降分（罚 3 时开关都是 154 条）。
- 两个节点上限不改变任何一项命中率（改前改后逐位相同），只省耗时。

## 5. 已知局限（后续阶段）

- 没有模糊音、纠错、误读。
- B 类（缩合音短词，`西安` / `李安`）在 26 键下本就几乎打不中首选，九宫格更差，未单独处理。

## 6. 双拼九宫格

音节图换一种建法（`SylGraph::shuangpin`），其余（词节点、Viterbi、候选、预编辑）与全拼共用。

- **配对**：每段（`'` 之间）从头起两键一对，与 26 键双拼的 `pairing_slots` 同规则；`'` 重置配对。
  每对键取两组字母的笛卡尔积（最多 4×4），逐个交给 `ShuangpinConverter::convert_pair`（零声母、
  模糊对偶声母都按布局规则），去重后成为 `[p, p+2)` 的音节边。不在标准音节表里的错音串
  （模糊音的 `din` 等）丢弃：九宫格不做模糊展开。
- **落单键**：输入末尾落单的键是残缺声母，取该键每个字母的布局声母（小鹤 `u` = sh），尾部残缺音节
  是声母恰为它的全部音节（`s` 不含 `sh`）；末字按声母前缀查后再按这张表过滤。段中落单（后面紧跟
  `'`）的键不成边，图在那里断开。
- **两套坐标**：节点起止与 `Candidate::boundary` 在击键坐标（节点带 `key_mask`），造词码、
  `learn_code` 的掩码与预编辑在全拼坐标（`mask`）。全拼九宫格下两者相同。

评测（`WIND_PINYIN_EVAL_T9=1 WIND_PINYIN_EVAL_T9_SP=1`，小鹤，每类 1000 条，桌面 release）：

| 类 | 26 键小鹤界面首选 | 九宫格界面首选 | 九宫格界面前 5 |
|---|---|---|---|
| A 普通词 | 86.7% | 63.6% | 80.4% |
| C 多音节含缩合音 | 96.8% | 80.0% | 93.7% |

耗时 p99：2–4 键 3.6ms，5–8 键 7.2ms，9–12 键 8.5ms，13+ 键 11.8ms。

A 类明显低于全拼九宫格（77.1%）：全拼下键数钉住了音节长度，双拼每两键就有十几种拼法，短词
（4 键 = 2 音节）同码的常用词极多，抽样里的低频词（`8353` 太可 → 深刻）几乎都输给常用词。期望词都
在候选里（没有一条完全找不到），差在排序，留给阶段 5。

## 7. 协调器闸门（阶段 3 的前提，已核实）

数字在电脑端是选词键。协调器的码元闸门 `try_code_char_gate` 排在选词键、翻页键和标点流水线之前，
判据只有 `can_enter_buffer`（空缓冲查首码集，否则查码元全集）。阶段 3 让这个函数在九宫格状态下按
`KeypadMap::is_code_char` 判断即可，不需要调整闸门顺序。

## 左栏逐段选拼音

打字时左栏列已锁定部分之后那一段的读法（`64426` → ni / o / mi / m / n），点一条锁定一段，左栏换成
下一段。复用全键盘的「首单元读法」（`wind-coordinator/src/leading_reading.rs`）：不改缓冲，把
「锁定的读法 + `'` + 剩余键」临时喂给引擎（九宫格引擎本就认锁定字母），差别是：

- 锁定可逐段累加：`Applied.head` 是 `mi'hao`、`orig_len` 覆盖 5 个键；
- 锁定区（缓冲前 `orig_len` 字节）没变就仍有效：续打的键接在后面；分步上屏后失效（比已上屏段数，
  剩下的键可能碰巧与锁定的键相同）；
- 退格从末尾删：锁定之后还有键先删键，删到锁定部分逐段撤锁；
- `consumed_length` 按「吃了几个键」换算回原缓冲（锁定字母与键一一对应，只有分词键位置不同）；
- 编码栏显示锁定后的读法（改写查询算出的预编辑）。

读法顺序：首选正在用的读法在前，其余音节按该音节最常用单字的权重降序，单字母声母殿后。只做全拼：
双拼的拼音与击键不一一对应，左栏照旧列标点。

候选码规范化：锁定字母还原成所在的键、去掉分词键（`ni'426` → `64426`），锁定后选的词与直接按
数字选的同一个词共用一份词频。锁单个声母仍可走简拼（每键本就自成音节）；锁成多字母音节的键不能
再拆成声母。
