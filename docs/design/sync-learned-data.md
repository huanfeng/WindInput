# 数据同步：学习数据（设计）

data-sync.md §10 的「二期」。一期、设备组见 [data-sync.md](data-sync.md)、[sync-device-groups.md](sync-device-groups.md)。

## 1. 目标

- 临时词、选词计数、联想历史、补全历史在设备间同步，**次数跨设备准确累加**：两台各打 10 次，合并后是 20，
  重复同步、乱序同步都不会多算。
- 打字统计各传各的，设置页默认显示全部设备合计，可切到本机或某一台设备。
- 学习数据同步节奏放慢：距上次学习数据同步不足 30 分钟则跳过，「立即同步」不受限。

**非目标**：草稿不同步（24 小时自动过期，首次选用即转入临时词，随临时词同步）；选词计数这次不加容量上限；
安卓统计页不加切换（默认即合计）。

**反目标**：次数越同步越大；删掉（淘汰、晋升、手动删、清空）的词被别的设备的旧贡献复活；每轮整份上传大文件；
单机或未启用同步时任何行为变化。

## 2. 现状

| 数据 | 文件 | 列 | 写入 | 清理 |
|---|---|---|---|---|
| 临时词 | `data/<schema>/temp.dict.yaml` | code, text, weight, count, created_at | 引擎日志折回 | 容量（默认 5000，删次数少的）；英文满 3 次晋升到用户词库并删除 |
| 选词计数 | `data/<schema>/freq.table.yaml` | code, text, count, last_used | 引擎日志折回 | 无 |
| 联想历史 | `data/<schema>/assoc.table.yaml` | context, text, count, last_used | 引擎日志折回 | 无 |
| 补全历史 | `data/completion.table.yaml` | kind, text, count, last_used | 内存表去抖整写，不走引擎 | 网址 200、快捷输入 1000 |
| 打字统计 | `data/stats/YYYY-MM.toml`、`meta.toml` | 按天 | 内存当天 + 30 秒整写 | 用户手动 |

一期把它们全部排除在同步范围外（`scope.rs`）。次数在文件里是原始值，衰减只在读时按 `last_used` 算。

**为什么不能直接三方合并**：现有合并是「本地 + 远端 + 上次同步的祖先」三方比对，取大、并集这类规则重复合并无害。
次数要相加就要求祖先精确，而多设备下 B 的版本可能已含 C 的增量，再分别合并 B、C 就把 C 算了两次。

## 3. 方案取舍

| 方案 | 次数 | 代价 | 结论 |
|---|---|---|---|
| A. 文本三方合并，次数取较大值 | 偏少（各 10 次合成 10） | 最小 | 不选 |
| B. 每台设备各传自己的贡献，本地文件 = 各设备贡献之和 | 准确，幂等 | 同步进程多一层；core 小改 | **选定** |
| C. 上传操作日志，core 导入外部日志按 (设备, 序号) 去重 | 准确 | 日志格式变成跨版本协议，core 要新入口，远端日志要压缩，新设备仍要整份文本起步 | 不选 |

## 4. 贡献模型

每台设备在远端只写自己名下的**贡献**，内容是「本机在当前世代里累计学了多少次」，从不改别人的。本地学习文件是
所有设备贡献物化的结果。次数只增不减；删除、清空、调低都靠**世代**表达，不靠负数抵扣。和合并顺序、重复次数无关。

### 4.1 世代

- **词条世代** `gen`：每个键一个。删除该键 = 立一个更大的世代，旧世代的贡献全部作废；之后的学习从新世代从 0 计。
- **分组纪元** `epoch`：每个贡献分组（某方案的某种数据、或补全历史）一个。清空整类 = 立一个更大的纪元，旧纪元下的
  一切贡献作废，不必逐条记删除。
- 键的有效世代 = max(该键所有设备的删除标记, 全部设备的分组纪元)。只有 `gen` 等于有效世代的 `+` 行参与物化。
- 新世代号 = `max(本机毫秒时间, 当前有效世代 + 1)`，再以设备号排序决胜（同值时设备号大者为大）。只与这个键自己
  已知的世代比较，**不维护全局时钟**：慢钟设备删除也一定立出更大的世代，快钟或乱钟设备的时间不会传染给别的键与别的设备。
- 世代号只用于比较，不当作业务时间；`last_used`、`created_at` 仍是原来的业务时间，衰减算法不受影响。

**删除优先**：设备 B 在不知道 A 已删除时继续用这个词，它这段学习属于旧世代，在 B 收到删除标记时一起作废（丢的是 B
离线期间对这个词的几次使用）。B 知道删除之后再用，才在新世代里从 1 计。这是「次数准确累加」目标的唯一例外，换来的是
用户删掉的词不会带着旧次数回来。

### 4.2 贡献文件格式

每 (数据方案, 种类) 一组，补全历史全局一组。每组两个对象：**底稿** `<kind>.base` 与**增量** `<kind>.delta`，
格式相同。增量里是变化过的行的**最新完整状态**（不是相对底稿的差值），读取时按键覆盖底稿，得到该设备的完整贡献。

```
#wind-learn 1 freq epoch=0
+	ni hao	你好	0	12	1764123456
+	ni men	你们	1764123461000:pc	3	1764100000
-	wo men	我们	1764123462000:phone
```

- 首行：格式版本、种类、本设备立过的最大分组纪元。
- `+` 行：键列 + `gen` + 本机贡献（非负整数）+ 字段。`gen` 为 `0`（初始世代）或 `<毫秒>:<设备号>`。
- `-` 行（删除标记）：键列 + 立出的世代。
- 字段转义沿用学习文件的 TSV 规则（文本里的制表符、换行）。按键排序输出，内容不变则字节不变。
- 上传前 deflate 压缩再加密（文本约可压到 1/4）。

| 种类 | 键列 | `+` 行其余列 |
|---|---|---|
| temp | code, text | gen, count, weight, created_at |
| freq | code, text | gen, count, last_used |
| assoc | context, text | gen, count, last_used |
| completion | kind, text | gen, count, last_used |

键的规范化与学习文件读取一致：编码去空白比较（`ni hao` 与 `nihao` 同键），输出保留原样写法。

**底稿与增量**：每轮只改写增量（本机自上次压实以来变化过的行），底稿不动；增量行数超过底稿的 1/4、增量超过 256 KiB
或底稿超过 7 天未压实时，把增量并入底稿、增量清空。〔我的决定：一轮打字只碰到几百个键，按键哈希分片也会几乎每片都变，
按时间分层才能让每轮上传量 ≈ 变化量〕

**提交的原子性与版本**：底稿、增量是本设备清单里的两个条目。清单本来就按设备单调编号、先传 blob 后发清单
（`manifest.rs`、`engine.rs`），所以底稿与增量总是一起切换、不会读到半新半旧；别的设备只认各设备最新编号的清单，
旧编号的迟到读不会回滚。不另设版本号与提交文件。

### 4.3 物化规则

对每个键：`G` = 有效世代（§4.1）；只取 `gen = G` 的 `+` 行：

- `count` = 求和；`last_used` = 最大；`created_at` = 最小；`weight` = 最大。
- 一行都不剩 ⇒ 本地文件里没有这个键。

### 4.4 本机贡献的更新（diff）

私有状态里保存每个学习文件的**基线** `M` = 上次物化写出（或上次计入贡献时读到）的内容。读当前文件 `F`：

| 情况 | 本机贡献 `C` 的变化 |
|---|---|
| 次数 `F > M` | 本机 `+` 行 `count += F − M`，字段取 `F` 的（`last_used` 取大） |
| 次数 `F < M`（用户手改调低） | 立新世代：记 `-` 行，本机 `+` 行改为新世代、`count = F` |
| `weight` 调低（用户手改） | 同上，立新世代，`count` 取 `F` 的值 |
| 只有字段变（`last_used`、`weight` 调高） | 更新字段 |
| 键只在 `F`（新学到） | 新增 `+` 行，`gen` = 当前有效世代，`count = F` |
| 键只在 `M`（被淘汰、晋升、手删） | 删去本机 `+` 行，记 `-` 行立新世代 |
| `F` 为空而 `M` 不空（清空） | 立新分组纪元，本机 `+`、`-` 行全部清掉 |

收到别的设备的删除标记或更大纪元后，本机 `gen` 小于有效世代的 `+` 行直接丢掉。

**删除标记的回收**：本机名下的 `-` 行，在所有其他设备的镜像里都已没有该键的旧世代 `+` 行（即它们都已处理）且
立出已满 30 天时删掉。被移除、长期不上线的设备的旧行会一直挡着，对应标记就一直保留——标记只有键和世代号，
压缩后很小。〔我的决定：用镜像隐式确认，不另设确认文件〕

### 4.5 一轮学习数据同步

学习数据与文件同步共用同一个 `sync_once`、同一套清单与 blob，在同一个工作线程里与其他同步命令串行。

1. 距上次**成功完成**的学习数据同步不足 30 分钟且非强制，或本轮被退避跳过 ⇒ 跳过 2、5，只做文件同步。失败不更新这个时间，随一期的退避重试。
2. **计入**：对每个学习文件 `data.beginEdit`（core 折回待处理操作并暂停写回），读 `F`，按 §4.4 得到 `C₁`，
   **把 `{C₁, M = F}` 原子写入私有状态**，`data.endEdit`。
3. 文件同步：本机贡献作为 `learn/<本机>/…` 上传；别的设备的 `learn/<设备>/…` 下载到私有目录镜像。
4. 3 失败时到此为止，`C₁` 下一轮继续上传。
5. **物化**：`beginEdit`，重读 `F₂`，把 `F₂ − M` 并入得 `C₂`；按 §4.3 物化全部设备贡献得 `F'`；按下面的次序写盘后
   `endEdit`。远端贡献与本机都没变化时不写。

**第 5 步的崩溃安全**。同步进程一退出，core 会代为结束租约并立即把租约期间的待处理操作折回文件，所以不能靠
「文件内容等于 `F'`」判断 `F'` 是否写成。改为在文件头记一个令牌：

1. 私有状态写入待定记录 `{C₂, M = F', token}`，已提交记录 `{C₁, M = F}` 保留。
2. `F'` 写入学习文件，文件头 `wind:` 映射里带 `sync: <token>`（core 后续折回只按行补丁，保留文件头）。
3. 待定记录转为已提交。

下一轮开始时若有待定记录：文件头令牌等于它 ⇒ 采用待定记录；否则 ⇒ `F'` 没写成，丢弃待定、沿用已提交记录
（`F₂ − F` 那部分会在下一轮重新计入，不丢也不重复）。

### 4.6 远端与本地布局

远端逻辑路径（与 `groups/<组>/…` 同一套命名空间映射）：

```
learn/<dev>/<schema>/{temp,freq,assoc}.{base,delta}
learn/<dev>/completion.{base,delta}
stats/<dev>/YYYY-MM.toml
```

**路径所有权**（plan 层强制）：`learn/<本机>/`、`stats/<本机>/` 只出不进——远端出现的变化忽略并告警；
`learn/<他机>/`、`stats/<他机>/` 只进不出——本地镜像被删改时丢弃本地、重新下载。这些路径不进三方合并、不生成
冲突副本。唯一例外是移除设备（§4.7）。

本地：

| 远端 | 本地 |
|---|---|
| `learn/<本机>/…` | 私有目录 `learn/self/…` |
| `learn/<其他>/…` | 私有目录 `learn/peers/<dev>/…`（只读镜像） |
| （无） | 私有目录 `learn/state`（基线 `M`、已提交与待定记录、上次学习数据同步时间） |
| `stats/<本机>/YYYY-MM.toml` | 私有目录 `stats/self/`：第 2 步时从 `data/stats/` 复制当时的快照 |
| `stats/<其他>/YYYY-MM.toml` | `data/stats/devices/<dev>/YYYY-MM.toml` |

本机统计不直接映射 `data/stats/`：core 每 30 秒整写一次，直接映射会让文件监听在打字期间不停触发同步。
`data/stats/` 整体继续排除在文件通道和监听之外；`devices/` 子目录由本命名空间写入。`learn/`、`stats/` 加入
`classify` 的保留顶层名，用户目录里同名目录不同步。

私有目录按「后端位置指纹 + `meta.check`」分开：换位置、换密钥、重置远端都是新库，不串用。

`NsLocal` 现在只包一个本地根；本命名空间需要一个按前缀路由到用户目录与私有目录两个根的组合 `LocalStore`，
`Namespace` 带上本机设备号。

### 4.7 加入、重置、换库、认领、改号、移除

| 事件 | 处理 |
|---|---|
| 新设备首次加入（没有该库的私有状态） | `C` = 本地学习文件全部内容，`M` = 当前文件 |
| 重置远端（本机发起） | `C` = 本地文件全部（它已含之前所有设备的合计），`M` = 当前文件 |
| 别的设备重置后本机用新密钥重新加入 | 同一后端位置下有旧库的私有状态：`C` = `F − M_旧`（只带上次同步之后的新增），`M` = 当前文件；否则同「新设备」 |
| 更换存储、在新位置建库 | 同「重置远端」 |
| 更换存储、切到已有库 | 有该库的私有状态则沿用；没有则同「新设备」 |
| 认领已有设备身份 | `C` = 远端 `learn/<该号>/` 的内容，`M` = 当前文件（本机现有学习数据视为已计入，下一次物化以同步结果为准）；统计按天合并，同一天两边都有时取本地 |
| 改号 | 远端路径从 `learn/<旧>/`、`stats/<旧>/` 换到新号下，blob 不变不重传 |
| 移除别的设备 | 见 §4.8 |
| 私有状态与 `state.json` 不一致（状态库里有 `learn/<本机>` 而本地 `C` 丢了） | 按损坏处理：重新下载自己的贡献，不套用「新设备」规则 |

已知局限：两台设备在启用同步前复制过同一份用户目录，首次加入时两边各自把同样的次数算作自己的贡献，次数翻倍一次。
〔我的决定：不检测，影响只是排序偏重这些词，会随衰减淡化〕

### 4.8 移除设备

移除只撤销那台设备的同步资格，它名下的 `learn/`、`stats/` **保留**：贡献继续计入，各设备次数不掉；它若回来就接着自己的
贡献继续，不会重复计数。统计页下拉里显示为「已移除的设备」。

保留不妨碍清空：

- 删除某个词、清空整类，靠的是更大的世代/纪元，被移除设备的旧贡献同样作废，效果与在线设备一致。
- 它挡住的只是删除标记的回收（§4.4），不挡清空本身。
- 要彻底清掉它的数据：同步页设备卡末尾一行「已移除设备的数据：N 台 · 清除…」，二次确认后在本机清单里发布对
  `learn/<它>/`、`stats/<它>/` 的删除（所有权规则的唯一例外），各设备次数随之减去它那部分，它挡着的删除标记随即可回收。
- 重置远端照旧清空一切。

## 5. core 的改动

| 项 | 内容 | 规模 |
|---|---|---|
| 联想历史外部编辑 | `external_edit` 放行 Assoc（与 Freq 同路径：折回 + 暂停写回 + 结束时按文件重载） | 小 |
| 补全历史外部编辑 | `beginEdit` 先写盘并暂停去抖写回；租约期间的新增量记在待重放列表；`endEdit` 按文件重载后重放 | 小到中 |
| 学习文件头令牌 | 文件头 `wind:` 映射保留未知键 `sync`（读取忽略，补丁保留） | 小 |
| 统计多设备 | `stats_report` 读 `data/stats/devices/<dev>/`；`stats.summary` / `stats.daily` 加 `device` 参数（`all` 默认、`self`、设备号）；`stats.devices` 列出有统计的设备号。合并口径见下表 | 中 |
| 不需要 | 引擎、日志、折回、学习规则都不动 | — |

**统计合并口径**（「全部设备」）：

| 项 | 口径 |
|---|---|
| 字数、上屏次数、分时、码长分布、选位分布、各方案用量、各来源 | 按天逐字段求和（数组按下标） |
| 输入时长 `active_*` | 求和，含义是各设备输入时长的合计（同时打字时大于自然时间） |
| 速度 | 合计字数 ÷ 合计时长，不对各设备速度求平均 |
| 最高速度 | 各设备取最大 |
| 使用天数、连续天数 | 日期并集后重算 |
| 首次使用日 | 取最早 |

日期以各设备记录时的本地日期为准，不换算时区。

`data.beginEdit` 的路径白名单加上 `assoc.table.yaml`、`completion.table.yaml`。

## 6. 同步进程与 wind-sync

- `wind-sync` 新模块 `learn`：贡献编解码（底稿/增量/压实）、§4.4 diff、§4.3 物化、世代与纪元、删除标记回收；纯函数，内存后端可测。
  学习文件的 TSV 编解码抽成轻量模块供 `wind-sync` 用，不让它依赖 `wind-userdata` 整个 crate。
- `scope.rs`、`plan.rs`：两个按设备命名空间、路径所有权、保留顶层名。
- 两段租约在 `wind_sync_host::Runner` 里执行，桌面同步进程与 `wind-mobile` 共用（安卓的 `InProcLink` 已转发租约）。
- 只物化本机已有数据方案的学习文件（未知方案 `beginEdit` 会失败）；他机的镜像照常接收。
- 用户开着编辑会话或 core 处于只读模式时，跳过该文件的 2、5 步，不影响文件同步。

## 7. 设置页

- 统计页顶部加「设备」下拉：全部设备（默认）/ 本机 / 其他每台设备（显示名取自同步设备名册，取不到显示设备号）。
- 未启用同步或没有其他设备的统计时不显示下拉。
- 「清空统计」只清本机，全部设备视图里其他设备的统计仍在；按钮说明写明。
- 同步页状态卡的说明里提一句学习数据每 30 分钟同步一次。

### 7.1 同步内容

同步页新增「同步内容」卡，三个开关，默认全开，不进向导：

| 开关 | 管什么 |
|---|---|
| 学习数据 | 临时词、选词计数、联想历史 |
| 补全历史 | 邮箱后缀、网址、快捷输入历史 |
| 打字统计 | 本机统计上传、他机统计下载 |

词库、方案、主题、设置这些文件始终同步，不设开关（设备组改版时删掉了一期的四个范围开关，不想要某台设备的设置被影响用
设备组表达，见 sync-device-groups.md §3）。

开关是本机设置，与同步设置一起存在设备本地，不进 `config.toml`、不随组同步。关闭某项：本机不再计入、上传、物化该项，
已上传的贡献留在远端继续计入别的设备（与「移除设备」同理）；再打开时沿用原有贡献，把关闭期间本机的学习
`F − M_旧` 计入后照常物化，不重复计数。

## 8. 已知的全局效应

容量淘汰、清空临时词、补全历史的条数上限都会变成删除标记传到所有设备。各设备临时词容量不同时，实际以最小的为准。
设置按设备组同步，同组设备容量一致；跨组时属于预期之内的取舍。

## 9. 测试要点

- 三台设备、乱序与重复同步，次数恒等于各设备学习次数之和；先收到新清单再收到旧清单不回滚。
- 合并函数的随机化测试（不引入新依赖，用固定种子的伪随机）：多设备随机学习、删除、清空、调低、重复与乱序交付，验证幂等、交换、结合，以及与「按世代逐次回放」的参照实现结果一致。
- 淘汰 / 晋升 / 手删后，别的设备该词消失；之后重学从 1 起；不知删除时的离线学习按删除优先作废；两台同时删除收敛。
- 慢钟设备删除仍生效；乱钟设备（时间在 2099 年）不影响其他键与设备。
- 手动调低后合计等于调低值；清空整类后旧纪元贡献全部作废、不逐条生成标记。
- 删除标记：所有镜像都已处理且满 30 天才回收；被移除设备的旧行挡住回收。
- 第 2 步后崩溃、第 5 步 1/2/3 之间各自崩溃（含 core 代为结束租约后立即折回），次数不重复不丢。
- 本机篡改他机镜像、远端篡改本机路径，均被所有权规则恢复。
- 重置、重新加入、认领、移除四种事件后次数守恒。
- 底稿/增量压实前后物化结果一致；一轮只改少量键时只上传增量。
- 统计：全部设备的按天求和、连续天数跨设备重算；`device` 参数三种取值。
- core：Assoc、补全历史租约期间学到的增量在 `endEdit` 后不丢；文件头令牌经折回保留。
