# 候选注释：命名模板、默认/详细两态与总表设置

> 2026-10-22 设计，已实施于分支 `feat/comment-templates`。前身：`candidate-comment-layering.md`（三层覆盖）、
> `candidate-comment-above-line.md`（上方注释条）。本设计**替换**前者的配置面，
> 不改模板语法与求值（`comment.rs` 的变量、`${a|b}`、`{…}`、`$[色]{…}` 全部保留）。

## 1 为什么做

候选注释是特色功能，但「强大」没能变成「好用」：

1. **开箱没有中英释义**。内置只有拆字、拼音、编码提示；英文词库只有 `word→word` 两列，
   仓库不带任何释义数据，`${dict}` 要用户自己找词库挂。
2. **配置难快速调**。模板是现场写的字符串，散在全局、方案文件 `[candidate]`、
   `[overlay]`、`input.{temp_english,temp_pinyin,url,email,unicode}`、`schema.mix_modes[]`
   七八处；模式级完全没有图形界面。想试几种组合、想备份，都只能手抄字符串。
3. **只有一种状态**。日常要最简（编码提示），偶尔才要详细（拆字、拼音、释义）；现在开了就
   一直是那一种，看一眼详细就得进设置改回来。

## 2 目标 / 非目标 / 反目标

**目标**

- G1 模板**命名**、集中存放：系统内置一批，用户可自定义，数量不限，可整体备份。
- G2 其它地方**只引用模板 id**，不再现场写模板字符串。
- G3 按「模式 → 方案 → 方案类型 → 全局」逐层指定，每层分「默认 / 详细」×「竖 / 横」。
  入门用户只配全局两格就能用。
- G4 全局**一个**「默认 / 详细」状态，Alt 键与动作命令可切换；支持仅本次候选窗、持久、按住三种。
- G5 内置中英释义数据（英→中、中→英），只要基础义项与词性，尽量覆盖全部系统词库。
- G6 设置端一个带 Tab 的对话框，核心是一张「作用范围 × 四列」的总表。

**非目标**

- 不改模板语法、变量集、注释词库机制（`[[ui.comment_dicts]]` 原样保留，内置释义也走它）。
- 不做第三态及以上（维护者明确：预留第三态太复杂）。
- 不改 `comment_max_chars_*`、`comment_above`、`auto_comment_dicts`、悬停提示 `ui.tooltip`。

**反目标（做成这样即失败，哪怕功能都在）**

- Alt 单击切换干扰了正常上屏或应用自身的 Alt 行为（菜单栏、Alt+Tab、已有的 Alt+数字上屏注释）。
- 各方案 / 模式各有各的状态，切来切去不知道当前处于哪一态。
- 入门用户打开设置面对的是一张必须填满的大表。

## 3 概念

| 概念 | 含义 |
|---|---|
| **模板** | `id` + 显示名 + 模板串。内置模板随包发布、只读；用户模板存用户配置。 |
| **两态** | `default`（默认）/ `detail`（详细）。全局唯一。 |
| **作用范围** | 全局 / 方案类型 / 方案 / 模式。每个范围 4 格：默认·横、默认·竖、详细·横、详细·竖。 |
| **格值** | 模板 id；`none`（不显示注释）；不写（跟随）。竖排格另有「同横排」（见 §13.2）。 |

## 4 状态与切换（维护者已定）

- **持久状态** `ui.comment.state`：`default` / `detail`，写回配置，重启保持。所有作用范围共用这一份。
- **临时状态**：本次候选窗内对持久状态**取反**。候选窗关闭（上屏、取消、清空）即丢弃，下一次输入
  回到持久状态。持久为 `detail` 时，临时取反看到的就是 `default`。
  - 输入途中切模式（如进入临时拼音），临时状态**保留**，在新范围的模板上同样生效（我方判断，
    理由：用户的意图是「这一下我想看详细」，与当前在哪个模式无关）。
  - 但同一键内**上屏了文字**就算候选窗关闭、临时状态复位：切模式顺带顶屏（如五笔 `gg` 后按反引号
    顶屏再进临拼）、顶码留下余码另起一段、联想被新组字替换，都属此类。
  - 显式设持久态（按键动词、命令栏）同时清掉临时状态，看到的就是刚设的态。
- **Alt 行为**（已由 §13.1 取代：改为 `switch_key` + `switch_mode`，出厂 Ctrl；下文保留作历史）`ui.comment.alt_switch`，四档：
  - `off`：不拦 Alt。
  - `session`：单击 Alt 切临时状态。**出厂档**（维护者已定）。
  - `persist`：单击 Alt 改持久状态。
  - `hold`：按住 Alt 期间临时为另一态，松开恢复。
- **Alt 的拦截边界**（我方判断，实施须逐条钉测试）：
  - 只在**候选窗可见**时拦；其余时候 Alt 原样交给应用。
  - **平台与服务分工**：组字中或候选可见时，平台把 Alt 按下 / 松开（`0xA4`/`0xA5`）转发给服务，
    并带上按住期间按过的 Shift / Ctrl / Win 粘滞修饰位；单击还是组合键由服务判定（见到任一非 Alt
    修饰位即算组合键），平台只在服务回 `Consumed` 时吃键。
  - 只认「干净的单击」：Alt 按下到松开之间有任何别的键（含 Alt+数字上屏注释、Alt+Tab），
    就不算切换，且不吞那次松开之外的任何键。
  - 左右 Alt 都认（我方判断；如需区分可后续加 `lalt`/`ralt` 取值）。
  - 被拦下的 Alt 松开**必须吃掉**，否则 Windows 应用会激活菜单栏、抢走焦点。
  - `hold` 档：候选可见时**吃掉 Alt 按下**（不吃的话应用先进入 Alt 状态）。按住期间又按了别的键，放行该组合键；**先处理组合键、后恢复**。所以按住 Alt 看着详细
    注释按 Alt+数字（`alt_commit = "comment"`），上屏的就是眼前那份详细注释（我方判断：上屏的应与所见一致）。
    `alt_commit_text` 因此要读当前生效态（持久态 ⊕ 临时态），不能只读持久态。
  - **实现路径**（我方判断）：做成与 `toggle_mode_keys` 同类的修饰键单击判定，不折算进按键表。
    裸 `lalt` / `ralt` 在 `key_actions` / `session_actions` 两表都绑不上，不存在让位问题。
- 切换只**重绘当前页**：不重新查询、不改候选顺序、不改高亮。
- **动作命令**：
  - 命令栏：`ime.toggle("comment")` 切持久状态；`ime.set("comment", "default"|"detail")` 直达。
    命令短语即可绑定，如 `$CC("切注释", ime.toggle("comment"))`，系统短语表加一条。
  - 按键动词 `comment_state`（切持久）、`comment_state:default` / `:detail`（直达持久）
    **两张表都加**：`keys.key_actions`（无会话）与 `keys.session_actions`（组字中），同 `single_char` 的先例。
    `comment_state:session`（切临时）只有会话里才有意义，**只进 `session_actions`**。
  - 命令栏 `ime.set` 现只认 `on`/`off`（`dict_ime.rs` 校验），需为 `comment` 目标扩出 `default`/`detail`。
    `comment` 与已占用的 `dict:<注释库id>` 是两个目标，互不影响。
- 总开关 `ui.comment.enabled` 关掉时，两态都不显示，Alt 也不拦。

## 5 解析链（维护者已定）

取「当前态 × 当前排布」那一格，从具体到一般逐层找，第一个**有值**的胜出：

```
模式 → 方案 → 方案类型 → 全局
```

每层的格先看用户配置 `[ui.comment.assign.*]`，再看出厂分配（`data/system.comments.toml`）：
同一作用范围同一格**用户格胜出**；用户格写 `inherit` 即跳过本层出厂格、直接看下一层。
方案文件不参与（见 §6.1）。

出厂分配放 `system.comments.toml` 而不放 `config.toml`：后者与用户配置深合并，出厂行用户删不掉。

- **方案类型**取引擎类型，五类：`codetable` / `pinyin` / `shuangpin` / `mixed` / `english`。
  `shuangpin` 是拼音引擎配了双拼布局，按此单独成类；其余直接取 `EngineType`。
  维护者点名的是前三类，后两类是我方补齐（不补的话混输、英文方案只能落到全局）。
- **方案层归属**取 active 方案（同 `candidate-comment-layering.md` 的既有判断：注释模板是呈现类配置）。
- **模式**沿用现有映射（`comment.rs` 的 `template_for`）：临时拼音、临时英文、快捷输入及其它
  mix_modes 实例、网址、Email、Unicode、引导键特殊模式（`special:<方案id>`）。生僻字、反查、
  辅助码维持「无模式层」。
- **横排为主**（见 §13.2）：
  - 横排格：写了值 → 用它；写 `inherit` 或不写 → 跟随下一层的**横排**；
  - 竖排格：写了值 → 用它；写 `inherit` → 跟随下一层的**竖排**；
    不写 → 本范围横排格**有值**（模板或 `none`）时同横排，横排也没值时跟随下一层竖排（同样按本条判）。
- **`none`** 是一个有意见的值：压过下层，渲染成空注释（同现行三态里的空串）。
- 全局层四格**必有值**：内置默认见 §7，用户删掉某格时按内置默认补。
- `system.comments.toml` 编译期内置一份副本；盘上文件缺失或解析失败时用副本并 `warn`。
  盘上文件仍是覆盖层（定制层可整份替换）。

## 6 配置形态

新段 `[ui.comment]`，取代 `ui.candidate` 里的 `comment_enabled` 与两份模板串。出厂 `config.toml`
只带 `enabled` / `state` / `switch_key` / `switch_mode` 四键；下例的模板与分配是**用户**写的（出厂分配见 §7）：

```toml
[ui.comment]
enabled = true                 # 原 ui.candidate.comment_enabled
state = "default"              # 持久状态：default / detail，按键动词、命令栏、Alt persist 档写回
switch_key = "ctrl"            # ctrl（出厂）/ lctrl / rctrl / alt / lalt / ralt（§13.1）
switch_mode = "session"        # session（出厂）/ persist / hold

# 用户模板（内置模板在 data/system.comments.toml，同 id 时用户版覆盖内置版）
[[ui.comment.templates]]
id = "wubi_learn"
name = "五笔学习"
text = "${chaizi} ${code_rev}{ · ${pinyin}}"

# 作用范围 → 四格。键名固定为 default_vertical / default_horizontal /
# detail_vertical / detail_horizontal；值 = 模板 id / "none" / "inherit"（跳过本层出厂格）。
[ui.comment.assign.schema.wubi86]
detail_horizontal = "wubi_learn"   # 竖排没写 → 同本行横排（§13.2）

[ui.comment.assign.mode.temp_pinyin]
default_horizontal = "pinyin"

[ui.comment.assign.mode.temp_english]
detail_vertical = "inherit"    # 不用出厂的 en_meaning，跟随方案 / 类型 / 全局
detail_horizontal = "inherit"
```

- **模式键名**：`temp_pinyin` / `temp_english` / `url` / `email` / `unicode` / `mix:<mix_mode id>` /
  `special:<方案id>`；`mix` 是快捷输入的默认（界面叫「快捷输入（默认）」），`mix:<id>` 没写的格先落到它，再到当前方案。TOML 表名里带冒号要加引号：`[ui.comment.assign.mode."mix:quick_mix"]`。
- **引用了不存在的模板 id**：启动 `warn` 一次，该格按「不写」处理（跟随下一层），不报错不阻断。
- **模板 id 规则**：`[a-z0-9_]+`；`none` / `inherit` 是保留字，用户模板用了即忽略并 `warn`。设置端新建时自动生成，用户可改名（改的是 `name`，不是 `id`）。
- 方案层的**用户**设置统一在用户配置的 `assign.schema.<id>`，与总表一一对应。

### 6.1 方案文件不再配置注释（维护者已定）

注释依赖的数据（英文词库、反查码表、注释词库）往往不在方案自己身上：五笔方案的 `${pinyin}`
来自拼音反查，`${dict:zh_en}` 来自全局注释词库。所以方案文件里写注释既做不到自包含，也让配置
多出一处来源。为了简洁，**方案文件里的注释配置整体作废**：

- `[candidate].comment_template_*` 与 `[overlay].comment_template_*` 不再读取。检测到残留时，
  启动 `warn` 一次，提示改到设置端总表的方案行 / 模式行。做法同 `schema_hotkeys` 废弃时的先例。
- 随包方案文件里的这些键一并删掉（当前随包方案都没写，实施时 grep 确认一次）。
- 引导键特殊模式的注释改由用户配置的 `assign.mode."special:<方案id>"` 表达。
- 用户覆盖层 `schema_overrides/<id>.toml` 里的旧键是用户写的内容，能否顺带迁到
  `assign.schema.<id>` / `assign.mode."special:<id>"`，并入 §10 的迁移评估。

## 7 内置模板与出厂分配

内置模板与出厂分配放 `data/system.comments.toml`（另含内置注释词库清单 `[[dicts]]`），与
`system.phrases.toml` / `system.quick.toml` 并列。清单：

| id | 显示名 | 模板串（示意） |
|---|---|---|
| `code_hint` | 编码提示 | `${code_hint\|code_rev\|shuangpin}`（即现行出厂值） |
| `pinyin` | 拼音 | `${pinyin}` |
| `chaizi` | 拆字 | `${chaizi}` |
| `chaizi_code` | 拆字+编码 | `${chaizi} ${chaizi_code}` |
| `chaizi_pinyin` | 拆字+拼音 | `${chaizi}{ · ${pinyin}}` |
| `en_meaning` | 英文释义 | `${dict:en_zh}` |
| `zh_english` | 中文对应英文 | `${dict:zh_en}` |
| `pinyin_english` | 拼音+英文 | `${pinyin}{ · ${dict:zh_en}}` |
| `detail_full` | 详细（全部） | `${chaizi}{ · ${pinyin}}{ · ${dict:zh_en}}` |

出厂分配（都写在横排格，竖排不写即同横排）：

| 作用范围 | 默认 | 详细 |
|---|---|---|
| 全局 | `code_hint` | `detail_full` |
| 码表 | 跟随 | `chaizi_pinyin` |
| 拼音 / 双拼 | 跟随 | `pinyin_english` |
| 英文 | `none` | `en_meaning` |
| 临时英文 | `none` | `en_meaning` |
| 临时拼音 | 跟随 | `chaizi_code` |

## 8 内置中英释义数据

- 作为两张**内置注释词库**随包：`en_zh`（英→中）、`zh_en`（中→英），走现有
  `[[ui.comment_dicts]]` 的加载与 `.wcmt` mmap 缓存，不另造机制。内置条目默认 `enabled = true`，
  用户可在注释词库页关掉。
- 内置库只能按 id 取（`${dict:en_zh}` / `${dict:zh_en}`），裸 `${dict}` / `${dict_all}` 不查：
  老用户模板里的 `${dict}` 不因升级冒出英文释义，出厂默认态也就不带释义。
- **内容**：每个词一行，「词性 + 最基础义项」，不要例句、不要多义项堆叠。
  例：`apple → n. 苹果`；`苹果 → n. apple`。
- **来源**：
  - 英→中：ECDICT（MIT），按 `en.dict.yaml` + `en_ext.dict.yaml`（约 2.4 万词）裁剪；
  - 中→英：CC-CEDICT（CC BY-SA 4.0，单向兼容本仓 GPL-3.0）打底，只覆盖约 12 万词条；
  - 系统中文词库约 70 万词条（`base` 37 万、`ext` 24 万、`idiom` 5 万、五笔 `jidian` 9 万），
    CC-CEDICT 覆盖不到的部分用 AI 生成补齐，并抽检。
- **授权落实**：ECDICT 与 CC-CEDICT 的署名写进第三方声明；AI 生成部分标注来源，与 CC 部分**分文件**
  存放，便于以后替换。
- **体积**（实测，CEDICT / ECDICT 部分）：
  - `en_zh`：覆盖词表 21337 词的 93.23%，719 KB（gzip 299 KB）；
  - `zh_en`（仅 CEDICT）：覆盖 672508 词的 14.39%，4.43 MB（gzip 1.96 MB）；余下 575724 词要靠 AI 补齐。
  - **补齐口径**（维护者已定）：通用词库 base/ext 中 CEDICT 未覆盖、词频 ≥100 的约 9.1 万词，加五笔 `wubi86_jidian` 独有词按其词频取前 1 万；分类词库（人名/地名/历史/体育等专名）与成语不补。合计约 10 万词。
  - **取义与格式**（维护者已定）：AI 统一挑最常用的一两个义项，统一写成「词性. 义项」；英→中与 CEDICT 部分也按此规则重整，不再机械取「第一个词性 + 前两个义项」。
    - **取词范围**（维护者已定）：只给词汇和固定说法释义（视觉效果、药物治疗、言之有理）；短语碎片留空——词加虚词、代词加动词、半截句子（就坐在、你不用担心、最好的办法就是、讲一下、在这样）。提示词里带正反例，使各批口径一致。
    - **专名**（维护者已定）：人名、作品名、品牌只在有通行英文名时给出（街霸 → Street Fighter），否则留空；不音译成拼音（绝代双骄 不写 Juedai Shuangjiao）。
  - **生成结果**（2026-10-22，会话内 agent 分批生成，源数据在 `data/comments-src/`）：
    - AI 补齐 94322 词，给出释义约 4.1 万，其余为碎片或无通行英文名的专名、留空；拼音化释义 482 条构建时过滤。
    - 重整：英→中 19892 条、CEDICT 96784 条，重整为空的回退原值。
    - 构建产物：`zh_en` 137207 条，4.26 MB（gzip 1.76 MB）；`en_zh` 19893 条，527 KB（gzip 210 KB）。
  - **随包内置**（维护者已定）：安装包约增 2 MB（压缩后），运行时 mmap。
- **发版节奏**（维护者已定）：AI 补齐、抽检完成后，与模板 / 切换功能**一起发**，不先发半套数据。
  因此释义数据是主线阶段，不是可选的后续工作。生成过程中要持续盯住体积：
  - 每条只留一个词性、最基础的一两个义项；
  - 生僻词、长尾专名没有可靠释义就宁缺，不硬凑。
  
  中间产物的体积也要报给维护者。
- **可复现的边界**：AI 生成的释义作为**源数据入库**（`data/` 下单独文件，带来源标注），`scripts/`
  里的脚本只做裁剪、格式化、合并、去重，这一步可复现；调模型生成本身是一次性的离线工序，不进构建。
- **加载时机**（我方判断）：沿用现行「模板引用到哪个变量 / 词库就加载哪个」（`data_needs.rs`）。
  出厂的详细模板引用了拆字与 `zh_en`，所以启动即加载。释义库是 `.wcmt` mmap，冷页只占页缓存、
  不计进程 Private 内存（见 `memory-footprint.md` 的口径），代价可接受；换来的是第一次按 Alt 不卡、
  不空。体积报给维护者时一并报 mmap 映射量。

## 13 真机反馈后的修订（维护者已定）

真机试用后推翻 §4 的 Alt 方案与 §9 的 Tab 对话框，本节为准；与上文冲突处以本节为准。

### 13.1 切换键

- Windows 上 TSF 收不到单独 Alt 的按下（`WM_SYSKEYDOWN`），只收到松开，服务端判不出单击，
  Alt 松开照常激活宿主菜单栏。Ctrl / Shift 的单击走普通按键通路，`lctrl` 作中英切换键、
  `lrctrl` 选词、`session_actions` 里绑 `lctrl` 都早已可用。
- 配置拆成两键（未发布，直接改名，不兼容 `alt_switch`）：
  - `ui.comment.switch_key`：`f1`（**出厂**，见下）/ `ctrl`（左右任一）/ `lctrl` / `rctrl` / `alt` / `lalt` / `ralt`；
    取值另有 `none`（不用切换键）与 `f2`…`f12`；`switch_mode` 不再有 `off`，不用切换键就设 `switch_key = "none"`
    （维护者 2026-10-29 定：切换方式里留一个「不使用」，与按键总览的绑定容易打架）。
    出厂原为 `ctrl`，真机后改 `f1`（维护者 2026-10-29 定）：单击 Ctrl 与中英切换、选词、组合键的干扰太大。
    F1 不走修饰键单击判定，生效时由 `Config::effective_session_actions` 补一条 `f1` 会话绑定（`session` / `hold`
    → `comment_state:session`，`persist` → `comment_state`），转发与分派复用会话按键通路；用户自己绑了 F1 的优先。
    F1 没有按住，`hold` 档按临时切换处理。mac 键码表只补 F1，其余 F 键仍透传；
  - `ui.comment.switch_mode`：`off` / `session`（出厂）/ `persist` / `hold`，语义同 §4 原四档。
- 按住（`hold`）Alt / Ctrl 都可用：按下切换键立即翻转、松开恢复（按得多久、期间按没按别的键都恢复）；
  按住期间按组合键（Ctrl+C、Ctrl+数字）注释会闪一下，接受。按住期间候选窗关了，翻转随之清掉，不残留。
- Ctrl 的上报（三端一致）：**按下那一刻**有输入会话（组字中或候选窗开着），平台就把这次 Ctrl（左右分开，
  0xA2 / 0xA3）的按下与松开如实上报（新事件类型 `EVENT_MOD_DOWN` / `EVENT_MOD_UP`），与切换键、切换方式
  无关，平台不吃 Ctrl；松开带 `TOGGLE_MOD_NOT_TAP` 表示平台看见过服务端看不见的输入（透传的组合键、鼠标）。
  否则维持原「平台本地判单击、只报确认过的松开」。一次按住只走一条路（按下时定，松开时不再看会话），
  不会两边各报一次。旧 core 对未知事件类型放行，新 DLL 配旧 core 不会误切。
- 服务端统一判 Ctrl 单击：按下建 track，其间任何别的键（含 `WM_HOTKEY` 送来的 Ctrl+数字）弄脏，
  松开时干净且 ≤500ms 才算；判出单击再按原「确认过的松开」走 keyup 分支，中英切换键、`session_actions`
  的 lctrl / rctrl、`lrctrl` 选词照旧优先，且同样只在单击时触发。TSF 的 `DispatchHotkey` 也作废待判单击
  （候选窗不显示那条旧路的 Ctrl+数字误判单击一并修好）。
- Shift 按着时单击 Ctrl：如实上报这条路按组合键算（按下带 Shift 位即弄脏），不算单击；旧路在 mac / Linux
  上会算单击。两路在这点上不一致，保留新行为。
- 功能键（F1 等）不进切换键：按键绑定里绑 `comment_state` / `comment_state:session` 已能做到。
- 选了 Alt 的 Windows 用户才装全局低级键盘钩子（与 CapsLock 绑定同一套线程与投递约束）：
  钩子判单击、在 Alt 松开前补一个无含义的屏蔽键压住菜单栏；不选 Alt 时进程里没有这个钩子。
- 切换键与中英切换键、选词键组、会话绑定撞键时，那些功能优先，切换键在设置页标出冲突。

- 顶部固定「全局」：「默认」「详细」两态各一行，横排选模板 / 不显示，竖排第一项固定「同横排」。

  「默认 跟随上级」「详细 拼音+英文」；不标「出厂」。
- 每一态只有「跟随上级 | 自定义」两种状态：

  不显示「生效结果」。
- 「只改竖排、横排跟随」在界面里写不出；core 仍认，遇到时照实显示「横排：跟随上级」。
- 每一项都可删除，删除后这一项按上级显示。用户加的项删掉整段；出厂项写四格 `inherit`，
  视为已删除，不再列出。列表下方提示「已删除 N 项出厂设置」，重新添加或「恢复默认」可找回。
- 出厂项改过的，展开后末行给「恢复此项出厂设置」。
- 底栏：「添加覆盖」、「恢复默认」（气泡二次确认，只清 `[ui.comment.assign]`）、(i) 优先级说明、

模板库对话框：

### 13.6 编码来源开关并入注释分配；内置模板重整（维护者已定方案 A）

**为什么**：三个「编码来源」开关决定 `${code_rev}` / `${shuangpin}` 有没有值，模板又决定显示什么，
两层叠着管同一件事。模板里写了 `${code_rev}`、开关却关着时什么都不显示，用户找不到原因。

**退役的键**（不再读、不迁移，写回清理时从用户配置移除）：

| 键 | 出厂 | 原含义 |
|---|---|---|
| `schema.pinyin.code_hint_source` | `off` | 拼音 / 双拼方案（及码表方案）下拼音候选的编码来源 |
| `input.temp_pinyin.code_hint_source` | `auto` | 临时拼音 / 快捷输入期间的编码来源 |
| `schema.mix.pinyin_code_hint` | `true` | 混输方案下拼音候选显示码表编码 |

`${code_rev}` 一族与 `${shuangpin}` 从此只看候选来源（拼音来源才有值），不再有档位门控；
显不显示、显示哪种由分配到的模板决定。`${code_source}` 与上屏注释（`input.alt_commit = "comment"`）
同样不再读档位。

`schema.codetable.show_code_hint`（码表引擎是否产出「剩余编码」）**本轮不动**：它能按方案在方案文件 /
`schema_overrides` 里覆盖，迁移要跨文件改写；且它只管 `${code_hint}` 这一个变量，等价的模板写法别扭。
设置页原位置保留，说明里指向注释分配。

**内置模板**（id 未发布，直接改；分隔统一用「 · 」）：

| id | 名称 | 模板串 | 用途 |
|---|---|---|---|
| `code` | 编码（自动） | `${code_hint\|code_rev\|shuangpin}` | 通用：码表补全剩余码，拼音候选给码表编码，没有码表给双拼 |
| `code_hint` | 剩余编码 | `${code_hint}` | 码表前缀候选还要打的剩余编码 |
| `code_rev` | 码表编码 | `${code_hint\|code_rev}` | 拼音候选反查码表编码（混输、借拼音学码） |
| `shuangpin` | 双拼编码 | `${code_hint\|shuangpin}` | 拼音候选的双拼键位（全拼学双拼） |
| `pinyin` | 拼音 | `${pinyin}` | 带调拼音 |
| `chaizi` | 拆字 | `${chaizi}` | 单字字根 |
| `chaizi_code` | 拆字 · 编码 | `${chaizi}{ · ${code_rev\|chaizi_code}}` | 字根加码表编码（取不到再用拆字表编码） |
| `chaizi_pinyin` | 拆字 · 拼音 | `${chaizi}{ · ${pinyin}}` | 码表详细态 |
| `zh_en` | 英文释义 | `${dict:zh_en}` | 中文候选的英文 |
| `en_zh` | 中文释义 | `${dict:en_zh}` | 英文候选的中文 |
| `pinyin_en` | 拼音 · 英文 | `${pinyin}{ · ${dict:zh_en}}` | 拼音详细态 |
| `full` | 拆字 · 拼音 · 英文 | `${chaizi}{ · ${pinyin}}{ · ${dict:zh_en}}` | 全局详细态 |

改名缘由：「编码提示」既是旧变量名又是模板名，用户分不清；「英文释义」实为英文词的中文释义，
与「中文对应英文」正好说反；「详细（全部）」看不出含什么。「编码」加「（自动）」、「补全编码」改「剩余编码」，
是为了让名字说出显示什么；内置模板都带 `desc`（一句说明），分配框下拉里逐项显示、模板框里可编辑，编码模板借它说清各自对拼音候选给什么。

**出厂分配**（横排格；复刻退役前的出厂效果）：

| 作用范围 | 默认 | 详细 |
|---|---|---|
| 全局 | `code` | `full` |
| 码表 | 跟随 | `chaizi_pinyin` |
| 拼音 / 双拼 | `none` | `pinyin_en` |
| 混输 | `code_rev` | 跟随 |
| 英文 | `none` | `en_zh` |
| 临时英文 | `none` | `en_zh` |
| 临时拼音 | `code` | `chaizi_code` |
| 快捷输入（默认）（`mix`） | `none` | `none` |

码表默认态不覆盖：主路上没有拼音来源候选，`code` 与 `code_hint` 效果相同，让用户改全局时码表方案跟着变。
临时拼音的默认态显式写 `code`：它的上级是当前方案，拼音方案下会落到 `none`。
快捷输入（通配的 `mix`，用户自建的也覆盖到）两态都 `none`：日期、计算这类候选带注释只是干扰（维护者 2026-10-29 定）。

**迁移**：不做，见 §10。旧版改过这三个开关的用户升级后回到出厂分配，在注释分配里重设。

**按需预载**：反查表是否预载改为按「可达上下文实际落到的模板」判断：每个可用方案的主路（码表、英文方案的主路不出拼音来源候选，跳过），
以及进得去的临时拼音、各快捷输入，两态两排布逐一解析，任一模板引用编码反查变量即预载。
纯拼音方案主路默认态是 `none`，但临时拼音、快捷输入出厂分到「编码」，所以出厂仍预载，与退役前一致；
两者都改成不显示编码才不预载。

**设置端**：三处原位置（拼音「编码提示来源」、临时拼音「临时拼音编码提示」、混输「拼音候选显示码表
编码」）不再给下拉，只显示一行「当前：<模板名>」（多个范围不一致显示「分别设置」）和跳转按钮「去设置」，
改在分配框里做——原位下拉与分配框是同一件事的两个入口，概念要讲两遍。首次设置向导的「拼音反查」改为写
`type.pinyin` / `type.shuangpin` 的默认态（任一格不是 `none` 即算开；开 = 把还是 `none` 的格写 `code_rev`，已另选的模板不动；关 = 两格写 `none`，与出厂相同）。
Android 端的同名设置项不在本仓，另行跟进。
