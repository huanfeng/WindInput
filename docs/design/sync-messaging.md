# 多端、剪贴板同步与图片互传（设计）

状态：P1 已实现（密钥分层、设备名册）；P2 起未做。日期：2026-11-24。前置：`data-sync.md`（文件同步一期）。

## 1. 三类数据的差别

| | 文件同步（已做） | 剪贴板 | 图片 |
|---|---|---|---|
| 时效 | 分钟级，最终一致 | 秒级 | 秒～十几秒 |
| 生命周期 | 持久、需合并 | 用完即弃 | 一次性 |
| 方向 | 全体收敛 | 广播给我的其他设备 | 发给指定设备 |
| 大小 | KB～MB | B～KB 文本 | MB～几十 MB |
| 敏感度 | 一般 | 极高（常含密码） | 用户主动 |

剪贴板与图片**不进**文件同步的清单/合并/lamport 流程；共用设备身份、密钥体系、`Backend` trait、
同步进程与 core 管道、设置页，另加**消息层**（§4）。

## 2. 已定（2026-11-24）

1. P1（密钥分层 + 设备名册）趁未发布现在做，远端格式直接改，不做兼容。
2. 桌面收到剪贴板：默认以候选/提示条一键上屏，不覆盖系统剪贴板；设置里可改为自动写入。
3. 桌面发送剪贴板：自动监听 + 过滤（密码管理器标记、超长内容），功能默认关闭。
4. 局域网直连列入计划，排在剪贴板信箱之后。

## 3. P1：密钥分层与设备名册

### 3.1 密钥分层

根密钥 DEK（即用户的「同步密钥」，生成/查看/粘贴与校验值都针对它）经 HKDF-SHA256 派生用途子密钥，
`info` 为固定标签：

| 标签 | 用途 |
|---|---|
| `windinput-sync/files` | 文件同步对象加密与 blob id 的 HMAC |
| `windinput-sync/devinfo` | 设备信息对象 |
| `windinput-sync/clip` | 剪贴板消息（P3） |
| `windinput-sync/xfer` | 图片/文件传输（P5） |
| `windinput-sync/lan` | 局域网直连的预共享密钥（P4） |

目的：一种用途的实现缺陷或密文泄露不牵连其他用途；局域网 PSK 不能是能解密文件的密钥本身。
代码里加密函数只接受子密钥类型，不再接受 DEK，从类型上杜绝误用。

### 3.2 设备名册

- 对象 `devices/<dev>/info`（devinfo 子密钥加密）：`{name, platform, app_version, caps[], last_seen}`。
  `caps` 为能力位（`files`、`clip`、`xfer`、`lan`），供发送方选目标。
- 写入时机：加入/改名/能力变化时立即写；`last_seen` 只在跨天时刷新（避免每轮多一次写）。
- 设备名：默认取主机名（Android 取设备型号），存设备本地同步设置 `device_name`，不随同步传播。
- 列表：`sync.command{op:"list_devices"}` 返回各设备 info（含本机标记）；读不出的 info 显示为「未知设备」。
- 移除：`remove_device{dev, confirm:true}` 删除该设备目录（清单与 info），不能移除本机。
  被移除设备若仍在运行，下次同步会重新出现——**真正吊销需轮换 DEK 并重加密**，列为以后（§7）。
- 回收只扫 `blobs/` 与本机旧清单，不碰 `devices/*/info` 与将来的 `inbox/`。

### 3.3 设置页

「数据同步」下加「我的设备」：列表（名称、平台、最后在线、本机标记）、本机改名、移除其他设备（二次确认，
提示「若该设备仍在使用，下次同步会重新出现；要彻底阻止请重置远端换新同步密钥」）。

## 3a. P2：Android 文件同步

### 3a.1 平台类别命名空间（2026-11-24 定）

设备分两类：`desktop`（Windows/macOS/Linux）与 `mobile`（Android）。**所有设备都上传自己的全部范围内文件**；
平台相关的文件在远端带类别前缀，只被同类设备应用：

| 类别 | 本机路径 | 远端逻辑路径 |
|---|---|---|
| 共用：词库与短语、方案 | `data/…`、`schemas/…` | 原样 |
| 平台相关：配置、主题、兼容 | `config.toml`、`themes/…`、`compat.toml` | `<类别>/config.toml` 等 |

多台手机之间、多台电脑之间各自同步配置，手机与电脑互不覆盖。「哪些跨类采用」以后靠策略调整
（如配置拆分后把共用部分移到公共路径、或「手机采用电脑配置」开关），不改远端格式。

### 3a.2 形态

- 同步逻辑在输入法进程内运行：`wind-mobile` 新增同步门面，复用 `apps/sync` 的 `Runner`，
  `CoreLink` 用进程内实现（编辑会话、各类重载直接调核心，与桌面 RPC 共用同一实现）；不起文件监听。
- 机密：私有目录 0600 文件（复用桌面 Unix 实现），并从系统备份中排除。
- 触发：键盘弹出且距上次同步超过 10 分钟时后台同步一轮；设置页手动「立即同步」。不引入 WorkManager。
  弹出触发的一轮发 `sync_now {"auto": true}`：不强制、不解除停止态，学习数据 30 分钟节奏与失败退避照常；手动才强制。
  P3 剪贴板的秒级轮询同样只在键盘显示期间进行，键盘收起即停，不常驻后台。
- 隐私政策：联网场景由「仅检查更新」改为「检查更新与（启用后的）数据同步，只连接用户自己配置的存储」。

## 4. 消息层（P3 起）

传输抽象 `Messenger { send(target, msg), poll() }`，选路：局域网可达优先，否则信箱。

- **对象存储信箱**：`inbox/<收件设备>/<毫秒时间戳>-<随机>`，clip/xfer 子密钥加密，收件方取后删除；
  超过 24 小时的由任一设备回收。广播 = 给每个具备该能力的设备各写一份。
  轮询：core 发「键盘活跃」信号（不含内容）时每 5–10 秒，空闲停止，另有低频兜底。
  坚果云等 WebDAV 有请求频率限制，额度待实测后定轮询上限。
- **局域网直连（P4）**：mDNS 发现同组设备；以 lan 子密钥为 PSK 做双向认证加密通道，同组设备免配对。
  Windows 首次监听会有防火墙提示，需在界面说明。
- **官方服务（P6）**：WebSocket 推送，实现同一 `Messenger`。

## 5. 剪贴板同步（P3）

- 读取：桌面由同步进程监听（Windows 剪贴板变化通知；macOS 轮询 changeCount；Linux X11 可行、
  Wayland 受限）；Android 由输入法读取（Android 10+ 仅前台应用与当前输入法可读），接入已有 `ClipboardStore`。
- 过滤（必须）：跳过 Windows `ExcludeClipboardContentFromMonitorProcessing` / `CanIncludeInClipboardHistory=0`、
  macOS `org.nspasteboard.ConcealedType` / `TransientType`、KDE `x-kde-passwordManagerHint` 标记的内容；
  长度上限；仅文本。
- 接收：同步进程经管道发 `ClipReceived{from, text}` 给 core；core 在内存中保留最近一条，作为候选/提示条
  「来自 <设备>：…」一键上屏（遵守输入流程零读盘）；可选自动写入系统剪贴板。Android 进剪贴板面板历史。
- 不落盘、不进 `data/`。

## 6. 图片互传（P5）

- 发送：Android 从剪贴板面板/相册；桌面从剪贴板图片或命令条。指定目标设备（名册 caps 含 `xfer`）。
- 传输：分块（如 4 MB/块，各自加密，可续传）+ 缩略图；局域网优先；单件上限如 20 MB，24 小时过期。
- 插入：Android 用 `commitContent`（目标支持时直接插图），否则写剪贴板；桌面写入系统剪贴板图片并提示
  Ctrl+V（模拟粘贴有兼容风险，不默认）。图片字节只经同步进程，core 只显示提示。
