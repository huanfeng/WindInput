# 模式主字可配（`[ui.labels]`）

语言栏图标 / 工具栏模式格 / 状态气泡上那个「中」「英」「五」「拼」的字，本文称**模式主字**。

中文态的主字一直可配（方案文件的 `[schema] icon_label`），非中文态是硬编码。本次把非中文态
也开放出来，并顺带把主字的上限从 1 个字符放宽到**显示宽度 2**（`En` 两个字母的宽度约等于
一个汉字；双汉字仍只取首字，见 §3）。

## 一、改造前：一个"单一真相源"，七处硬编码

`icon_label` 在架构上是协调器单点预计算、下发给各消费面的（`wind-host` 的 `ModeFlags`
注释写着"宿主不得自记一份"）。但**这条真相源的取值本身**散在七处：

| # | 位置 | 场景 | 消费面 |
|---|---|---|---|
| 1 | `coordinator.rs` `build_status` | 英文半角 / CapsLock | 语言栏图标 + IPC |
| 2 | `handle_menu.rs` | 英文半角 / CapsLock | 工具栏模式格 |
| 3 | `coordinator.rs` `status_indicator_text` | 英文半角 / CapsLock | 状态气泡 |
| 4 | `coordinator/langbar_icon.rs` | 不可输入（密码框等） | 语言栏图标覆盖层 |
| 5 | `wind-ui/toolbar.rs` | 不可输入 | 工具栏覆盖层 |
| 6 | `handle_mode.rs` | 临时英文 | 模式指示（另一条线） |
| 7 | `wind-bridge/push.rs` | 握手早期 | 无调用点 |

1/2/3 是同一段 `effective_chinese ? schema : caps ? "A" : "英"` 抄了三遍。

⚠️ 这是本仓反复出现的形态（简繁上屏出口曾七处全漏）：**直接加配置键必然漏掉几处**，
表现为"设置里改了，某个面还是旧字"。故本次先收口、再开放。

## 二、配置落点：`[ui.labels]` 全局段

```toml
[ui.labels]
english = "英"   # 英文半角：左/右 Shift 切出的英文态，按键原样透传
caps_lock = "A"  # 大写锁定
```

排除过的两个落点，理由都不是"不好看"而是语义错位：

- **`[ui.langbar]`** 只管语言栏图标的角标参数，而主字同时喂工具栏、气泡、移动端。
- **`english.schema.toml` 的 `icon_label`** ——「英文半角」与「英文方案」是本仓明确
  区分的两件事（前者是 `chinese_mode` 全局状态、按键透传；后者是 active 方案切换、
  走常规候选路径）。且英文方案可被用户禁用，复用它等于让一个可禁用对象持有全局状态的呈现。

**中文态刻意不进这个段**：那是方案的属性，搬进来就成了两个来源争同一个显示位。

## 三、上限 = 显示宽度 2（首版按字符数，issue #85 后改）

两条独立依据，缺一都能单独定案：

1. **渲染**：图标画布 16px（DPI 缩放后 20/24/32），两个 ASCII ≈ 一个汉字宽，是"还认得出"
   的上限。
2. **安全**：C++ 侧 `CLangBarItemButton::_inputTypeLabel` 走 `wcscpy_s`——超长**不是静默
   截断，是触发 invalid parameter handler 终止进程**，而那段代码跑在 Word / QQ 的进程里。

### ★ 单位是显示宽度，不是字符数（issue #85）

首版按**字符数**取 2，两条依据都只在"两个 ASCII"这一档上被验证过，却顺带把**两个汉字**
也放行了。第三方方案 `icon_label = "虎单"` 因此从 v0.118 的「虎」变成 v0.119 的「虎单」，
渲染端为了不裁切把字号回缩到约一半——**用户没动配置，升级后图标从清晰变成认不出**。

改为按显示宽度计（CJK 记 2、其余记 1，上限 2）后两侧同时成立：`En` 仍是 2×1 完整显示，
「虎单」宽 4 超限、截回「虎」，与 v0.118 的观感一致。

⇒ **一般化**：放宽一个上限时，依据是拿某一类取值论证的（"两个 ASCII 约等于一个汉字"），
就必须回头问"这个上限还放行了哪些**别的类**的取值"。宽度才是那条论证真正说的东西，
字符数只是它在 ASCII 上的巧合等价物。

实现上与工具栏按钮 `toolbar_label_trunc` 合并成一条规则（共用 `display_width_trunc`），
上限常量各留一个——两处的物理约束不同（等宽方格的长宽比 vs. 16px 位图 + C++ 缓冲）。

⚠️ 缓冲容量不能按"2 字符 = 2 wchar + NUL = 3"算：截断以 **Unicode 标量值**推进，
一个标量值在 UTF-16 里可能占 2 个 wchar（emoji，粗口径里记 1 宽）。宽度 2 蕴含最多
2 个标量值，最坏 2 char = 4 wchar + NUL = 5，故 `_inputTypeLabel` 由 `[4]` 扩到 `[8]`，
与 `STATUS_UPDATE_DATA::iconLabel` 对齐。

截断口径收在 `wind_config::schema::icon_label_trunc`，三个调用点共用：方案标签
`schema_icon_label`、特殊模式 `overlay_modes`、非中文态 `LabelsConfig`。
**前两处从前各写一份 `.chars().next()`，靠注释声明彼此一致**——改一处漏一处的表现是
"方案切换显 `Wb`、进特殊模式显 `符`"，没有测试会发现。

## 四、渲染：宽标签按实测宽度回缩字号

图标字号原本写死 `size - 2`，且 `x0 = ((s - m.width) * 0.5).max(0.0)`。`"En"` 在该字号下
宽约 15px、画布 16px，`.max(0.0)` 会把它钳成左对齐，**右半个字母画到画布外被裁掉**。

修法是多字符时按 `measure` 的实测宽度回缩（`WIDE_LABEL_SAFETY` 留出 overhang 与抗锯齿的
余量）。四条约束，其中前两条是实测才发现的：

- **★ 必须循环收敛，一次比例换算不够。** 排版引擎把字号吸附到整像素：16px 下「符号」
  行盒宽 28，按比例算出 6.58px，**实际按 7px 排版，宽度仍是满格的 14**，画出来照样裁掉
  右缘。比例算法在吸附值上原地打转，每轮必须至少降 1px 才能走出那一档
  （实测「符号」14 → 7 → 6 两轮收敛）。
- **★ 行盒宽相同不代表能不能装下相同。** 全角「Ｅｎ」与「符号」在同一字号下 measure
  完全相同（都是 28.00），但前者通过、后者触边——全角字母的墨迹远窄于其 advance，
  汉字则几乎填满。这也是为什么判据只能量真实输出，不能拿 measure 的数值直接断言。
- **判据必须是实测宽度，不能按字符数分档**——全角「Ｅｎ」是 2 个 char 却有 2 个汉字宽。
- `MIN_FONT_SCALE` 是**防御性下限，不是设计档位**。定在两全角字自然缩放比（约 0.5）之上
  会反过来把本可装下的标签顶出画布。

⚠️ 这**不是**该文件注释里翻过两次车的那种"字号分档"。那次的依据是运行时状态（有无角标），
同一个字会随中英切换忽大忽小；这里的依据是标签自身宽度，各自字号稳定。**别照着那条注释
把这段删掉。**

## 五、不可输入态跟随英文标签，不另设配置键

密码框 / 无编辑上下文 / 系统禁用时主字显英文标签。依据是行为一致——此刻键已全部透传给
宿主，与英文半角干的是同一件事。

两个消费面**处理方式不同，不要"统一"**：

- 工具栏：协调器直接算好 `ToolbarState.icon_label`（不下发 TSF，无持久值顾虑）。
  `wind-ui` 侧原有的覆盖已撤——那个 crate 读不到配置，留着只会让用户配的 `En` 在密码框里
  变回 `英`。
- 语言栏图标：只能在 `IconSpec` 上覆盖，**不能动 `icon_label` 本身**——它会经 StatusUpdate
  写进 TSF 的 `_inputTypeLabel`（持久值），把随焦点来去的临时态烧进去，漏一次刷新就长期卡住。

## 五之二、拉丁与汉字必须分两档（真机反馈后补）

首版把可用宽度和字重都按汉字那一套算，真机反馈**「显示 En 时 E 有些细」**（工具栏正常，
只有语言栏图标）。两个原因叠加，根子是同一件事：

**拉丁字母的 advance 里天然含左右边距、墨迹远窄于行盒；汉字几乎填满 advance。**

**宽度**分两档，判据是 `has_cjk`：

| | 汉字 | 拉丁 |
|---|---|---|
| 可用宽度 | `s - FONT_SIZE_INSET`（16px 下 14） | `s - LATIN_EDGE_INSET`（15） |

`"En"` 行盒 15.65，16px 画布本就差不多装得下，却被按汉字档缩到 11px 上下。

⚠️ 判据**不能写成 `is_ascii`**：全角「Ｅｎ」不是 ASCII 却是字母，ASCII 判据会把它
错分到汉字档。

### ★ 字重的判据是「有没有被缩小」，不是「是不是字母」

首版按字符集分字重（字母一律 400），真机第二轮反馈**「现在的 A 不太好」**——判据错了：

**字重补偿的理由是字号回缩带来的变细。** `"En"` 缩到 12px 上下、配 300（Light）就发虚；
而单字符 `"A"` 行盒不到 8px、**根本不进回缩**，字号仍是满格的，给它加粗只会比改动前突兀。

两条判据只在多字符标签上一致，单字符会分道扬镳。现行判据 `label_weight(label, base_width,
target)`：`base_width > target && !has_cjk`。汉字即使被缩小也不补偿——300 本就是为汉字
笔画密度定的。

⇒ **装得下的标签（「英」「五」`A`）走的是与本功能上线前完全相同的路径。**

★ 测试必须同时钉住四个方向（`"En"` 要补、`"A"` 不补、「英」不补、「符号」缩了也不补）：
只测第一条的话，被否掉的那版"凡字母都加粗"照样全绿。

⚠️ 字重决策抽成了纯函数，因为**走渲染结果反推字重会被居中校正的亚像素位移搅进来**——
`render_glyph_mask` 末尾有按墨迹重心迭代微调的循环，逐像素比对等于在测抗锯齿噪声
（首版回归测试就是这么写挂的）。

## 六、行为变更

- v0.119：现有第三方方案若配了多字符 `icon_label`，显示从 1 字符变 2 字符
  （`符` → `符号`）。
- issue #85 修复后：双汉字标签**回到 v0.118 的单字显示**（`符号` → `符`、`虎单` → `虎`），
  双拉丁标签（`En`）仍完整显示。两次都要在发版说明里提。

## 七、⛔ 刻意不进设置页

本功能定位为**高级特性，只进文档站，不做设置页 UI**（2026-08-25 用户拍板）。
改法是直接编辑 `config.toml` 的 `[ui.labels]`。

⚠️ 别"顺手补上"：设置页那边加一个配置项要过五道守门测试、占一行 spec，
而这两个键的目标用户是会改配置文件的人。
