# 候选展开（多行网格 / 卷轴）

> 2026-10-19 设计，§12 决策已于同日确认。
> 关联需求：GH#153（翻页键一次展开全部候选）、GH#183（参照搜狗智慧版卷轴）。

## 1 问题

候选窗一次只显示一页（出厂 7 个）。目标字不在首页时，只能一页一页按 `=`
翻着找。拼音单字的同音字多（yi、ji、xi 动辄几十页），用户已经多次反馈。

主流做法是**卷轴**：一按翻页键，候选窗原地展开成多行。用户能一眼扫完几页
候选，再用方向键在二维网格里移动高亮。

## 2 调研结论

| 输入法 | 展开触发 | 布局 | 数字键 | 筛选 |
|---|---|---|---|---|
| macOS 内建拼音 | 翻页键 / ↑↓ | 横向多行，每行 ≤9，按词长变宽 | 选当前行 | 底部排序（词频/部首），Tab 切换；Option-Tab 按声调筛选 |
| 搜狗 PC 16.3b（2026-04） | **↓**；翻页键是否展开可在设置里改 | 多行面板 | — | Tab 切换「服务」；`0` 跳到单字页 |
| 搜狗智慧版 | 翻页键 `=` | 卷轴 | — | 「筛选模式」（推测按部首） |
| QQ 拼音 5.4+ | ↓ / 翻页 | 多行，可在外观里关闭 | 当前行 | — |
| MS-IME 日文 / 微软繁体 | Tab / →；焦点到列尾自动展开 | 表格（日文纵向 4 列） | — | 旧版有排序 |
| 微软拼音（简体） | **没有网格**（Tab 是必应建议） | — | — | — |
| Rime / Fcitx5 / ibus | 不支持；librime#618、weasel PR#1854 都未合入 | — | — | — |
| 威注音（开源） | 首次翻页**只展开、不翻页** | 每行 ≤ 选字键数，按宽度换行 | 当前行 | — |
| 水杉 PR#7415（开源） | ↓ / 展开按钮，默认关 | 每行 = 每页数，最多 5 行可滚动 | 当前行，**只有该行显示序号** | — |

有共识的设计：

1. **单行起步，按需展开**。翻页键和 ↓ 都可以触发，各家做成可配置。
2. **数字键只选高亮行的第 N 个**，序号也只标在高亮行上。没有一家给网格做全局编号。
3. **收起要宽松**：Esc、在首行按 ↑、继续打字或退格都收起，组字保留。网格不处理的键，
   先收起，再照常处理。
4. **展开态的真正用途是找单字**。筛选或排序是加分项，但没有任何 PC 输入法公开过
   「单字 / 词组 / 生僻字」这样的标签页规则。

## 3 现状约束

详细链路见 `engine-candidate-pipeline.md`、`candidate-tooltip-sections.md`。
以下几条决定了方案的形状：

- **协议只认页内下标**。`UiCommand::UpdateCandidates` 只带当页候选；`selected`、`hover`、
  `CandidateSelect`、`CandidateOp`、`RequestCandidateMenu` 都是页内下标。
  数字键、`;'`、Ctrl/Alt+数字、右键菜单、`quick_history_at`、UI-less 页快照也都基于
  `page_range().0 + offset`。
- **三端宿主不解释下标**。Linux 的 `ShmFrame::hitTest`、macOS 的 `CandidatePanel.hitRects`、
  Windows 的 `HostWindow::_HitTest` 都把服务端给的命中矩形下标原样回传。只要下标还在
  `[0, 帧内候选数)` 里，宿主不用改。
- **渲染器只有 Row / Column 两种布局**（`view.rs`），没有换行或网格。三端共用
  `wind-ui::CandidateWindow`，所以网格只需在这里实现一次。
- **每帧成本和条数成正比**。`notify_ui_update` 会持 state 锁，为每个候选同步渲染悬停提示
  和注释。`mouse_hover` 的每次变化都会触发一次完整的 notify。
- **候选分批加载**。拼音首批 300 条，扩容会翻倍并整份重建，上限 5000。`has_more` 不下发
  给 UI，`total_pages` 只是按已加载条数估出来的。
- **`+` 键**。默认翻页键是 `=`（也就是 `+` 那颗键）。`Shift+=` 没有绑定，会落进标点臂。
  本设计所说的「按 + 翻页」指的就是翻页动作本身，不额外绑 `Shift+=`。

## 4 核心思路：一行就是一页

**展开态下，网格的每一行恰好是原来的一页（`per_page` 个），高亮所在的行就是 `current_page`。**

这一个等式让现有的页模型几乎不用动：

| 现有语义 | 在网格里的含义 | 要不要改 |
|---|---|---|
| `current_page` | 高亮行 | 不改 |
| `selected`（页内下标） | 高亮列 | 不改 |
| 数字键 / `;'` / Alt+数字 / Ctrl(+Shift)+数字 | 作用于高亮行 | **不改** |
| 空格 | 上屏高亮项 | 不改 |
| `page_next` / `page_prev` 的扩容、末页放宽 | 往下滚动时照常触发 | 复用 |
| `turn_page` 与 `paged` 的不变量 | 换行 = 翻页 | 复用 |

新增的只有**视图状态**和**二维导航**：

```rust
// State 新增（coordinator.rs）
/// `Some(p)` = 已展开，第 p 页在可见区第一行。可见行数读配置，不进状态。
grid_top: Option<usize>,
```

选「一行一页」，而不选威注音那种按宽度自适应换行，原因有三：

- 行宽要在 UI 端测量，协调器拿不到。按宽度换行就得让 UI 回传布局，三端协议都要跟着改。
- 列数固定后，↑↓ 保持列号就行，结果确定、好写测试；不需要「找 X 最近的格」这类启发式。
- 序号 1–7 在每一行都指向同样的位置，用户形成的肌肉记忆不变。

代价是长词会撑宽一列。处理见 §6.2：限制格宽，被截断的原文由悬停提示里已有的
`${full_text}` 段补齐。

## 5 交互规格

### 5.1 进入

| 条件 | 行为 |
|---|---|
| 收起态，按 `PageNext`（`=`、PageDown 等已绑定的翻页键），且候选多于一页 | **只展开，不翻页**，高亮停在原位（决策 D3） |
| 收起态，按 ↓ | **不展开**，保持现有的线性移动（D1） |
| 鼠标在候选窗上往下滚、或点翻页栏的 › | 展开（与翻页键同语义） |

**不展开**的情况：只有一页、竖排或旋转布局（v1，见 §9）、TSF UI-less 宿主、候选窗被隐藏、
联想态、临拼与临英以外的 overlay 模式（快捷输入、辅助码筛选、特殊模式等）。判据收在
`Coordinator::grid_eligible` 一处，只在进入时判。

### 5.2 展开态的按键

| 键 | 行为 |
|---|---|
| ← / → | 在行内移动。到行首、行尾时折到上一行末、下一行首 |
| ↓ / ↑ | 换行并保持列号（目标行较短时落到行尾）。在首行按 ↑ 收起 |
| `=` 等翻页键（`PageNext`） | 下移一行并保持列号，同滚轮（§5.4）：到可见区末行再按滚一行，到底走末页放宽 |
| `-` 等翻页键（`PagePrev`） | 上移一行，到首行停住、不收起 |
| PageDown / PageUp | `grid_pageupdown_screen` 开着（出厂）时滚一整屏（`rows` 行），首屏再上翻回到首行；关掉同上逐行。只看物理键，不管绑在哪组 |
| Tab / Shift+Tab | 切换分类标签（决策 D5，§8）；没有标签栏时（`grid_categories` 少于两个）照旧是绑定表里的动作，出厂即换行 |
| 1–9 / 0、`;'`、Alt/Ctrl+数字 | 从高亮行行首起按序号选；序号按 `grid_index_fill` 顺延到下面的行（见 §5.3） |
| 空格 | 上屏高亮项；分步上屏（拼音只吃掉前一段）时余下那段照样展开，整串上屏才结束 |
| 回车 | 保持现有的 `enter_behavior`（上屏原码 / 清空） |
| Esc | **先收起，保留组字**；再按一次才是现有的取消（决策 D4） |
| 字母、退格、标点等组字键 | 照常处理，候选重建后**保持展开**（本次组合展开过，见 §5.5） |
| 上屏编码（`CommitCode`） | 照常处理 |

还有两点：

- ↑↓ 必须走 `apply_session_action` 这个统一入口（根 `AGENTS.md`「候选导航键」）。展开态下
  `HighlightUp/Down` 的含义改为换行；`flip_when_above` 只在竖排时才翻转方向，对网格没有影响。
- 展开态下 ←→ 不再移动编码区光标。Home/End 仍然移动光标。
- ←→ 与 Esc 在 `apply_session_action` 的最前面截下（`candidate_grid::grid_key`）：主输入与
  各 overlay 都先经过这里，才落到各自的光标移动臂与 Esc 臂，所以只需接这一处。用户绑了
  `cancel` 的其它键同样先收起。

### 5.3 序号顺延（维护者 2026-10-19 定）

数字键有 1–0 十个，一行用不完时顺延到下面的行，默认**只补整行**，避免半行带号半行不带号：

| `ui.candidate.grid_index_fill` | 每页 5 个 | 每页 7 个 |
|---|---|---|
| `rows`（出厂） | 高亮行 1–5、下一行 6–10 | 只编高亮行 |
| `cells` | 同上 | 高亮行 1–7、下一行前 3 格 8、9、10 |
| `off` | 只编高亮行 | 只编高亮行 |

- 只往**下**补、只补可见行：高亮在可见区最后一行时只编它，不给看不见的格子编号。
- 第 10 个的序号沿用普通候选窗的写法（`10`，可用 `index_labels` / 主题改）。
- 实现：`select_range` = 「按序号选」的下标范围，起点仍是高亮行行首（于是各模式 `start + offset`
  的写法原样成立），终点延到带序号的最后一格；数字键、`;'`、Alt / Ctrl+数字、临拼与临英的
  对应入口都从它取。帧里用 `CandidateGrid::index_start / index_count` 告诉渲染端哪几格画序号。

### 5.4 鼠标

- 单击任意格：先把 `current_page` 和 `selected` 切到那一格，再上屏。
- 右键任意格：先切高亮，再弹现有的候选菜单。置顶、删除、设为生僻等菜单项全部照常可用。
  悬停也落到被右键的这一格：菜单开着时鼠标消息到不了候选窗，在另一格上再右键时，悬停若停在
  旧格，旧格的悬停底色会留在原处，看上去像高亮没跟过来（靶机实测）。
- 滚轮 / 翻页栏的 ‹ ›：展开态滚一行（与逐行的翻页键同一条路 `grid_scroll`），往上滚到第一行停住、不收起（滚轮滚过头是常事）；
  收起态往下滚与翻页键同语义，先展开。host-render 宿主的滚轮（`handle_candidate_scroll`）
  同此。
- 悬停：用于驱动提示，见 §7。

### 5.5 收起

真正收起的只有：Esc、在首行按 ↑、组合结束（整串上屏、取消、失焦）、候选窗隐藏。

候选重新装填时（打字、退格、分步上屏后续查）视图先经 `reset_candidate_view` 复位成单行，
`paged` 也在这里清零。随后 `grid_keep`（「本次组合展开过」）把它展开回来：主路、临拼、临英
三个刷新入口（`update_candidates` 等）末尾都调 `grid_resume`。拼音用户的反馈：分步确认一段后
又缩回单行，等于每段都要重按一次翻页键。新候选不够两页时不展开，标记留着，够了再展开。

`grid_keep` 由 Esc / 首行 ↑ 的收起、隐藏候选窗清掉；组合结束的出口有几十处，不逐个清，而是
在每次按键开头（`handle_key_event`）看到「没有输入会话、或只剩联想」就清——那说明上一次组合
已经结束。不看「候选为空」：码表空码、分步上屏后删空余码时组合还在。按键入口判不到的只有顶码
（这一键按下时候选还在，首选上屏、余码在同一键里另起组合），`commit_top_text` 自己清。所以
**不跨组合记忆**：每次新输入都从单行开始。

同一组合内的其他重建：置顶 / 调位 / 删除（`candidate_op`）先 `grid_snapshot`、重建后
`grid_restore`，留在原来那一行、那一列和那个分类；退出辅助码也 `grid_resume`。扩容之后仍不足
两页就不展开（`try_expand_grid` 回滚），免得一行真候选加一屏占位行。末页放宽在临拼 / 反查下会重建候选，那两支与页码一起存还
网格位置。

## 6 协议与渲染

### 6.1 协议：只加一个可选字段

```rust
// wind-ui-types/src/command.rs  UpdateCandidates 新增
grid: Option<CandidateGrid>,

// wind-ui-types/src/candidate.rs
pub struct CandidateGrid {
    pub cols: u16,          // = per_page
    pub rows: u16,          // 可见行数（配置值）；末屏实际行数由 candidates.len() 推出
    pub highlight_row: u16, // 高亮行在可见区内的行号
}
```

`page` / `total_pages` 照旧下发，展开态读作「高亮行 / 总行数」，翻页栏无需改。P2、P3 又加了
`index_start / index_count`（带序号的格子，§5.3）与 `tabs / active_tab`（分类标签位集与当前分类，§8），
分类名与编号的映射是 wind-ui-types 里的纯数据枚举 `GridTab`。

展开态下 `candidates` 是可见区内**扁平排列**的 `rows × cols` 项，`selected` 和 `hover`
也是这个扁平数组里的下标。

宿主回传的仍然是一个整数下标，由协调器换算成页和列：
`page = top_page + idx / cols`，`col = idx % cols`。三端宿主都不用改，因为它们本来就
不解释这个数。下面这些协调器入口统一先换算，再走原有逻辑：

- `mouse_select`、`show_candidate_menu`：函数内先经 `resolve_event_index` 换算（收起态原样返回），
  它们的其它调用方传的页内下标不受影响；
- `CandidateOp`：只在 UI 事件分发处换算——Ctrl+数字热键等调用方传的本来就是页内下标；
- `mouse_hover`：校验范围从「当页条数」改为「可见区条数」；
- `tooltip_page`：按帧内平铺下标存，与 UI 回报的下标天然一致。

这样做满足 wind-ui-types 的三条红线：纯数据、不加依赖、不分平台。wind-mobile 的映射层
直接忽略这个字段，移动端本来就走 `candidate_pull` 拉取。

### 6.2 渲染（`wind-ui::CandidateWindow`）

- **布局**：一个 `Column`，里面每行一个 `Row`。不给 `view.rs` 新增布局变体。
- **对齐**：列宽取可见行里这一列的最大宽度，各列对齐成表格。
- **格宽上限**：新增配置 `ui.candidate.grid_cell_max_chars`，出厂 6 个字，超出部分截断加 `…`
  （协调器截，与 `max_chars` 取较紧者）。
  被截断时，悬停提示的 `${full_text}` 段会自动出现（这是现有能力）。
- **列宽缩减**：表格总宽超过 `screen_safety_max_width_px` 时，对各列宽用 `water_fill`
  缩减（这是现有的截断算法）。
- **序号**：带序号的格子按 §5.3 顺延编号，其余格子由渲染端画成**透明序号**占住同样的宽度，
  各行文字起点才对得齐。
- **翻页栏**：挂在表格下方独立成行（同竖排），沿用现有的 `‹ 页/总页 ›`，展开态读作行位置。
- **行距**：沿用主题 `candidate_list.row_gap`。
- **注释**：沿用现有的注释模板，同样受格宽上限约束；上方注释条按列宽截断。
- **P1 不加主题字段**。整行底色、`12+` 这类「还有更多」提示、分类栏样式留到确有需要时再加
  （按 `theme-capability-extension.md`，新字段必须在当期被引擎实际消费）。

### 6.3 定位：尺寸要稳定

窗口在展开和收起之间跳来跳去、滚动时变宽变窄，这两类问题是卷轴最常见的投诉
（搜狗的更新日志里专门修过「卷轴展开时显示在屏幕下方跳跃的视觉效果」）。

- **高度固定**：滚到末尾、行数不够 `rows` 时，用占位行补齐。这与竖排的 `min_rows` 是同一种做法。
- **宽度只增不减**：一次展开期间，宽度取见过的最大值（`grid_peak_w`，每帧测量后回写，
  下一帧作根容器的宽度下限），收起时复位。
- **位置只在展开那一刻决定一次**：按网格的高度判断下方放不放得下；放不下就翻到上方，
  让底边贴住光标。之后滚动期间位置不变。
- Windows 的 `place_window`、macOS 的 `CandidatePanel.show`、Linux 的 `placePanel` 本来就按
  帧尺寸定位。只要保证「同一次展开期间尺寸不变」，三端都不用改。

## 7 悬停提示

现有规则（`update_tooltip`、`render_tooltip_frame`、`tooltip_place` 这三处判据）是：
横排时提示放在候选下方，竖排时放在右侧。放进网格里，两种都会**盖住相邻的格**。

### 7.1 定位：放到网格外

展开态新增第三种定位，**贴着窗口外缘**：

1. 首选窗口**右侧**，**停靠在顶端**：不随悬停行上下移动，只换内容。
2. 右侧放不下时放左侧。

起初做的是纵向对齐悬停行，实测是「半跟随」：位置在变却够不着——气泡贴在窗口外侧，过去要
横穿同一行好几格，一路擦过的格子把悬停换掉，气泡也跟着换掉。改成停靠，并配朝向宽限（§7.4）。

**已实现（P2）**：三处判据收进 `CandidateWindow::tip_anchor` 一个函数——展开态返回「侧边 +
整个内容区的左右缘」（`grid_box_x`，每帧测量后记下），竖排 / 旋转态返回「侧边 + 候选项左右缘」，
横排返回「下方」。三端各自的侧边落位（Windows `clamp_beside`、host-render、外部宿主
`tooltip_place`）只认锚点矩形的左右缘与行顶，所以一行没改。左右都放不下（窗口几乎占满屏宽）
时沿用侧边落位的既有兜底（贴屏幕左缘），没有另做「改放上下」——横排展开态窗口宽度受屏幕安全
宽度约束，实际碰不到。停靠的行顶取内容盒顶（`grid_box` 记下的 `(左, 右, 顶)`）。Linux e2e 钉了
「气泡在候选窗外侧、停靠在顶端（悬停第 3 行也不下移）」。

### 7.2 键盘高亮也显示提示：已撤回

P2 一度加了 `ui.candidate.grid_tooltip_follows_highlight`（无悬停时提示跟随键盘高亮）。靶机试用
（2026-10-19）的结论是展开后立刻弹提示太突兀，维护者定为**只在鼠标悬停时显示、移开即消失**，
该键在发布前整个删除。同时修了同源的另一处：展开时窗口原地往下长，可能长到静止的鼠标底下、
系统补发移动消息而凭空冒出悬停——`set_grid` 在收起 → 展开那一刻重置悬停闸门（同窗口刚显示时）。

遗留：提示贴在窗口外缘，鼠标从格子移到提示上要穿过别的格子，悬停随之换格、提示跟着换，
「在提示上右键复制」不好用。维护者定为后续再议。

### 7.3 性能：只渲染需要的那一份

展开态一帧有 35 项（5 行 × 7 列）。如果像现在这样每项都渲染一份提示，再加上每次悬停都
重新 notify，热路径上的开销是现在的 5 倍。所以展开态下：

- 只为悬停格（或高亮格，见 §7.2）渲染提示，其它格的 `tooltip` 置空。**P1 已做**：悬停一变
  `mouse_hover` 就重新下发，所以按需渲染不丢气泡；`${word_code}` 的反查也随之跳过。
- `tooltip_page` 按平铺下标逐格存，未渲染的格子是空文档（与 UI 收到的一致，指纹校验照常成立）。
- 注释无法按需渲染（格子里要直接显示），只能逐格渲染。用日志打点量一次 35 项下的按键延迟
  （在 Dev 实例日志里分段计时）。超出预算的话，就把展开态的注释限制为只在高亮行显示。

**实测（2026-10-19，Dev 靶机，五笔拼音混输、每页 5 个）**：`notify_ui_update` 的组装 + 发送
耗时，单行 5 格中位 1.28ms / p90 1.91ms（907 帧），展开 25 格中位 1.31ms / p90 1.94ms（227 帧）。
按需渲染气泡之后，展开态在协调器侧没有可测的额外开销，注释不必限制。UI 线程的绘制耗时
（`render[...]` 那行 debug 日志）在靶机日志里被过滤掉了，未测。

### 7.4 朝向宽限：滑进气泡途中不切换

既有的悬停宽限是：气泡显示着时，离开它所属的候选，悬停变化延后上报（去另一个候选 150ms、
去空隙 280ms），给鼠标挪进气泡留时间；中途换目标不顺延。只够穿过一格。

现在加一条：这一步若**朝着气泡去、且离气泡的距离刷新了本次宽限的新低**（`tip_gap`），截止往后
顺延 150ms——一路滑过去不切换，停下 150ms 就切到停住的那一格；往回走、偏离气泡照旧在 150ms
内切换。「刷新新低」挡的是抖动：指针停在格子上 ±1px 来回，一来一回刷不出新低，不会把切换
无限拖住；总顺延量也就以指针到气泡的距离为界。气泡已自己收起时不判（Windows 读气泡共享的
可见标志，Linux 看 `mapped`，macOS 看 `isVisible`）。判据（`heading_to_tip`）不用严格的安全
三角：气泡停在顶端时，从靠下几行水平滑过去并不指向气泡本身。改用「沿气泡所在那一侧在靠近，
且偏离气泡跨度的位移不比靠近的快」。

判朝向用的气泡框：Windows 是内容盒，Linux / macOS 是整个浮层窗口（含阴影扩边）；差别只在指针
贴着候选窗最右一格时，影响可忽略。收起态（横排气泡在下方）同样生效，水平扫过候选不会触发
（不在靠近），只在「左移后再右移、气泡在右侧」这类边角让切换等到停下。

三端各一份、同一张用例表：Windows `candidate_window::heading_to_tip`（`CandidateMouse` 逐次移动
判）、Linux `OverlayInput::headingToTip`（X11 面板；Wayland 面板本就没有悬停宽限）、macOS
`OverlayInput.headingToTip`（候选视图每次移动另报 `onPointerMoved`）。Windows host-render 路径
（C++ `HostWindow`）本就没有宽限，未动。

## 8 分类筛选（P3）

调研里，没有任何 PC 输入法公开过「单字 / 词组 / 生僻字」标签页的规则。但「找单字」恰恰是
卷轴的核心用途：搜狗有 `0` 键跳单字页，佛振也建议给单字归类。所以做一个轻量版本。

| 标签 | 判据（全部来自 `Candidate` 上的现有字段） |
|---|---|
| 全部 | 不筛选 |
| 单字 | `semantic_units(text) == 1`（复用 `common::semantic_units`） |
| 词组 | 字数 ≥ 2，并且不是整句、不是 emoji 建议 |
| 生僻 | `!is_common`，或者 `charblock::block_of` 落在 CJK 扩展区；与「设为生僻」（`user_rare`）取并集 |
| 符号 | 只有当前候选里存在 emoji 或符号类候选时才显示这个标签 |

**判据细化**（全部取自现有字段）：「汉字」用 `wind_candidate::is_han`（与常用性判定同一个域）；
单字 = 汉字且 `semantic_units == 1`；词组 = 汉字且 ≥ 2、且不是整句；生僻 = 汉字且
`!is_common || user_rare`，常用字表没加载时不给；符号 = 既不含汉字、也不含字母数字（英文词另在
「全部」里）。

**每个分类都要在完整列表里已经有内容才给**——只看「还能再取」不够：拼音 `yi` 取到上限也没有一个
词组、临英全是英文词，给出点开必空的标签，Tab 还会因循环一路跳过而被吞掉。出厂智能档下同码有
常用字就滤掉生僻字，于是「生僻」只在全部字符档、或该码本就没有常用字时出现。配置只决定**有哪些**，
顺序固定按 `GridTab` 枚举（标签栏按枚举画，Tab 循环若按配置顺序走两者就对不上；设置端的多选写回
也只保证集合）。「全部」恒在首位。少于两个标签时不显示标签栏。

**实现（P3，已做）**：

- **就地换成子集，而不是下标映射**。设计时打算维护一张 `view → candidates` 的映射，但候选
  下标在几十处调用里按 `state.candidates` 解释，映射会扩散到每一处。改为：切到某分类时把完整
  列表暂存进 `State::grid_full`，`candidates` 换成筛过的子集；切回「全部」换回来。选词、序号、
  右键、置顶删除因此都不必知道筛选的存在。
- **重建后重套筛选**（`grid_reapply_filter`）：扩容（`expand_candidates`）与末页放宽会整份重建
  `candidates`，重建出来的是完整列表，要重新筛一遍；末页放宽「有没有放出东西」在重套**之前**判
  （放出来的字不一定落在当前分类里）。整句切换在筛选中让出按键（整句窗口按完整列表的位置滚）。
- **补加载**：筛选结果填不满两屏、且引擎还有更多时扩容，**最多两次、可见条数不再增长就停**。
  每次扩容都是整份重建、且在按键线程上（TSF 那边同步等着）；分类稀疏时一路翻倍到 5000 要重建五次。拼音完整
  音节下引擎条数随 limit 翻倍、去重后可见条数纹丝不动（`yi` 实测停在 145 条，且一个词组都没有），
  按 `has_more` 一路扩到 5000 只是白白整份重建；临拼的扩容直接返回、不动 `has_more`，只看它会死循环。
- **空分类跳过**：标签已保证当前列表里有内容，补加载后仍筛空（检索范围变了）时退回原分类、
  重新锚定；候选窗不会变空。
- **调位按完整列表计**（`reorder_positions`）：shadow 规则写下的位置，读端按完整候选列表解释。
  筛选中置顶 / 前移 / 后移把子集下标换算回完整列表，前移 / 后移的目标是子集里**前一个 / 后一个
  可见词**的位置。删除按候选本身认，不受影响。
- **进辅助码前退回全部**（`grid_restore_full`）：辅助码要拿原始候选做快照。
- **高亮锚定**：切分类后高亮落在原来那个词上（新列表里有的话），否则落到第一个；可见区尽量凑满一屏。
- **标签点击**：标签的命中 tag 是 `GRID_TAB_TAG_BASE(1000) + 编号` 这段**正数**。宿主只把翻页键
  重映射成负数、其余下标原样当候选下标回传，所以点击走候选点选那条路回到协调器，三端宿主不用改；
  悬停 / 右键落在这一段时，已有的范围校验当越界忽略。
- **按键**：Tab / Shift+Tab 在 `grid_key` 里截下（先于绑定表），但只在 Tab 没被另作他用时：
  没绑会话动作、或绑的就是出厂的高亮上下（展开态下本是换行，方向键照样能换行），且不是整句
  切换键。用户把 Tab 绑成 `aux_code:page_next` / `cancel` 等时不截；没有标签栏时也不截。
- 标签栏在表格**下方**、与翻页箭头同一行整体居中（`[标签栏]  ‹ ›`），展开期间恒在，切分类时
  窗口高度不变。最初放在表格上方，靶机试用发现它把首行往下推、展开不像「原地往下长出来」，改到
  下方后首行位置与收起态的单行一致。翻页箭头在展开态滚一行（同滚轮）。实测切换耗时（Release）：首批就够时约 20µs，
  需要补加载一次时 2–5ms。

**不做**：按部首 / 笔画排序、声调筛选（macOS 有）。部首和笔画缺数据（拆字数据不是笔画序），
声调需要逐字反查读音。可以作为后续独立项目，不放进本期。

## 10 配置

与 `[ui.candidate]` 其余键同为扁平写法（P1–P3 已全部落地；P2 的跟随高亮已撤回，见 §7.2）：

```toml
[ui.candidate]
grid_expand         = false   # D2：默认关
grid_rows           = 5       # 可见行数，夹在 2..=10
grid_cell_max_chars = 6       # 单格最多几个字，0 = 只受 max_chars 约束
grid_index_fill     = "rows"  # 序号顺延：rows 只补整行 / cells 逐格编满 10 个 / off 只编高亮行
grid_pageupdown_screen = true # PageUp/PageDown 翻整屏；其余翻页键恒逐行
grid_categories     = ["all", "single", "phrase", "rare"]   # P3；可加 "symbol"
```

- Esc 两段式（D4）是固定行为，不设开关。
- 预置 `data/config.toml` 按惯例列全三个键（`data_config_toml_covers_registry` 守这条）。
- ⚠️ 新键要同步邻仓 wind-setting 的 capability 快照（`dev.sh sg` 重生成），否则合并后
  `cargo test -p wind-rpc --test wind_setting_assets` 会红。设置页本身在 P4 做。
- 设置端在「外观 → 候选窗」下面加一个「展开候选」分组。label 用到的生字要先过一遍拼音
  检索表的用例。
